# 表示スナップショットと操作記録

[ビューワーの使い方に戻る](../README.md) / [開発・検証・公開](development.md) / [描画とデータ処理](rendering.md) / [スナップショット](snapshots.md)

## 操作を記録する

F8キーを押している間、ビューワーへ届いた操作を記録する。押した時点の表示状態とUI配置、フレームごとのマウス移動・ボタン・ホイール・キー・文字入力・ドロップされたファイル・フォーカス・経過時間、および操作後のカメラ状態を保存する。押し始めから既に押されていたボタンとキーの状態も残す。記録中は画面に通知し、F8を離すと最後の描画を確保して一つのスナップショットへ保存する。長押しのキーリピートで記録やファイルを分割しない。アプリからフォーカスが外れた場合は、その時点で記録を終了する。ウィンドウを閉じる場合も記録を保存する。

保存先はアプリのデータフォルダー内の `snapshots`。日時・プロセスID・連番付きのファイル名を画面右下に通知する。Windowsでは通常 `%APPDATA%\yamamuki-viewer\data\snapshots`。圧縮・書き込みはバックグラウンドで行う。「即時保存」では操作記録を含めず、その時点の静止状態だけを保存できる。

操作記録付きファイルを読み込むと、まず終了時点を固定表示する。「スナップショット」メニューの「記録した操作を再生」で開始状態に戻り、入力を記録順・記録時刻に沿って再生する。Escで中止でき、終了・中止時には再生中の押下状態を解除する。記録はこのアプリに届く入力が対象であり、別アプリやOSのファイルダイアログ内の操作は含まない。元データの読み込みやGPU処理の完了時刻は環境で変わるため、再生時の負荷や描画途中まで完全に同じになるとは限らない。

## 静止状態を保存・復元する

ツールバーの「スナップショット」から「現在の表示を保存…」を選ぶと、`viewer.snapshot.json.gz` に表示状態を保存する。カメラ・展望位置、オンライン地図・地表の設定、読み込んだファイルのパスに加え、地形は直前に実際に描画したタイル集合・局所評価区画・分割数・描画パッチ・切替前のメッシュ・LOD補間率を保存する。読み込み途中で隙間が出た状態も記録できる。

「読み込んで固定表示…」で保存ファイルを選ぶと、LODを選び直さず、保存したメッシュ構成を通常と同じGPU描画経路で再生する。カメラ操作・LOD更新・曲面の細分化・LOD補間率の進行は止める。「同じタイルを修正版で再分割」で、保存したカメラとタイル集合を保ったまま現在の接合方式へ切り替えて比較できる。「固定を解除」で通常表示へ戻る。保存時のマップ描画サイズを維持するため、ウィンドウが小さい場合は表示の端が切れる。地形の描画解像度も保存時のDPI倍率を使う。

## 再現に必要な元ファイル

スナップショットは元のSQLite・地点データ・オンライン地図画像を内包しない。同じパスの元ファイルが必要で、地形SQLiteのサイズとデータ版を検査してから復元する。オンライン地図はキャッシュまたは配信元から再取得するため、画像の配信内容や読み込み途中の画像までの完全一致は保証しない。問題報告ではスナップショットと画面のスクリーンショットを併用する。

通常の起動コマンドへスナップショットを渡して開くこともできる（ファイル名は `.snapshot.json.gz` または `.snapshot.json` で終える）。

```powershell
.\viewer\run_win.bat C:\path\viewer.snapshot.json.gz
```

## 遷移途中の再現

過去の遷移途中を保存したスナップショットは、旧表示の背景曲面・前景と背景の区別・描画パッチも保持して固定再生する。固定解除後は新しい完成メッシュへの一括切り替えに戻る。隣接候補の範囲は元タイルの接合幅で決め、評価区画の分割密度で接合対象を変えない。

実データによる再現検査の環境変数とコマンドは[開発・検証・公開](development.md#エラーログと性能診断)を参照。
