# 山むき・データビューワ

[リポジトリの README に戻る](../README.md)

山むきの地点 JSON と、森林・水域・陰影などを収録した地表 SQLite を開いて重ねて表示できる、Windows と macOS（Apple Silicon）向けの Rust アプリ。地理院地図や OpenStreetMap 系のオンライン地図を下地に使える。地表データはオフラインでも表示できる。

## 起動

Rustのstableツールチェーンを用意する。WindowsではMSVCのビルドツール、macOSではXcode Command Line Toolsを用意する。macOSで未導入なら、ターミナルで `xcode-select --install` を実行する。

以下は両OSともリポジトリのルートから実行する。

```sh
cargo run --locked --release --manifest-path viewer/Cargo.toml
cargo run --locked --release --manifest-path viewer/Cargo.toml -- points/gsi-peaks/gsi-peaks-source.json
```

Windowsでは `viewer\run_win.bat` からも起動できる。起動のたびにCargoで変更を確認し、必要な部分をリリースビルドしてから実行ファイルを起動する。ファイルのパスを引数に渡すこともできる。macOSではターミナルから上記のコマンドで起動する。

「地点ファイルを開く」から `.json` または `.json.gz` を選ぶ。ファイルをウィンドウにドロップしても開ける。[地点データ版6](../points/schemas/data-v6.schema.json)と[版5の配列](../points/schemas/data-v5.schema.json)に対応する。左ドラッグで移動し、ホイールでカーソル位置を中心に拡大縮小する。右ドラッグの左右で地図を回転し、上下で最大80°まで傾ける。右上のコンパスは北を示し、クリックすると北が上の真上視点に戻る。地図をクリックすると、その位置にピンを置いて緯度・経度を表示する。ラベルの「コピー」で緯度・経度をカンマ区切りでクリップボードに入れられる。地点マーカーをクリックすると名称・座標・標高・IDを表示し、一覧の地点を選ぶ。近接する地点もそれぞれの座標に表示する。

左ペインの「レイヤー一覧」で、地理院地図の標準地図・淡色地図・白地図・写真・色別標高図・陰影起伏図・傾斜量図と、OpenStreetMap系の標準地図・地形図（OpenTopoMap）・自転車地図（CyclOSM）・人道支援地図（HOT）を切り替えられる。地図の提供ズームより拡大したときは、取得できる最も細かいタイルを拡大表示する。選んだ地図は次回起動時も使う。出典は [国土地理院（地理院タイル一覧）](https://maps.gsi.go.jp/development/ichiran.html) と [© OpenStreetMap contributors](https://www.openstreetmap.org/copyright)。

国土地理院とOpenStreetMap系のすべてのオンライン地図は、表示範囲のタイルを取得し、配信元のキャッシュ指定に従ってディスクへ保存する。写真のJPEGも対象。地図の種類ごとに保存先を分け、再起動後も有効なキャッシュを再利用する。期限切れは条件付きリクエストで更新を確認し、期限の指定がない場合は7日を既定とする。保存先はアプリの保存フォルダー配下の `gsi-std-tiles`、`gsi-photo-tiles`、`osm-tiles` など。容量上限と自動整理は設けていない。出典は各スタイルの表示中に画面下部に示す。[OSM標準地図の利用方針](https://operations.osmfoundation.org/policies/tiles/)、[OpenTopoMapのライセンス](https://opentopomap.org/about)、[CyclOSMとHOTの配信元の利用方針](https://www.openstreetmap.fr/usage/)を参照。

## 地表SQLite

「地表SQLiteを開く」から [山むきSQLiteコンテナ](../formats/sqlite.md) の地表データを選ぶ。ファイルのドロップや起動引数でも開ける。別の地表SQLiteを開くと一覧に追加され、既に開いている地表も表示したままになる。一覧にはデータセット名が出る。行のチェックでデータセット全体の表示を切り替える。`i` を押すとファイル名・パスと「全体」ボタンが出る。「閉じる」でそのファイルを一覧から外す。地表だけを表示する場合はタイルの取得にネット接続を使わない。一覧でオンライン地図を選ぶと、森林の地色を省いて、森林や水域がない場所にオンライン地図を表示する。地点データを同時に開いて重ねられる。

「レイヤー一覧」の「オンライン地図」にチェックを付け、配下の国土地理院またはOpenStreetMap系から下地を1種類選ぶ。地表のデータセットは開いた順に並び、後から開いたファイルを上に重ねる。各ファイルの中ではレイヤーの描画順に並べる。地表レイヤーは各行でON/OFFと自動または固定のLODを設定できる。固定LODの候補は各レイヤーの収録レベルから表示し、レベル名は実XYZズームに基づく `z10` などの表記に統一する。森林・水域・陰影の表示名は仕様に定めた `id` と `role` の組み合わせで判別し、汎用レイヤーは `id` を表示名に使う。オンライン地図と地表の自動LODは、256画素タイルに換算した画素密度を基準にする。タイルは表示に必要になった時点で読み込み、陰影を陸地に適用してから水域を合成する。オンライン地図に重ねると、下地の地図の色にも陰影を掛ける。地表単独表示で陰影だけを選ぶとグレースケールで表示する。ファイルに含まれる出典を画面下部に表示する。[地表画像のSQLite形式](../surface/formats/sqlite.md)

```powershell
viewer\run_win.bat 'build/surface/japan-0.1.0/esa-worldcover.sqlite3'
cargo run --locked --release --manifest-path viewer/Cargo.toml -- --check-surface 'build/surface/japan-0.1.0/esa-worldcover.sqlite3'
```

`--check-surface` はウィンドウを開かず、地表データセットと各レベルの代表タイルを読み込んで合成する。

## 地形SQLite

「地形SQLiteを開く」で、既存マップの表示領域に地形を追加する。左のレイヤー一覧・地点一覧・地点詳細はそのまま使える。地形のチェックで起伏をON/OFFし、表示範囲・回転・傾き・拡大縮小は共通にする。SQLiteの起動引数やドロップも内容から判別する。

オンライン地図と地表SQLiteは、既存レイヤーの順序・ON/OFF・LOD・配色・陰影・クロスフェードを使い、GPU上で合成して地形へ貼る。国土地理院やOpenStreetMap系の地図を選ぶことも、オンライン地図をOFFにして自作地表だけを使うこともできる。地形と地表を同じSQLiteへ収録した場合も、地表をレイヤー一覧に追加する。3D表示中に地表を追加しても視点は維持する。

[地形形式版1](../terrain/formats/sqlite.md) に対応し、自由配置制御点を復号してGPUで自然近傍曲面を再構成する。固定・自動LOD、品質上限、C1傾き調整、制御点・描画メッシュのワイヤーフレーム、画面サイズによるパッチ分割、境界接合とLODのスムーズ切替を備える。

```sh
cargo run --locked --release --manifest-path viewer/Cargo.toml -- --terrain build/terrain/gsi-terrain.sqlite3
cargo run --locked --release --manifest-path viewer/Cargo.toml -- --terrain build/terrain/gsi-terrain.sqlite3 build/surface/esa-worldcover-z12.sqlite3
cargo run --locked --release --manifest-path viewer/Cargo.toml -- --check-terrain build/terrain/gsi-terrain.sqlite3
```

`--check-terrain-render <地形SQLite> <出力PNG> [地表SQLite]` は富士山の実画面を保存して終了する、手元の描画検査用コマンド。地形と地表を統合したSQLiteでは、収録された地表も自動的に重ねる。

`--check-terrain` は各レベルの代表タイルを復号し、GPU探索情報を作って点数・容量を報告する。配布前の全点監査は `terrain-tool validate` を使う。地表のON/OFF・固定/自動LODは既存のレイヤー一覧で操作する。読み込みは背景スレッドで行う。

## 地点一覧と地図

[Web版の地点ビューワ](../points/viewer.html)と同様に、地点名・読み・別名・IDで検索し、タグ、出典、取得元での分類、標高の出典はそれぞれ複数選択できる。同じタグ欄ではいずれかに一致し、検索語とタグ条件は両方に一致する地点を表示する。絞り込み対象外の地点は小さな灰色マーカーで残る。マーカーの大きさはズームと絞り込み後の件数で切り替わる。2万地点以上のファイルは、表示範囲に入る地点から最大1万件を個別表示する。検索や条件解除で地図の縮尺は変わらない。

一覧を選ぶと、その縮尺のまま地図の中心と詳細が切り替わる。一覧にフォーカスがあるときは上下キーでも移動できる。地図で選んだ地点が一覧にある場合はその行までスクロールする。一覧は番号、地点名、標高、所在地（参考）、緯度・経度、よみがな、別名、タグ、SVG、IDの10列。見えている行だけを描画し、列見出しから並び替えられる。横スクロールと列幅調整で右側の列を表示できる。

地点の詳細では出典、取得元での分類、標高の出典、関連ID、タグ、別名、SVG、元のJSONを表示する。「近くの山」は直線距離が近い20地点を表示し、選んだ地点へ移動できる。所在地は座標からの参考判定。行政区域は国土交通省の国土数値情報を共同通信社が加工した[行政区域データ](https://github.com/kyodo-official/japan-choropleth#行政区域)を取得する。

## 地点JSONの互換性

入力仕様は[地点データの形式](../points/formats/data.md)、[地点README](../points/README.md)、版5・版6のJSON Schemaに従う。ビューワは表示用にID・名称・緯度経度・標高・読み・別名・タグを取り出す。ほかの項目を含む配布ファイルも開ける。標高は数値・null・省略を扱う。読みは版5で文字列、版6で文字列または文字列の配列を扱い、両版ともnull・省略を扱う。複数の読みは入力順に表示する。別名は版5の文字列と版6の名前・読みを持つオブジェクトを扱う。

表示項目を変更するときは、スキーマの `$ref` が指す共通定義と地点READMEも確認する。Cargoテストはスキーマから表示項目の型の候補を組み立て、実際の読み込み処理に通す。リポジトリにある国土地理院の地点JSONも読む。共通CIでWindowsとmacOS（Apple Silicon）のリリースビルドとテストを実行する。Windowsではビルドした実行ファイルを起動し、国土地理院の地点JSONを読み込めることも確認する。

## 自動LOD

ツールバーの「オンライン地図の表示設定」でオンライン地図の自動LODを、「地表の表示設定」で地表の自動LODを設定する。上限ズームと選択基準はそれぞれ独立して保存する。上限は利用可能な最大ズームまでの整数スライダーで指定し、初期値は最大。選択基準は+1で目標の画素密度が2倍、−1で半分になる。地表ではタイルの画素数も考慮する。収録範囲より低い上限を指定した場合は最も粗い収録レベルを使う。各行で選んだ固定LODを優先する。新しいレベルの可視タイルを読み込んでから約0.22秒でクロスフェードする。

ツールバーの「地表の表示設定」で、水域・森林・その他の色をまとめて変更できる。「データの既定色」「深緑」「淡色」「高コントラスト」「落ち着いた色」の5種類を用意する。選択は終了時に保存し、後から追加した地表SQLiteにも適用する。濃度と水際の位置は変えず、陰影は従来どおり合成する。「データの既定色」はSQLiteの設定を使い、配色プリセットは森林・水域のマスクと森林レイヤーの背景色に適用する。

## 配布版の公開

GitHub Actions の「データビューワ：下書き Release 生成・検査」を手動で実行する。Windows x64 と macOS Apple Silicon の ZIP を作り、それぞれの実行ファイルで地点 JSON を読み込んで確認する。

1. `main` で実行すると、生成日時から配布名とタグを自動で決め、Draft Release を作る。Release名は[共通の命名規則](../README.md#release名の規則)に従う。タグとZIP名の先頭には `viewer-` を付ける。バージョン番号の指定や更新は不要。作業ブランチでは Release を作らず、2 環境の ZIP を Actions の実行結果から 7 日間ダウンロードできる。
2. Draft の内容を確認し、「共通：Draft-release を試用公開」にそのタグまたは Release URL を指定する。2 環境の ZIP と `SHA256SUMS.txt` を検証し、同じ Release を Pre-release にする。
3. 試用して確認が済んだら、「共通：Pre-release を正式公開」に同じタグを指定する。添付ファイルを再検証して正式 Release にする。タグ・添付ファイル・取得 URL は変えない。ビューワの公開では Pages やデータカタログを更新しない。

配布先を選ぶ `channel` 入力は廃止し、生成時は常に下書きにする。次の配布も同じ Action を実行するだけで作れる。既存のタグや公開済み Release は上書きしない。

共通 Action の `sha256` は任意で、ビューワでは `SHA256SUMS.txt` 自体の SHA-256 を指定する。空欄でも、チェックサム一覧と両 ZIP の一致、ZIP 内の実行ファイルと破損の有無を検証する。公開時に ZIP の再生成・差し替えは行わない。

生成した Draft には整理用マーカーを付け、7 日以上経過した未公開の下書きは共通の整理 Action の対象になる。試用公開するとマーカーを外し、公開済みの Pre-release・正式版を保持する。長く保持する Draft は本文からマーカーを取り除く。

GitHub Releasesでは、ZIPと `SHA256SUMS.txt` を配布する。Windows版はZIPを展開して `yamamuki-viewer.exe` を起動する。macOS版はApple Silicon向けのZIPを展開して `YamamukiViewer.app` を開く。macOS版はアドホック署名で、Appleによる公証は行っていない。

Cargo.toml の `version` は Rust の内部情報として固定し、配布の識別には使わない。macOS の内部の版は UTC の生成日から自動設定する。既存の `viewer-v<版>` の下書きも、引き続き試用公開・正式公開できる。

Release名とGitタグの扱いは、[共通のRelease名の規則](../README.md#release名の規則)に従う。

地形を読み込むと、レイヤー一覧にデータセット名が現れ、チェックで3D地形をON/OFFできる。地形の自動・固定LODはレイヤー一覧で選び、自動LODの上限・精細度はツールバーの「地形の表示設定」で設定する。「地形の表示設定」では傾き調整・境界接合・スムーズ切替・ワイヤーフレームを設定する。3Dのホイール拡縮には地形と同じ透視投影を使い、ドラッグ先の地形標高を参照してカメラの基準標高を補正しない。地図・地表の合成範囲も視点の傾きと方位に追従する。

3Dの地図・地表は、2Dと共用する地図・地表タイルをGPUで直接参照する。地形の画面ピクセルごとに地理座標を記録し、その座標から元タイルをサンプリングして合成する。固定サイズの中間画像へ縮小してから貼る処理は行わない。近景・中景・遠景では取得範囲とLODのみを変え、近景は2Dと同じ画面密度でタイルを準備する。遠景は読込中の粗い代替とLOD切替前の地形も覆う。元タイルのバイリニア補間、陰影、レイヤーの合成順、旧・新LODのクロスフェードを維持し、地形の陰影は合成後に一度だけ適用する。復号キャッシュは距離間で共用し、LODのフェード状態は分離する。

地形データ名の横の「i」ボタンは地形をOFFにしていても使える。ファイル名・パス・データセットID・データ版・形式版・容量・出典などのMetadata JSONに加え、レベルごとのタイル数・制御点数・圧縮BLOB容量・上方/下方の許容誤差と設定JSONを表示する。集計は背景で実行する。「地形の表示設定」のレベル上限は、収録された最小〜最大ズームの整数スライダーで設定する。

地形データの行の「閉じる」で地形とその描画資源を解放し、同じ視点の2D表示へ戻る。地表や地点など、別に読み込んだデータは維持する。「地形の表示設定」の最後の項目はワイヤーフレーム表示の選択メニューで、親メニューと連動するサブメニューとして操作する。

広域の粗い地形では、評価格子の各8区間を目安にパッチへまとめ、粗タイル1枚を無条件に最大1024パッチへ分解しない。表示中の地形タイルと同じ範囲の粗い代替タイルは重複して描かず、画面分割計画が必要なときだけ密度情報を用意する。境界の共通分割と制御点密度による下限は引き続き確認する。

3D表示ではカメラ距離の100 m下限を設けず、オンライン地図の取得上限z18によって視点の接近を制限しない。オンライン地図や地表の取得レベル上限はそのまま適用し、拡大時は取得済みの画像を使う。

ドラッグ移動でも地表への追従・接近回避は行わず、カメラの基準標高を保持する。山へ移動しても自動的にカメラを持ち上げない。

地形の粗いレベルを固定したまま拡大した場合も、保存タイル全体の低密度な格子を引き伸ばさない。可視中心付近の評価領域をタイル内で切り出し、同じレベルの制御点からGPUで自然近傍曲面を再計算する。局所評価キャッシュの分割上限は通常512とし、同じ領域に必要以上の密度のキャッシュがあれば再利用する。局所領域の外側は全体の粗いキャッシュで覆い、端では高さと勾配を接続する。元の保存データ・許容誤差・補間方法を変更したり、拡大時に強い平滑化を掛けたりする処理ではない。

地形の読み込みは現在の画面に必要なタイルを先に準備し、全国の粗い背景タイルは後から読み込む。SQLite接続と復号済みの親点群を共有し、GPU補助情報の作成は最大4件で並列化する。視点を変えたときは古い残りの仕事をバッチ間で打ち切る。情報ウィンドウ用の全件集計は「i」を初めて開いたときに実行する。

全タイル索引はユーザーのキャッシュフォルダー内の `yamamuki-viewer/terrain-index-v1` に保存する。Windowsは `LOCALAPPDATA`、macOSは `~/Library/Caches`、その他は `XDG_CACHE_HOME` または `~/.cache` を使う。元SQLiteは変更しない。パス・ファイルサイズ・更新時刻・データ版が一致した索引だけを再利用し、不一致や破損時はSQLiteから作り直す。キャッシュを使っても、読んだタイルの点数・XYZハッシュ・差分依存の検査は省略しない。

接近時もテクスチャの被覆範囲をゼロへ縮めない。詳細画像の範囲は、オンライン地図の最大ズームと、ONになっている地表レイヤーの収録ズーム・タイル画素数・固定LOD設定から決める最大画素密度を下限にする。中景の範囲には注視標高の平面だけでなく、地形描画と同じ標高範囲（−500〜4,500 m）への透視投影を含める。これは画像の被覆範囲の制御で、カメラの距離や標高を制限する処理ではない。

局所評価は視点中心の一枚に限定せず、視錐台と交差する領域全体を四分木の評価区画で覆う。目標に細かい子タイルがない領域や読み込み中の領域を埋める背景も、同じ画面占有サイズの基準で評価する。完全に目標タイルで覆われた背景だけを省き、同じ元タイルから作った複数の評価区画をすべて描く。評価予算は画面の大きさに対する過密度を見て配分し、細かい既存キャッシュの再利用も予算内に制限する。距離200 mを下限にして分割の増加を止める処理は行わない。

地形のON/OFFだけでオンライン地図や地表の近景LODを変更しない。LOD選択は2D・3Dとも同じ画面ズームと各データ種別の自動LOD設定を使い、3Dのタイル収集用座標系の倍率とは分離する。中景・遠景は画面ズームを上限とし、広い範囲の画像に必要な密度へ落とす。

ズーム操作中の曲面再評価は、GPUの完了通知に合わせて投入量を制限する。未完了の仕事を積み上げず、表示中の曲面を維持しながら残りを後続フレームで準備する。同じ保存タイルの制御点・探索情報は評価区画間で共有し、不要になった途中の評価キャッシュも更新完了を待たずに解放する。

描画パッチの目標間隔は画面上で約3pxとし、従来の約6pxより細かく分割する。曲面評価キャッシュの密度と描画量の予算内で適応し、遠景の分割や境界の共通格子も維持する。保存された地形データのLODや制御点数は変更しない。

カメラ操作中は約3実画素を目標に描画し、停止後0.4秒で約1.5実画素、1.2秒で約0.75実画素へ段階的に細かくする。メッシュだけでなく曲面評価領域と評価密度も更新し、同じ低密度な評価格子を細分化するだけにはしない。各段階の準備中は直前の地形を維持し、操作を再開すると軽い基準へ戻す。高DPI倍率を考慮し、GPU評価量と描画量の予算・境界接合は維持する。

地形の陰影は、タイル合成後の画面色をsRGB値へ戻して倍率を掛け、線形値へ変換して出力する。直接貼付への変更前と同じ明暗を保つため、線形値への単純な乗算は行わない。陰影用の画面色は実画面と同じ解像度で保持し、元タイルを地理範囲の中間画像へ縮小することはない。「地形の表示設定」の「地形の陰影の強さ」で調整できる。

地形は1行目に表示チェック・データセット名・情報（i）・閉じるを表示し、2行目にLOD選択のみを置く。LODは「自動」と収録済みの各ズームを選べる。自動時は現在の主表示レベルも表示し、固定レベルから自動へ戻すと元の自動LOD上限を復元する。ツールバーの「地形の表示設定」の設定と連動する。

3Dの地図・地表キャッシュは近景・中景・遠景を同じ描画フレームとして扱い、3範囲の処理後に一度だけ整理する。別範囲で表示中のタイルを削除して再取得し続けることを防ぐ。近景・中景が未準備の間は、取得済みの広域テクスチャを空白の背景色で上書きしない。

## 選択地点から景色を見る

地点ファイルを開き、リストで標高のある地点を選んで、ツールバーの「選択地点から見る」を押す。地点の標高と、現在表示している地形曲面の標高の高い方＋2mに視点を置き、水平に周囲を見渡す。左ドラッグで向きと仰角・俯角を変更でき、右ドラッグは左右で向き、上下で視点の高さを変更する。上へドラッグすると高くなり、下へドラッグすると低くなる（表示上の1pxあたり1m）。高さの変更は「加算する高さ」に反映し、ドラッグ操作による高さの制限は設けない。ホイールは移動ではなく視野角の変更に使う。「地点視点の設定」で地点からの視点高と視野角を調整できる。別の地点をリストで選ぶと、その地点へ視点を移す。

オンライン地図・地表SQLiteの貼付と地形の自動LODを引き続き使う。「俯瞰視点に戻る」で切替前の地図視点へ戻る。地点の選択を解除した場合、地点ファイルを閉じた場合、地点視点を終了する。地形OFFまたは地形SQLite未読込でも景色モードを使える。その場合は標高0mの平面にオンライン地図・地表を表示し、地点標高＋加算する高さを視点高とする。標高のない地点からの開始はできない。

地図をクリックして座標を選び、「選択座標から見る」を押すと、地点ファイルがなくてもその位置から景色を見られる。標高は表示中の地形レベルの自然近傍曲面と傾き調整から背景スレッドで計算する。視点の高さは、地点からの場合は地点標高と地形標高の高い方、座標からの場合は地形標高に、設定の「加算する高さ」を加えた値。LODや傾き調整が変わった場合は地形標高を再取得する。

「地点の表示設定」メニューの「地点名を常時表示」で、丸印の横に名前を表示できる。名前が重なる箇所は選択地点などを優先して省略し、丸印の表示は維持する。この設定は次回起動時も保存する。

3D・景色モードの地点マークと名前は、俯瞰地図の取得範囲ではなく3D画面への投影結果で絞り込む。背面や近すぎる地点を除き、無限大・非数の頂点はGPUへ送らない。LOD切替では新旧の曲面と背景を含むアトラスを機器の実際のバッファ上限内へ収める。

異常終了時のRustエラーとスタックは、アプリの保存フォルダーの `logs/viewer.log` に追記する。起動時と通常の終了エラーも記録する。メインスレッドのエラーでは保存先をダイアログに表示する。OSやGPUドライバーによる強制終了など、Rustのエラー処理を通らない終了は記録できない場合がある。

元タイル直接貼付のバインドグループとテクスチャビューは再利用し、座標・UV・LOD混合率は共通の動的オフセット付きパラメーターバッファへまとめて更新する。不要なタイルの設定は削除し、描画中も非同期に完了済みGPU資源を回収する。連続描画でディスクリプターが増え続けることを防ぐ。

GPU資源の連続描画検証は `cargo test --release --locked --manifest-path viewer/Cargo.toml -p yamamuki-terrain-view continuous_drawing_reuses_gpu_descriptors_and_uniform_storage -- --ignored --nocapture` で実行できる。`YAMAMUKI_GPU_STRESS_FRAMES` でフレーム数を指定でき、同じ192タイルを描き続けてもバインドグループ生成数と共通バッファ数が一定で、使用しなくなったタイルを解放することを検査する。


3D表示の地点の丸印と名前は、表示中の地形曲面の標高＋2mに配置する。地点JSONの標高はマークの高さに使わない。地形のない場所は標高0mとする。GPUで表示中の曲面と遮蔽を確認し、手前の地形に隠れる丸印・名前・ホバー表示を省く。判定結果は非同期に読み戻す。地形の自動LOD設定は「地形の表示設定」に統合している。

地点名の遮蔽判定を更新している間は直前の結果を保持し、現在のカメラで位置を投影し直す。新しい結果を待つたびに丸印と名前を消すことはしない。地点ファイル行の操作は「i」と「閉じる」とし、「地点全体」ボタンは置かない。

景色モードの地表・オンライン地図は、視点からの距離が2倍になるごとに一段ずつ粗くする複数の範囲で取得する。中景全体に一枚の広域LODを使わず、各範囲の内側境界で約2画面画素に1画像画素の密度を基準とする。オンライン地図と地表のLOD上限・選択基準、地表タイルの画素数、固定LODの指定は引き続き適用する。

「選択座標から見る」はツールバーに表示する。地図をクリックして座標を選ぶと使える。地形OFF・未読込では標高0m＋設定値からの景色になる。

景色モードでは画面右下のズーム表示の上に「視点標高」を常時表示する。地点・地形の標高と加算する高さから求めた実際の視点標高をメートル単位で表示し、右ドラッグや設定の変更に合わせて更新する。

景色モードへの切替時、景色モード中に地図上の地点をクリックしたとき、および選択地点を変更したときは、手動で変更した加算する高さを既定の＋2mへ戻す。同じ地点の再クリックでもリセットする。

地図をクリックして座標を選択すると、読込済みの地形SQLiteからその座標の標高を背景で取得し、座標ラベルに標高を併記する。地形表示中の座標ピンも取得した標高に配置する。標高を取得しただけでは景色モードへ切り替えず、「選択座標から見る」を押したときに取得済みの標高を利用する。別の座標を選んだ場合、古い取得結果を新しい座標へ適用しない。地形データがなければ標高0mの扱いを維持する。

3D表示中のクリックは、平面への逆投影ではなく、深度テストを通過した描画ピクセルの地形座標・標高を読み取る。現在の視点、地形LOD・切替途中の形、傾き調整を反映した位置を選び、空をクリックした場合は座標ピンを置かない。読み戻すのは1ピクセルで、GPU待ちは非同期に処理する。

元タイル直接描画とLOD合成の画像サンプラーは、タイル別の設定から分離して全タイルで共用する。D3D12の2048個のサンプラー領域をタイル数・新旧LODの組合せ数だけ消費しない。GPU負荷試験の `YAMAMUKI_GPU_STRESS_TILES` でタイル数も指定できる。

細かい地形を読み込み済みの範囲では、重なる粗い背景地形を地理座標の被覆でも除外する。画面のステンシルだけで背景を補うと、粗い標高誤差で視点が背景面の内側に入ったとき、空に背景の裏側と地図が出るため。被覆する矩形はGPUへ渡す前に包含関係で整理し、細かい地形がない範囲の背景表示は維持する。

遠景は画面の外側だけでなく、視点標高と標高4500mの山を含む地平線距離（15%の余裕付き）でもカリングする。地表近くの景色モードでは約300〜500kmが目安で、高高度や全国俯瞰では注視距離に応じて広げる。同じ距離をCPUのタイル選択・パッチ分割とGPUの投影、地点表示に用いる。描画用の曲面評価領域は保存タイル全体ではなく実際の小領域の範囲で判定し、遠方・画面外の地図画像も描画設定を作る前に除外する。山の陰に隠れた地形の遮蔽カリングは行っていない。

視野の判定は包囲箱を最初に平面で分類し、完全に画面外なら即座に除外、完全に内側なら面の切断処理を省く。境界をまたぐ箱だけ詳細に切り、カメラを含むタイルや地平線付近を保持する。計測は `cargo test --release --locked --manifest-path viewer/Cargo.toml -p yamamuki-terrain-view benchmark_visible_depth -- --ignored --nocapture` で実行できる。

景色モードでは最近の方向ごとの描画メッシュを最大32組記録し、同じ位置から向きを戻したときに既存のGPUメッシュを直ちに復帰させる。次の方向に対するタイル選択結果が届くまで、旧方向の非同期結果で上書きしない。画面外の描画はカリングしたまま、メッシュを表示対象から外すこととキャッシュの解放を分ける。曲面・制御点探索情報を含むGPUキャッシュの整理上限は512MiBとし、未表示分を一括で捨てず、古い未使用メッシュから必要量だけ解放する。方向の記録も容量不足時に古い順に手放し、表示中のメッシュを保護する。長く見ていない方向は上限に応じて再生成が必要になる場合がある。

地図・地表のカラー画像は、16タイルを元解像度のまま共有画像へ格納する。各タイルの周囲に1pxの複製余白を付け、通常表示・回転・LODクロスフェード・3D貼付のUVを変換する。画像枚数だけeguiのサンプラーを確保しないため、D3D12の2048個制限に達しにくい。未使用領域の再利用は3描画パス待ち、全タイルが不要になった共有画像は解放する。陰影の描画サンプラーも共用する。

3D地形の深度は32ビット浮動小数点の逆Zとし、近くを大きな値、遠くを小さな値で判定する。地表近くから数十〜数百km先を見る際、従来の24ビット深度で遠い面が手前の面を上書きする競合を防ぐ。背景の優先順位は地理座標の被覆で扱い、深度とステンシルの組合せによる優先描画は使わない。GPUのない環境ではGPU固有の試験を省き、形式・CPU・UIの試験を実行する。
