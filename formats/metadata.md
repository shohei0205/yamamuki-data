# metadata フォーマット

[リポジトリの README に戻る](../README.md)

## 概要

データ JSON と配布 manifest で共有する共通情報。各文書のトップレベルに `metadata` object として置く。配布 manifest には、指し示すデータ JSON の `metadata` をそのままコピーする。

配布版・取得先・サイズ・ハッシュ・配布データの生成日時 `dataTimestamp` は manifest の直下に置く。これらは `metadata` に含めない。manifest の項目は [manifest フォーマット](manifest.md) を参照する。

## 版について

metadata の現行版は `1`。`metadata` 自体に `schemaFormat`・`schemaVersion` は置かず、文書全体のスキーマが参照する共通スキーマで版を指定する。地点 JSON・補足 JSON・manifest の版とは独立して管理する。

版内の変更は `版1.1` のように小数点以下で区別する。小数点以下は文書上の番号で、参照するスキーマの版には含めない。

項目表の「版の履歴」は、フィールドの追加や変更があった版を示す。スキーマは版ごとに分けて管理する。

| 形式の版 | 機械検証用スキーマ | 規格 |
|---|---|---|
| 1 | [metadata-v1.schema.json](../schemas/metadata-v1.schema.json) | JSON Schema Draft 2020-12 |

### スキーマからの参照

文書全体のスキーマから `$ref` で共通定義を参照する。

```json
{
  "$ref": "../schemas/metadata-v1.schema.json"
}
```

参照パスは、参照元のスキーマファイルからの相対パスにする。出典一覧だけを共用する場合は `#/$defs/sources`、タグ情報だけなら `#/$defs/tags` を参照する。形式ごとの必須条件は、参照元のスキーマで追加する。

## 共通項目

共通スキーマでは、各項目は任意。`metadata` には空 object を指定できる。未知の項目は許可し、読み手は解釈しない。既知の項目の制約は維持する。

| 項目 | 型 | 必須 | 内容・制約 | 版の履歴 |
|---|---|---|---|---|
| `sources` | object の配列 | 任意 | 出典名を `name` に持つ出典情報の配列。元データと補足の出典を同じ一覧に保持する。各出典の構造は下表を参照 | [版1] 追加 |
| `tags` | object の配列 | 任意 | タグ名を `name` に持つタグ情報の配列。各地点の `tags` 配列とは別の、文書全体で共有する情報 | [版1] 追加 |
| `pointCount` | integer | 任意 | 収録地点の件数。1 以上の整数。地点 JSON の `points` の要素数と一致させる | [版1] 追加 |
| `coverage` | object | 任意 | 対象の国・地域と提供範囲。地点・地表で共通の構造を使う | [版1.2] 追加（Issue #99） |
| `language` | string | 任意 | 含まれる文字列の主な言語。BCP 47 の言語タグ（例: `ja`）。国・地域とは独立 | [版1.2] 追加（Issue #99） |
| `authors` | object の配列 | 任意 | 配布データを編集・加工した主体の配列。元データの作者は `sources` に記載する。各要素の構造は下表を参照 | [版1.1] 追加（#91） |

### 対象地域と提供範囲

`coverage` は国・地域の一覧と、実際にデータを提供する範囲を持つ。国境の図形や元データの取得元をそのまま対象範囲とみなさない。国・地域コードと個々の多角形は対応付けない。

| 項目 | 型 | 必須 | 内容・制約 | 版の履歴 |
|---|---|---|---|---|
| `coverage.regions` | string の配列 | 任意 | 対象の国・地域の ISO 3166-1 alpha-2 コード。大文字2文字、1件以上、重複なし。複数国も指定できる | [版1.2] 追加（Issue #99） |
| `coverage.geometry` | object | 任意 | 全体の提供範囲を表す GeoJSON Polygon / MultiPolygon | [版1.2] 追加（Issue #99） |
| `coverage.finest` | object | 地表のみ任意 | 最も精細な LOD の範囲。指定する場合は全体の `geometry` も必要 | [版1.2] 追加（Issue #99） |
| `coverage.finest.geometry` | object | `finest` 内で必須 | 最も精細な LOD の提供範囲を表す GeoJSON Polygon / MultiPolygon。全体の提供範囲に含まれる | [版1.2] 追加（Issue #99） |

図形は [GeoJSON（RFC 7946）](https://www.rfc-editor.org/rfc/rfc7946) の Geometry object を使い、`type` と `coordinates` を記載する。Feature / FeatureCollection では包まない。`coverage` 自体は独自の metadata object であり、GeoJSON object ではない。

- 座標は WGS 84 の `[経度, 緯度]`、単位は度。高さを含めない。経度は −180〜180、緯度は −90〜90 の有限な数値とする。
- Polygon の最初のリングは外周、以降は穴。リングは4座標以上とし、始点と終点を一致させる。途中の頂点の重複、面積のないリング、自己交差は認めない。穴は外周の内側に置き、ほかのリングとの交差や穴の重なりを認めない。面を分断しない、位相的に有効な点での接触は許可する。
- 離れた領域は MultiPolygon で記載する。領域の内部を重ねない。生成時には重なる面を統合し、外周は反時計回り、穴は時計回りにする。読み込みでは過去の図形との互換性のため逆向きのリングも受け付ける。
- 日付変更線をまたぐ面は経度 ±180 度で分割する。隣接頂点間の経度差が180度を超える辺は認めない。
- 提供範囲の境界上は範囲内、穴の内部は範囲外。地点では範囲内のすべての場所に地点が存在することを保証しない。
- 図形の省略は範囲不明。`null`・空の図形は認めない。国・地域だけが分かる場合は `regions` だけを記載できる。未知の項目は許可する。

地表では `coverage.geometry` を、実際に収録された全レイヤー・全 LOD のタイル領域の和集合とする。`coverage.finest.geometry` は最も精細な LOD の範囲で、LOD の値は記載しない。全体の範囲内でも精細範囲の外で利用できる精細さは、この情報だけでは分からない。最も精細な LOD は、収録タイルの `tilePixels × 2^z` が最大になる解像度で決める。空のレベルは使わない。分割後の各ファイルで両方の範囲を再計算し、単一解像度のファイルでは両者が等しくなる。透明な画像もタイルが収録されていれば範囲に含め、画素ごとの有効・無効までは表さない。中間の LOD ごとの範囲は扱わない。地点・地点補足には `finest` を指定しない。

共通スキーマは図形の型・配列の形・座標の範囲を確認する。リングの閉鎖・交差・穴の位置と、精細範囲の包含は生成・公開処理で別途検証する。`regions` はコードの形式と重複を検証し、登録済みコードの一覧には問い合わせない。

### 文字列の言語

`language` は山名・別名だけでなく、地表画像に焼き込まれた地名・注記などの主な言語を示す。複数国のデータでも、日本語で提供するなら `ja` とする。個々の文字列がすべて同じ言語であることを保証しない。

文字列を含まない場合、不明な場合、主な言語を決められない場合は省略する。`null` や空文字は使わない。BCP 47 の構文と variant・拡張 singleton の重複を検証するが、IANA の登録済みタグ・subtag との照合は行わない。

`nameLanguage`・`nameReadingScript` は追加しない。日本語の読みはひらがなで提供し、文字の種類を表す別項目は持たない。中国語などの読みの表記方式は、この版では定義しない。

### 出典ごとの情報

`sources` の各要素は、必須の `name` と任意の出典情報を持つ object。`name` は空文字・前後の空白・配列内の重複を認めない。タグ名やファイル名とは独立して扱う。以下の項目は `metadata.sources[]` に置く。

| 項目 | 型 | 必須 | 内容・制約 | 版の履歴 |
|---|---|---|---|---|
| `name` | string | 必須 | 出典名。配列内で重複しない名前 | [版1] 追加 |
| `source` | string | 任意 | 資料名・参照 URL | [版1] 追加 |
| `license` | string | 任意 | 資料に適用される利用条件の名称・版・説明 URL | [版1] 追加 |
| `attribution` | string | 任意 | 利用条件に従って表示する著作者名・出典表示 | [版1] 追加 |
| `changes` | string | 任意 | 資料に加えた加工・変更 | [版1] 追加 |
| `latestTimestamp` | string | 任意 | この出典に由来する収録データの最終更新日時。タイムゾーン付き ISO 8601。取得日時や配布データの生成日時ではない。不明なら省略する | [版1] 追加 |

`name` 以外の出典属性は任意。未知の属性は許可し、読み手は解釈しない。既知の属性には指定された型を使う。日時を推測で補わない。検証時は JSON Schema の `format` 検査を有効にする。

### 作成者ごとの情報

`authors` の各要素は、必須の `name` と任意の役割・URL を持つ object。`name` は空文字・前後の空白・配列内の重複を認めない。配列を指定する場合は 1 件以上にする。以下の項目は `metadata.authors[]` に置く。

| 項目 | 型 | 必須 | 内容・制約 | 版の履歴 |
|---|---|---|---|---|
| `name` | string | 必須 | 作成者名。配列内で重複しない名前 | [版1.1] 追加（#91） |
| `role` | string | 任意 | 配布データに対して行ったこと（例: `配布データの編集・加工`） | [版1.1] 追加（#91） |
| `url` | string | 任意 | 作成者の説明ページの URL | [版1.1] 追加（#91） |

`authors` は配布データを作った主体の記録で、元データのライセンスが求める帰属表示を置き換えない。利用者への表示の義務も新たに生じない。元データの出典・利用条件・帰属表示は、これまでどおり `sources` に記載する。未知の属性は許可し、読み手は解釈しない。

### タグごとの情報

`tags` の各要素は、必須の `name` と任意の読みを持つ object。`name` は空文字・前後の空白・配列内の重複を認めない。以下の項目は `metadata.tags[]` に置く。

| 項目 | 型 | 必須 | 内容・制約 | 版の履歴 |
|---|---|---|---|---|
| `name` | string | 必須 | タグ名。各地点の `tags` の値と一致させる | [版1] 追加 |
| `nameReading` | string または string の配列 | 任意 | タグ名の読み。複数ある場合は重複のない1件以上の文字列配列。空文字や前後の空白・空配列は指定できない | [版1] 追加 |

読みが不明なら `nameReading` を省略する。読みがなくても `name` は必須。未知の属性は許可し、読み手は解釈しない。既知の属性には指定された型を使う。

読みを登録していないタグは読みなしとして扱う。読みのあるタグを読みの文字コード順、同じ読みならタグ名の文字コード順で並べ、読みのないタグはその後にタグ名の文字コード順で並べる。配列の記載順には依存しない。読みをひらがなで記載する運用では、検証処理は空でない文字列かを確かめ、ひらがなだけかどうかは検査しない。

## 形式ごとの条件

| 形式 | metadata の扱い |
|---|---|
| [地点 JSON](../points/formats/data.md) | `metadata` と各項目は任意。生成時は実際の地点数を `pointCount` に設定する |
| [補足 JSON](../points/formats/supplements-data.md) | `metadata` は任意。`sources` と `tags` を使い、`pointCount` は指定しない |
| [配布 manifest](manifest.md) | `metadata` と、1 件以上の `sources` は必須。地点データの manifest では `pointCount` も必須。内容はデータ JSON と一致させる |

必須条件は各形式のスキーマで検証する。本体と manifest の一致や、`pointCount` と実際の件数の一致はスキーマだけでは確認できないため、生成・公開処理で照合する。

## JSON の例

地点 JSON の `metadata` の例。manifest にも同じ object をコピーする。URL・件数・日時は説明用の値。

```json
{
  "metadata": {
    "sources": [
      {
        "source": "見本の地名資料 https://example.com/source",
        "license": "CC BY 4.0 https://creativecommons.org/licenses/by/4.0/",
        "attribution": "見本資料の著作者",
        "changes": "地点名・座標・標高を抽出",
        "latestTimestamp": "2026-10-14T00:00:00Z",
        "name": "元資料"
      },
      {
        "source": "見本の山名一覧 https://example.com/supplement",
        "license": "CC0-1.0",
        "attribution": "見本の補足資料の作成者",
        "changes": "読み・別名・タグを追加",
        "latestTimestamp": "2026-10-14T01:00:00Z",
        "name": "補足資料"
      }
    ],
    "tags": [
      {
        "name": "日本百名山",
        "nameReading": ["にほんひゃくめいざん", "にっぽんひゃくめいざん"]
      }
    ],
    "pointCount": 1,
    "authors": [
      {
        "name": "見本の作成者",
        "role": "配布データの編集・加工",
        "url": "https://example.com/authors"
      }
    ]
  }
}
```

### 対象範囲と言語

座標は説明用の仮の値。実際の提供範囲ではない。地点は `finest` を省略し、地表は必要に応じて追加する。

```json
{
  "metadata": {
    "coverage": {
      "regions": ["JP", "KR"],
      "geometry": {
        "type": "MultiPolygon",
        "coordinates": [
          [[[130, 30], [140, 30], [140, 40], [130, 40], [130, 30]]],
          [[[126, 34], [129, 34], [129, 39], [126, 39], [126, 34]]]
        ]
      },
      "finest": {
        "geometry": {
          "type": "Polygon",
          "coordinates": [
            [[131, 31], [139, 31], [139, 39], [131, 39], [131, 31]]
          ]
        }
      }
    },
    "language": "ja"
  }
}
```

## 変更履歴

### 版1.2（2026-11-13）

- 対象地域と GeoJSON の提供範囲を示す任意の `coverage`、文字列の主な言語を示す任意の `language` を追加する（Issue #99）。未知の項目を許可する既存の読み手とスキーマで扱えるため、JSON の形式の版は上げない。
- 地表の最も精細な範囲は `coverage.finest.geometry` に記載する。地点には指定しない。

### 版1.1（2026-11-04）

- 配布データを編集・加工した主体を記録する任意の `authors` を追加する。未知の項目を許可する版1のスキーマ・読み手で扱えるため、版は上げない（#91）。

### 版1（2026-10-14）

- 地点 JSON・補足 JSON・配布 manifest の共通定義をまとめる。
- 出典一覧 `sources`、タグ情報 `tags`、地点件数 `pointCount` を定義する。
- `sources`・`tags` は object の配列とし、出典・タグはそれぞれ必須の `name` で識別する。識別子の重複は認めない。未公開の版1に統合する。
- 出典ごとの最終更新日時は `sources[].latestTimestamp` に記載する。
