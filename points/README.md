# 地点データ

[リポジトリの README に戻る](../README.md)

山頂やランドマークなど、名前と位置を持つ地点データの共通形式をまとめる。生成処理・収録条件・配布手順は、取得元と対象ごとのフォルダに分ける。

| 対象・取得元 | 状態 | 詳細 |
|---|---|---|
| OpenStreetMap の山頂 | 実装済み | [osm-peaks](osm-peaks/README.md) |
| 手動作成のテスト用地点 | 開発版限定 | [testdata](testdata/README.md) |
| ランドマークなど | 将来追加予定・未実装 | 追加時に専用フォルダを作る |

## フォルダ構成

```text
points/
  README.md         地点データの一覧・共通形式
  osm-peaks/
    README.md       OSM 山頂データの生成・公開手順
    scripts/        取得・生成・検査・公開
    tests/          山頂データのテスト
  testdata/
    README.md       開発版限定のテストデータの生成・公開手順
    points.json     手動作成した架空の地点データ
schemas/points/
  data-v5.schema.json     地点データのスキーマ
  catalog-v1.schema.json  地点カタログのスキーマ
```

取得元・対象ごとに専用フォルダを作り、収録条件・作成方法・配布先を各 README に記載する。スキーマはリポジトリ直下の `schemas/points/` に、`data-v<版>.schema.json`・`catalog-v<版>.schema.json` として保存する。

## 地点データの manifest

manifest の共通項目は [ルート README](../README.md#manifestjson) を参照する。地点データでは共通スキーマの `#/$defs/pointManifest` を使い、次の追加項目を検査する。

| 項目 | JSON の型 | 必須 | 内容 |
|---|---|---|---|
| `pointCount` | integer | 必須 | JSON 配列に収録した地点数。正の整数 |
| `latestPointTimestamp` | string または null | 任意 | 収録地点の元データ上の最終編集日時の最大値。不明なら省略 |

展開後は `pointCount` と配列の件数を照合する。`latestPointTimestamp` は現地調査日・標高の測定日・生成日時ではない。`sourceTimestamp` もある場合はそれ以下とする。地点以外の件数・日時をこれらの項目に入れない。

## 公開データのカタログ

公開済みの地点データすべてのダウンロードと検証に必要な情報を、次のカタログから取得できる。

| 配布先 | カタログ |
|---|---|
| 正式版 | [正式版のカタログ](https://shohei0205.github.io/yamamuki-data/points/catalog.json) |
| 開発版 | [開発版のカタログ](https://shohei0205.github.io/yamamuki-data/points/catalog-dev.json) |

正式版の `points/catalog.json` には正式版のデータだけ、開発版の `points/catalog-dev.json` には開発版のデータだけを収録する。配布先は取得したカタログの URL で区別する。アプリは利用する配布先のカタログを取得し、他方に自動で切り替えない。まだ公開していないデータや地形など地点以外のデータは含めない。

機械検証用のスキーマは [地点カタログの版1](../schemas/points/catalog-v1.schema.json) を参照する。同じカタログ内の `id` は重複させない。

| 項目 | 内容 |
|---|---|
| `schemaVersion` | カタログの形式の版。現在は整数の `1`。manifest・地点データの版とは独立 |
| `datasets` | データセットの配列。公開済み地点データがない場合は `[]` |
| `datasets[].id` | データセット名（例: `osm-peaks`）。地点の `id` と組み合わせて識別する |
| `datasets[].name` | データセットの表示名（例: 山頂）。識別には `id` を使う |
| `datasets[].manifestUrl` | 対応する最新版 manifest の HTTPS URL（個別取得用） |
| `datasets[].manifest` | manifest の内容。形式の版・データの版・`downloadUrl`・ファイル名・SHA-256・圧縮前後のサイズ・件数・出典などを含む |

両カタログは公開・削除時にサイト全体の manifest 一覧から自動生成し、他の地点データと配布先を引き継ぐ。アプリは利用する配布先の項目を選び、同梱された `manifest.downloadUrl` から本体を取得する。manifest を別途取得する必要はない。`manifest.sizeBytes`・`manifest.sha256` で取得した gzip を検証し、展開後にサイズと件数を照合する。形式の版とデータの版も同梱情報から確認する。manifest とカタログは同じ Pages 配置で更新し、配置後に一致を確認する。生成物は git に含めない。サイト全体の更新用 `/catalog.json` とは別の、地点データの取得先を一覧するファイル。

`manifest` はカタログに必ず含める。

同梱情報は公開する manifest のコピーで、アプリ側で URL を組み立てない。件数は `pointCount` で確認する。

表示名は各データセットの manifest の `name` から取得する。山頂は「山頂」として生成し、正式版・開発版で同じ名前を使う。カタログ生成時は必ず `name` を出力する。

### カタログから削除する

Actions の「地点：カタログから削除」→「Run workflow」で、正式版なら `main`、開発版なら `dev` を選び、`dataset` に `osm-peaks` などのデータセット名を入力する。配布先は実行元ブランチで決まり、対象の配布先だけを削除する。

地点カタログとサイト全体の一覧から対象を除き、その manifest・公開履歴の Pages ファイルも削除する。他のデータ・配布先・公開履歴、Release とデータ本体は保持する。

既存一覧の取得・検証に失敗した場合や対象がない場合は配置を中止する。公開と同じ `publish-data-pages` グループで直列化し、配置後にカタログと履歴の一致を確認する。削除済みデータを再度公開すれば一覧に戻る。定期生成があるデータは次回の公開時に再掲載されるため、継続して配布を止める場合は生成・公開の運用も変更する。

### アプリで利用できるデータを判定する

アプリは、カタログ自身の `schemaVersion` に対応していることを確認し、各データの `manifest.schemaVersion` と `manifest.dataSchemaVersion` をそれぞれ確認する。単純に「現在の版以下」と比較せず、アプリが対応すると明示した版の一覧に含まれるかで判定する。

例えばカタログ版1・manifest 版5・地点データ版5に対応するアプリなら、各データの同梱 manifest が `"schemaVersion": 5`・`"dataSchemaVersion": 5` のときに利用できる。非対応の項目はダウンロードせず、対応しているほかのデータは利用できる。読み込みに失敗しても保存済みデータは消さない。

`dataSchemaVersion` は新規生成の manifest に必ず含め、カタログにもそのまま同梱する。版が不明な場合は、アプリは利用不可として扱い、manifest の版から本体の版を推測しない。

この判定は読み込み側アプリで実装する契約であり、このリポジトリでは判定に必要な版の情報を生成・配布する。

## 地点データをブラウザで確認する

[viewer.html](viewer.html) を保存して、Edge や Chrome などのブラウザで直接開く。ローカルサーバーは不要。地点データは内蔵しておらず、起動時は空の状態になる。右上の「使い方」から説明を開ける。

### 地点 JSON を開く

「地点 JSON ファイルを開く」で、共通形式の JSON または JSON.gz を選ぶ。osmId のない手動作成の地点も読み込める。gzip の読み込みには DecompressionStream に対応するブラウザが必要で、対応していない場合は展開した JSON を使う。

読み込み時は必須項目、ID の重複、緯度・経度、osmId、タグの形式を確認する。不正な場合は現在のデータを保持する。読み込み結果は画面下に 5 秒間表示する。別の地点 JSON を開くと、読み込んだタグ CSV と画面上のタグ編集は解除される。切り替える前に必要な編集を保存する。

### 一覧と地図

| 列 | 内容 |
|---|---|
| 地点名 | 地点 JSON の name |
| 標高 (m) | elevationM。値がない場合は空欄 |
| 所在地（参考） | 座標から判定した都道府県・市区町村 |
| 緯度・経度 | latitude・longitude |
| ID / osmId | osmId があれば OSM へのリンク。なければ通常の id |

行のどこをクリックしても、その地点の詳細を表示し、現在の縮尺のまま地図を移動する。ID の OSM リンクは別タブで開く。左右のペインは個別にスクロールでき、中央の境界をドラッグすると幅を変えられる。境界を選択した状態で左右キーでも幅を調整できる。狭い画面では地図と一覧を上下に並べる。

検索欄とタグ選択欄で、一覧と地図を同時に絞り込む。タグは「(JSON)」「(CSV)」を区別し、同じ名前でも別の選択肢になる。画面で追加したタグと「タグ一括追加」で作ったタグは (CSV) に含める。「絞り込みを解除」は検索語とタグ条件を解除し、条件がないときは無効になる。絞り込み・解除・タグ編集では地図の縮尺を変えず、新しい地点 JSON を開いたときだけ全地点に合わせる。

### 地点のタグを編集する

地点の詳細パネルでは、タグ名を入力するか既存タグの候補を選び、「タグを追加」を押す。タグの × で削除できる。タグで絞り込んでいるときは、一覧の「このタグから削除」でも、その地点から該当タグを削除できる。削除後も絞り込み条件は保持する。

詳細パネルの「読み込んだ元データ」は入力 JSON をそのまま表示し、画面上のタグ編集は反映しない。JSON を保存する機能はない。編集結果はタグ CSV として保存する。

### タグ CSV を開く

「タグ CSV ファイルを開く」で、タグ別の CSV を選ぶ。複数選択でき、ファイル名から拡張子 .csv を除いた部分をタグ名として、osmId で地点に対応付ける。見出しは `#osmId,name` とし、従来の `osmId,name` も受け付ける。

```csv
#osmId,name
204683948,羊蹄山
```

元の JSON のタグを保って CSV のタグを追加し、読み込んだタグで自動的に絞り込む。複数ファイルの場合は最後のタグを選ぶ。同名の CSV を開き直すと、その対応表を差し替える。画面での追加・削除は別に保持されるため、同じ地点への編集は引き続き有効になる。

存在しない osmId、ID の重複、不正な列や値がある場合は、選択したファイルを適用せず現在の表示を保つ。山名が地点 JSON の name・aliases と一致しない場合は要確認として表示する。読み込み結果は一時通知に、エラーや山名の不一致は上部に表示する。

### タグを一括追加する

1. 「タグ一括追加」を開き、山の一覧を貼り付ける。1 行に 1 地点とし、山名のみ、osmId のみ、両方の 2 列を使える。CSV 形式のテキストや表計算ソフトからの貼り付けに対応する。見出しを付ける場合は name・osmId を使う。
2. 「照合して補完」を押す。タグ名が空でも照合できる。山名・別名から osmId を補い、osmId から山名を補う。同名の候補が複数ある場合は、すべて追加対象にする。「補完した対応表」は見出し行なしで表示する。
3. 要確認の行があれば、候補検索・選択や山名・osmId の直接入力で修正する。候補には所在地・標高・座標を表示し、OSM リンクから登録内容も確認できる。不要な行や重複は「除外」にチェックし、「修正した内容で再照合」を押す。
4. 全行の照合が済んだら、既存タグを選ぶか新しいタグ名を入力し、「タグを一括追加」を押す。同名タグの既存地点を残して追記し、同じ osmId は重複させない。追加したタグは (CSV) として絞り込める。

この画面は追加専用で、CSV の読み込み・保存は上部のボタンから行う。反映だけではファイルに保存されない。

### 保存とクリア

「タグ CSV を保存」を押すと、保存するタグの選択画面が開く。選んだタグが付いている全地点を、絞り込みに関係なく保存する。BOM 付き UTF-8・LF で、見出しを `#osmId,name` にして書き出す。osmId のない地点を含むタグや、ファイル名に使えないタグ名は保存できない。

対応ブラウザでは保存先とファイル名を選べる。既存ファイルを選ぶとそのファイルへ保存する。非対応の環境では通常のダウンロードに切り替わり、保存先はブラウザの設定に従う。キャンセルや保存失敗では未保存の編集を保持する。選んだタグの全地点を削除した場合は、見出しだけの CSV を保存できる。

「タグ CSV をクリア」は、確認後に読み込んだ CSV のタグと画面上の追加・削除をすべて取り消し、元の JSON のタグへ戻す。JSON のタグをすべて消す操作ではない。解除する内容がないときは無効になる。

未保存のタグ編集がある場合は、タブを閉じる・再読み込み・別ページへの移動時にブラウザ標準の確認を表示する。保存状態はタグごとに判定するため、一部のタグだけ保存しても、ほかに未保存の編集があれば確認を続ける。元の JSON や CSV は、読み込みや画面上の編集だけでは書き換えない。

### 所在地の判定と通信

所在地は、[共同通信社の japan-choropleth](https://github.com/kyodo-official/japan-choropleth) が加工した国土交通省「国土数値情報 行政区域データ 2025 年版」（CC BY 4.0）を取得し、座標と照合する。約 9.7 MB の全国市区町村境界を一度取得し、同じ画面では再利用する。所在地は参考値で、境界付近では実際と異なる場合がある。取得できない場合は「未判定」、該当する行政区域がない場合は「不明」と表示する。所在地は元の JSON やタグ CSV には追加しない。

地図ライブラリ・地理院タイル・境界データの取得には通信が必要。地点ファイルはブラウザ内で処理し、読み込んだファイルや地点の座標をアップロードしない。地図を取得できない場合も、一覧・詳細表示・タグ編集は使える。

### HTML と補完ツール

共通ビューアは [viewer.html](viewer.html) だけを編集する。CSV の補完ツールが生成する確認用 HTML も同じファイルを元にする。別の場所へコピーする場合は、[補完ツールの --viewer](osm-peaks/tags/README.md#ブラウザで地点データを選ぶ) も使える。ビューアの読み込み検査は、公開前のスキーマ検査の代わりにはしない。

## 地点の形式

データ本体は gzip で圧縮した UTF-8（BOM なし）の JSON 配列とし、配列の各要素を1地点のオブジェクトとする。以下は山頂・ランドマーク・手動作成の地点に共通するスキーマで、現在の地点データのスキーマは版5で、山頂の新規生成もこの版を使う。地点データの版は manifest の版と独立して管理する。manifest の形式と版は [リポジトリ共通仕様](../README.md#manifestjson) に従う。

機械検証用の [地点データの版5](../schemas/points/data-v5.schema.json)（JSON Schema Draft 2020-12）は、gzip 展開後の JSON 配列に適用する。配列は1地点以上とし、定義していない地点の項目は許可しない。データセット全体での `id` の重複、別名と表示名の一致、数値が有限であることは別途確認する。URL の `format` 検査も有効にする。

### 項目

「必須」は項目自体を省略できないことを表す。必須項目は `id`・`name`・`latitude`・`longitude` の4つで、`null` は許可しない。すべての任意項目は省略と `null` を同じ意味として扱う。`aliases`・`tags` は空配列、`type` は種別不明、`graphic` は画像なし、`graphic.scale` は `1.0` として扱う。

| 項目 | JSON の型 | 必須 | 内容・制約 |
|---|---|---|---|
| `id` | string | 必須 | データセット内で一意な、空でない固定 ID。取得元の接頭辞は不要 |
| `graphic` | object または null | 任意 | `svg` に SVG 本文、任意の `scale` に表示倍率を持たせる。省略時は画像なし |
| `tags` | string の配列 または null | 任意 | 日本百名山などの分類ラベル。省略時は `[]`。空文字・前後の空白・重複は不可 |
| `type` | string または null | 任意 | 地点の種別。`peak`（山頂）、`parking`（駐車場）、`trailhead`（登山口）、`landmark`（目印）など。省略時は種別不明 |
| `osmId` | integer または null | 任意 | 関連する OSM ノードの正の整数 ID。関連付けがない場合は省略または `null` |
| `name` | string | 必須 | 空でない表示名 |
| `latitude` | number | 必須 | WGS 84 の緯度（度）。−90 以上90 以下 |
| `longitude` | number | 必須 | WGS 84 の経度（度）。−180 以上180 以下 |
| `elevationM` | number または null | 任意 | 地点自体の標高（m）。不明なら `null`。負の標高も使用できる |
| `nameReading` | string または null | 任意 | 表示名の読み仮名。不明なら `null` |
| `aliases` | string の配列 または null | 任意 | 別名。ない場合は `[]`。空の名前・表示名と同じ名前・重複は含めない |
| `wikipediaUrl` | string または null | 任意 | Wikipedia の解説記事の HTTPS URL。ない場合は `null` |
| `wikidataUrl` | string または null | 任意 | Wikidata の項目の HTTPS URL。ない場合は `null` |

数値に `NaN` や無限大は使用しない。文字列の名前・読み仮名・別名は前後の空白を除く。標高に建物の高さなどを入れない。リンク先の記事本文は同梱しない。

### JSON の例

次の配列は、OSM 由来の山頂と、OSM との関連付けがない手動作成の地点の形式を示す。手動作成の地点は説明用の架空のデータ。

```json
[
  {
    "id": "3403990450",
    "type": "peak",
    "osmId": 3403990450,
    "name": "万三郎岳",
    "latitude": 34.8627963,
    "longitude": 139.0018525,
    "elevationM": 1405.6,
    "nameReading": "ばんざぶろうだけ",
    "aliases": ["天城山"],
    "wikipediaUrl": "https://ja.wikipedia.org/wiki/%E5%A4%A9%E5%9F%8E%E5%B1%B1",
    "wikidataUrl": null
  },
  {
    "id": "example-tower",
    "type": "landmark",
    "name": "展望塔",
    "latitude": 35.0,
    "longitude": 139.0
  }
]
```

### 地点ごとのグラフィック

任意の `graphic.svg` に SVG 本文を文字列として内蔵する。JSON 内の引用符・改行などは通常の JSON 文字列としてエスケープする。画像を持たない地点は `graphic` 自体を省略または `null` とする。

```json
{
  "id": "fuji",
  "type": "peak",
  "name": "富士山",
  "latitude": 35.3606,
  "longitude": 138.7274,
  "graphic": {
    "svg": "<svg xmlns=\"http://www.w3.org/2000/svg\" viewBox=\"0 0 100 100\"><path d=\"M10 90 L50 10 L90 90 Z\"/></svg>",
    "scale": 1.5
  }
}
```

`scale` はアプリの標準表示サイズに対する幅・高さの倍率で、省略または `null` の場合は `1.0`。有限の正の数とする。富士山を通常より大きくする場合は `1.5` などを指定する。縦横比は `viewBox` から維持し、ラベルや他の画像との重なり判定にも倍率を反映する。表示倍率と SVG 自体の縦横サイズは独立する。

SVG はデータ本体の gzip に含まれるため、画像の追加ダウンロード・assetId・manifest の画像一覧は不要。カタログに同梱された manifest のサイズと SHA-256 で、SVG を含むデータ本体全体を検証する。同じ SVG を複数地点で使う場合も、それぞれの地点に本文を記載する。

SVG は UTF-8 の静止画とし、有効な `viewBox` と SVG の名前空間を必須にする。SVG 本文はUTF-8で100,000バイト以内。固定の縦横サイズや縦横比は設けない。パス・基本図形・グループ・グラデーション・クリッピングを使用できる。文字はパスに変換し、スクリプト・アニメーション・外部参照・埋め込み画像・CSS・フォント依存は使用しない。詳細な許可要素・属性は [graphics.py](osm-peaks/scripts/graphics.py) に定義する。生成時と公開前に SVG の内容と倍率を検査する。

`graphic` は任意項目の追加なので地点データの版は据え置く。アプリ側では SVG 非対応・描画失敗時に `type` に応じた標準アイコンへ戻す。画像表示はアプリ側で別途実装する。SVG の著作権・利用条件は地点データとは別に確認し、取得元・作成者・利用条件を各データセットの資料に記載する。

### 地点の種別

`type` は1地点につき1つの文字列で表す。小文字の英字で始め、続きには小文字の英数字・下線を使う。

| 値 | 意味 |
|---|---|
| `peak` | 山頂（山頂生成処理で収録する火山ノードを含む） |
| `parking` | 駐車場 |
| `trailhead` | 登山口 |
| `landmark` | 塔などの目印 |
| `mountain_hut` | 山小屋・避難小屋 |
| `campsite` | キャンプ場・テント場 |
| `water_source` | 水場 |
| `toilet` | トイレ |
| `viewpoint` | 展望地点 |
| `pass` | 峠 |
| `junction` | 登山道の分岐 |

例: `{"id":"trailhead-parking","type":"parking","name":"登山口駐車場","latitude":35.0,"longitude":139.0}`。

任意項目の追加として地点データの版は5のままとする。既存データでは省略可能とし、新規の山頂生成では必ず `peak` を出力する。省略やアプリが知らない種別は種別不明として扱い、その地点の名前・座標などは引き続き利用する。未知の種別を理由にデータセット全体を拒否しない。種別は今後追加でき、追加時はこの表と該当データの仕様を更新する。

### ID とデータセット

`id` は名前・座標を変更しても維持し、削除した ID を別の地点に再利用しない。OSM 山頂ではノード番号を先頭ゼロなしの文字列にし、手動作成では `"example-tower"` のような短い値を付ける。

アプリ側では「データセット名＋id」の組で地点を識別する。同じデータセットを複数ファイルに分ける場合も、そのデータセット全体で ID を一意にする。異なるデータセット間では同じ ID を使用できる。同一地点が複数のデータセットに含まれる場合の統合は別に判断する。

項目の取得方法・配列の並び順・収録対象の重複の扱いは各データの仕様に記載する。山頂では OSM ノード番号の数値順に並べる。

manifest の共通仕様は [リポジトリ共通の manifest.json](../README.md#manifestjson) を参照する。

## OSM との関連付け

手動作成の地点でも任意の `osmId` を指定できる。`id` は地点自体の永続的な識別子、`osmId` は関連する OSM ノードへの参照として扱う。

```json
{"id":"example-tower","osmId":123456,"name":"展望塔","latitude":35.0,"longitude":139.0}
```

上記は形式説明用の架空の地点・番号であり、実データでは確認した番号を指定する。`osmId` は正の整数とし、関連付けがない場合は省略または `null` とする。文字列は使わない。

OSM 由来の山頂は `id` と `osmId` の両方を出力する（例: `id` が `"123456"`、`osmId` が `123456`）。手動作成の地点は OSM の関連先を変更・削除しても元の ID を維持する。関連付けだけでデータの自動統合・上書きは行わない。

`osmId` はノードの番号を表す。way・relation は同じ番号のノードと区別できないため、この項目には指定しない。それらとの関連付けが必要になった時点で種別の表し方を追加する。

## データを追加するとき

`points/<取得元と対象>/` に `README.md`・`scripts/`・`tests/` をまとめる。例えば OSM のランドマークを追加する場合は `points/osm_landmarks/` とし、実装時にこの一覧とルートの一覧を更新する。生成物は各フォルダの `build/`・`dist/` に置き、git に含めない。

manifest は [リポジトリ共通仕様](../README.md#manifestjson) に従い、公開 URL・ファイル名・元データの取得方法・公開時の件数基準はデータセットごとに定める。生成・公開処理の共通化は追加データの要件に応じて行う。

## 地点のタグ

`tags` は種別と独立した任意の分類ラベルで、1地点に複数付けられる。例: `"tags": ["日本百名山", "花の百名山"]`。文字列をそのまま識別に使い、大文字・小文字や表記の違いは別タグとして扱う。同じ分類には同じ表記を使う。タグの順番に意味は持たせない。タグがない場合は省略・`null`・`[]` のいずれでもよい。

OSM の元タグをそのまま収録する項目ではない。データ作成者が分類を確認して付ける。山頂データの生成時は、[タグ別 CSV](osm-peaks/tags/README.md) の osmId と照合してタグを追加する。山名から百名山などの分類を推測しない。任意項目の追加のためスキーマの版は5のままとし、アプリは未知の項目・タグを無視できるようにする。

## リリース済みアプリ向けの互換データ

復元用ブランチから公開する `peaks/` と、存在する場合の `peaks-dev/` のmanifest・履歴は、リリース済みアプリのテスト用に保持する。main/devからの公開、地点カタログからの削除、テストデータの公開でも、既存の互換データを引き継いで同じ内容を配置する。osm-peaksの更新で互換データを上書きしない。互換データは地点カタログには含めない。存在しない互換データを新たに作成することはない。
