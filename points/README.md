# 地点データ

[リポジトリの README に戻る](../README.md)

山頂やランドマークなど、名前と位置を持つ地点データの共通形式をまとめる。生成処理・収録条件・配布手順は、取得元と対象ごとのフォルダに分ける。

| 対象・取得元 | 状態 | 詳細 |
|---|---|---|
| OpenStreetMap の山頂 | 全国 JSON を生成・検査し、正式版・開発版を Release で配布。開発版の最新版 manifest は Pages で公開 | [osm-peaks](osm-peaks/README.md) |
| 国土地理院の山頂 | コミット済み JSON から Release を作成 | [gsi-peaks](gsi-peaks/README.md) |
| 手動作成のテスト用地点 | 開発版限定 | [testdata](testdata/README.md) |
| ランドマークなど | 将来追加予定・未実装 | 追加時に専用フォルダを作る |

## データを取得して利用する

OSM 山頂とテスト用地点は、次の手順で取得して利用できる。

| データ | 取得する版の選び方 |
|---|---|
| OSM 山頂 | [OSM 山頂の取得先](osm-peaks/README.md)を参照する。開発版（Pre-release）は Pages の manifest から取得できる。正式版の新しい Release は Pages に反映しないため、[Releases 一覧](https://github.com/shohei0205/yamamuki-data/releases)で `osm-peaks-<version>` の版を選び、Assets の `manifest.json` を取得する |
| テスト用地点 | [開発版カタログ](https://shohei0205.github.io/yamamuki-data/points/catalog-dev.json)の `id` が `testdata` の項目を選ぶ。正式版は配布しない。データの内容は [テスト用地点の README](testdata/README.md)を参照する |

1. manifest を取得する。カタログを使う場合は、対象項目の `manifest` に同じ情報が入っているため、別途取得する必要はない。
2. manifest の `schemaVersion` とデータ本体の `dataSchemaVersion` に対応していることを、それぞれ確認する。項目の説明は [配布データの取得情報](../README.md#配布データの取得情報manifestjson)、カタログからの判定方法は [カタログの読み込みと検証](formats/catalog.md#読み込みと検証)を参照する。
3. `downloadUrl` から gzip ファイルを取得し、展開前に `sizeBytes` と `sha256` を照合する。
4. gzip を展開し、JSON のバイト数を `uncompressedSizeBytes`、`points` 配列の件数を `pointCount` と照合する。
5. [地点 JSON の形式](#地点-json-の形式)に従って文書内の `points` 配列を読む。山頂だけを使う場合は `type` が `peak` の地点を選ぶ。地図上で確認したい場合は [地点データビューアの操作手順](#地点データをブラウザで確認する)を参照する。
6. [出典・利用条件](../README.md#ライセンス)を確認し、利用するデータに必要な出典表示を行う。

OSM 山頂の配布データには補足が適用済みで、利用するアプリが補足 JSON を別に読み込む必要はない。補足前の値を確認・編集する場合は、[元データと補足の取得・編集手順](osm-peaks/README.md)を参照する。

## フォルダ構成

```text
points/
  README.md         地点データの一覧・共通形式
  viewer.html       地点データの共通ビューア
  tests/            共通処理・ビューアのテスト
  formats/          地点データ・カタログ・補足の形式説明と変更履歴
  schemas/          地点データ・カタログ・補足の版ごとのスキーマ
  osm-peaks/        OpenStreetMap の山頂データ
  gsi-peaks/        国土地理院の山頂データ
```

取得元・対象ごとに専用フォルダを作る。フォルダ内の構成・収録条件・作成方法・配布先は、[OSM 山頂](osm-peaks/README.md)、[GSI 山頂](gsi-peaks/README.md)、[テストデータ](testdata/README.md) の各 README を参照する。スキーマのファイル名と対応する版は、各フォーマット文書に記載する。

## 公開データのカタログ

Pages に掲載されている地点データの取得・検証情報を、次のカタログから取得できる。正式版の通常生成はカタログを更新しないため、正式版の最新 Release をすべて含む一覧ではない。

| 配布先 | カタログ | 現在の更新方法 |
|---|---|---|
| 正式版 | [正式版のカタログ](https://shohei0205.github.io/yamamuki-data/points/catalog.json) | 通常生成では更新しない。掲載済み情報を保持し、手動公開・復旧・削除時は更新する |
| 開発版（Pre-release） | [開発版のカタログ](https://shohei0205.github.io/yamamuki-data/points/catalog-dev.json) | 開発版の公開・削除時に更新する |

項目・制約・読み込み方法・配布先ごとの収録範囲は [地点カタログフォーマット](formats/catalog.md) を参照する。機械検証用のスキーマは [地点カタログの版2](schemas/catalog-v2.schema.json)。

### カタログから削除する

Actions の「地点：カタログから削除」→「Run workflow」で、正式版なら `main`、開発版なら `dev` を選び、`dataset` に `osm-peaks` などのデータセット名を入力する。配布先は実行元ブランチで決まり、対象の配布先だけを削除する。

地点カタログとサイト全体の一覧から対象を除き、その manifest・公開履歴の Pages ファイルも削除する。他のデータ・配布先・公開履歴、Release とデータ本体は保持する。

既存一覧の取得・検証に失敗した場合や対象がない場合は配置を中止する。公開と同じ `publish-data-pages` グループで直列化し、配置後にカタログと履歴の一致を確認する。削除済みデータを再度公開すれば一覧に戻る。Pages に公開するデータは次回の公開時に再掲載されるため、継続して配布を止める場合は生成・公開の運用も変更する。

### アプリで利用できるデータを判定する

対応する形式の版の判定と、ダウンロード後の検証方法は [地点カタログフォーマットの「読み込みと検証」](formats/catalog.md#読み込みと検証) を参照する。

### 共通ビューアのテスト

共通ビューアの補足 JSON 解析・タグ編集・保存内容の検査と、全部入り地点 JSON の逐次読み書きのテストは `points/tests/` に置く。Python 3.12 と Node.js を使い、リポジトリ直下で次のコマンドを実行する。外部通信は行わない。Node.js がない場合は、Node.js を使うテストをスキップする。

```bash
python -m unittest discover -s points/tests -v
```

CI の「共通：データ処理のテスト」（`.github/workflows/test.yml`）では、「地点 / 共通ビューア」ジョブで Python と Node.js を準備し、push・PR 時に実行する。山頂データの生成テストとは分けて確認する。

## 山以外も含む全部入り JSON を作る

保存済みの全国元データから、共通ビューアーで確認できる地点 JSON を生成できる。元データ・抽出 DB・DEM キャッシュ・全部入り JSON はローカルに保存し、Git には追加しない。以下のコマンドはリポジトリのルートで実行する。パスは保存先に合わせて変更する。

### OSM の名前付きノード

```bash
python -m pip install -r points/osm-peaks/requirements-all.txt
python points/osm-peaks/scripts/build_all.py \
  --pbf build/japan-latest.osm.pbf \
  --peaks build/osm-national-provenance/osm-peaks.json \
  --output build/osm-national-all-points
```

`--pbf` と同じ場所に、ダウンロード時の取得記録 `japan-latest.osm.pbf.source.json` が必要。サイズと MD5 を照合し、元データの日時を PBF から取得する。`--peaks` は任意で、同じ PBF から生成した山頂版の補足済み地点を引き継ぐ。指定しない場合も `natural=peak`・`natural=volcano` の地点は山頂とする。

`name:ja` または `name` があるノードを収録する。線・面・relation から代表点は作らない。分類タグは `provenance.classification` に記録し、標高は `ele` が解釈できる場合だけ採用する。標高を取得するための通信は行わない。

出力は `osm-all-points.json`、`osm-all-points.json.gz`、`report.json`。出典は OpenStreetMap contributors、ライセンスは ODbL。生成概要に入力のハッシュ・地点数・分類別件数を記録する。

### 国土地理院の名前付き注記

```bash
python -m pip install -r points/gsi-peaks/requirements-vector.txt
python points/gsi-peaks/extract_annotations.py \
  --archive build/gsi-vector-cache/optimal_bvmap-v1.pmtiles \
  --database build/gsi-national-annotations/annotations.sqlite3
python points/gsi-peaks/build_all.py \
  --database build/gsi-national-annotations/annotations.sqlite3 \
  --peaks points/gsi-peaks/gsi-peaks.json \
  --comparison build/gsi-national-dem1a/vector-comparison.json \
  --output build/gsi-all-base
```

ズーム 16 の `Anno` レイヤーから名前付きの単一点注記を抽出する。数字だけの注記・空名称・タイル外の複製は除く。抽出 DB に元の属性とタイル座標を残し、中断後はコミット済みのタイルの次から再開する。保存済みの同形式の `annotations.sqlite3` も再利用できる。山頂版と同時に生成した `vector-comparison.json` を使い、山頂版に対応する注記を除いて統合する。名前付き注記の集合であり、国土地理院の全地物を網羅するものではない。

標高取得済みの全部入り JSON がある場合は、統合時に `--previous 保存済み/gsi-all-points.json` を指定すると、名前と座標が一致する注記の標高を引き継ぐ。

### 山に関係する注記の標高を補う

```bash
python points/gsi-peaks/fill_annotation_heights.py \
  --input build/gsi-all-base/gsi-all-points.json \
  --output build/gsi-national-all-points \
  --cache build/gsi-cache \
  --offline
```

分類コード `311`・`312`・`313`・`314`・`315`・`316`・`323`・`331`・`332`・`333`・`810`・`830`・`831`・`832` のうち、標高のない山頂以外の注記を対象にする。`--codes` でこの中から対象を限定できる。DEM1A、DEM5A/B/C、DEM10B の順に、注記座標の地表標高を補う。混合分類には山以外の地形もあり、標高を補っても地点を山頂には変更しない。

`--offline` では保存済みの応答だけを使い、必要なキャッシュがなければエラーにする。新たに取得するときは `--offline` を外す。取得した PNG と 404 の応答記録をキャッシュに保持し、429 や一時的なサーバーエラーでは間隔を空けて再試行する。並列数は `--workers` で 1～4 を指定でき、既定は 2。入力を残すため、出力には別フォルダーを指定する。中断後も同じ入力とキャッシュで再実行できる。

GSI の出力は `gsi-all-points.json`、`gsi-all-points.json.gz`、`report.json`。標高補完では DEM の取得記録・地点ごとの割り当て・対象注記の JSON も出力する。標高がない地点は `elevationM: null` とし、`elevationSource` を省略する。元データの出典・ライセンスは [GSI 山頂データ](gsi-peaks/README.md#出典とライセンス) を参照する。

## 地点データをブラウザで確認する

[viewer.html](viewer.html) を保存して、Edge や Chrome などのブラウザで直接開く。ローカルサーバーは不要。地点 JSON と補足 JSON は、それぞれのファイルを選んで開く。地点データは内蔵しておらず、起動時は空の状態になる。右上の「使い方」から説明を開ける。地点一覧では Ctrl / Command + クリックで選択を追加・解除し、Shift + クリックまたは Shift + ↑・↓で表示順に範囲選択できる。通常のクリックは1地点の選択に戻る。詳細と地図の中心は最後に選んだ地点に合わせる。複数選択中は選択件数を表示し、地図上でも選択した地点すべてを桃色の枠で強調する。通常の地点は塗りも薄い桃色にし、配布対象外の地点は赤い塗りを保つ。選択地点は表示上限の範囲で優先して地図に残し、最後に選んだ地点を最前面にする。地点一覧にフォーカスがあるときは Ctrl / Command + A でもすべて選択できる。右クリックメニューの「すべて選択」は、現在の絞り込みで一覧に表示される全地点を選ぶ。仮想化で画面外にある行も含む。山を選んだ後はブラウザの「戻る」「進む」で選択履歴を移動できる。移動先が絞り込みで隠れている場合は絞り込みを解除して表示する。地点 JSON を読み替えると、それ以前の選択履歴は適用しない。

### 地点 JSON を開く

「地点 JSON ファイルを開く」で、共通形式の JSON または JSON.gz を選ぶ。osmId のない手動作成の地点も読み込める。gzip の読み込みには DecompressionStream に対応するブラウザが必要で、対応していない場合は展開した JSON を使う。

読み込み時は必須項目、ID の重複、緯度・経度、osmId、タグの形式を確認する。不正な場合は現在のデータを保持する。読み込み結果は画面下に 5 秒間表示する。別の地点 JSON を開くと、読み込んだ補足 JSON と画面上の編集は解除される。切り替える前に必要な編集を保存する。

### 一覧と地図

「出典」「取得元での分類」「標高の出典」を、それぞれ独立した選択欄で絞り込める。選択肢は `[JSON の値] 説明 (件数)` の形式で表示する。タグを含む各選択欄はチェックボックスで複数選択できる。同じ欄では選んだ条件のいずれかに一致する地点を表示し、検索と各欄の間ではすべての条件に一致する地点を表示する。「すべて」を選ぶとその欄の絞り込みを解除する。最後のチェックを外した場合も「すべて」に戻る。地点 JSON の `provenance` を使い、各項目の情報が記録されていない地点は 「出典情報なし」 と表示する。この選択肢は 3 つの出典関連の欄すべてで「すべて」の直下に表示し、該当地点がなければ 0 件とする。「標高の出典」の「標高情報あり」は、出典の記載にかかわらず標高が数値で入っている地点を表示する。0 m や負の標高も含む。「標高情報なし」は標高が省略または `null` の地点を表示する。選択肢の件数は読み込んだ全地点での件数とし、説明の右側に右寄せで表示する。コンボボックスは上下キーで候補を移動し、Enter または Space でチェックを切り替え、Escape で閉じられる。 選択地点の詳細パネルにも、同じ `[JSON の値] 説明` の形式で出典・取得元での分類・標高の出典を表示する。詳細には件数を付けない。 国土地理院の注記分類は [公式の分類コード表](https://maps.gsi.go.jp/help/pdf/vector/optbv_featurecodes.pdf)に基づいて表示し、施設名・地形の種類・拡大表示用の分類などを説明する。未知のコードは「注記コード」に値を付けて表示する。

20,000 地点以上のデータでは、一覧を仮想化し、画面付近の行だけを描画する。ページ切り替えはなく、全件を続けてスクロールできる。検索と所在地以外の並び替えは全地点を対象にする。地図は表示範囲内の最大 10,000 地点を表示し、それより多い場合は一部を間引く。地図を拡大すると詳しく確認できる。所在地は一覧の表示範囲だけを判定するため、大量データでは所在地での並び替えは利用できない。読み込み時の JSON 解析・検証と gzip 展開は、画面とは別のスレッドで行う。

| 列 | 内容 |
|---|---|
| 番号 | 絞り込み・並び替え後の表示順に付ける、1 からの通し番号 |
| 地点名 | 地点 JSON の name |
| 標高 (m) | elevationM。値がない場合は空欄 |
| 所在地（参考） | 座標から判定した都道府県・市区町村 |
| 緯度・経度 | latitude・longitude |
| ID / osmId | osmId があれば OSM へのリンク。なければ通常の id |

行のどこをクリックしても、その地点の詳細を表示し、現在の縮尺のまま地図を移動する。ID の OSM リンクは別タブで開く。左右のペインは個別にスクロールでき、中央の境界をドラッグすると幅を変えられる。境界を選択した状態で左右キーでも幅を調整できる。狭い画面では地図と一覧を上下に並べる。 詳細パネルを開くと地図との間に境界が表示され、ドラッグして詳細の高さを変えられる。境界にフォーカスを合わせると上下キーで 10 px、Shift を押しながらで 50 px ずつ調整でき、Home・End キーで最小・最大の高さにできる。詳細を閉じて開き直しても、同じ画面内では調整した高さを保持する。

列見出しをクリックすると、その列で昇順・降順に並び替える。標高は数値順、緯度・経度は緯度を優先した数値順、所在地は都道府県コード順（北海道から沖縄県）、同じ都道府県内では市区町村名順に並べる。複数の都道府県に該当する地点は最も小さいコードで比較する。地点名・ID は数字の大小を考慮した文字列順で並べ、値がない地点や所在地が未判定の地点は末尾に置く。

地点一覧をクリックしたあと、↑・↓キーで表示順の前後の地点を選べる。絞り込みで非表示の地点は飛ばし、選択した行が見える位置まで一覧をスクロールする。

地点の詳細にある「近くの山」で、選択した地点から直線距離の近い 20 地点を確認できる。表には地点一覧と同じ地点名・標高・所在地・緯度経度・ID / osmId・よみがな・別名に加え、基準地点からの距離を表示する。距離は緯度・経度から計算し、登山道の距離や所要時間は表さない。「絞り込み中の地点だけを表示」で対象を限定できる。山を選ぶと地図と詳細を更新し、絞り込み対象外の地点を選んだ場合は絞り込みを解除する。

地点一覧の「よみがな」は `nameReading`、「別名」は `aliases` を表示する。複数の別名は読点で区切り、値がない場合は空欄にする。どちらも検索と列見出しからの並び替えに使える。

検索欄とタグ選択欄で、一覧を絞り込み、地図では対象外の地点も灰色で残す。配布対象から除外した地点は赤、対象地点は緑（確認対象は橙）、選択中は桃色の枠で表示する。配布対象外と絞り込み対象外が重なる場合は赤を優先する。重なり順は、絞り込み対象外・配布対象外・表示対象・選択中の順に手前へ重ねる。配布対象外の地点は地図でマウスを重ねた際の山名に「（除外）」を付ける。対象外の点は拡大率に応じて半径 2・3・5・6 px で表示し、絞り込みで対象件数が減っても大きくしない。大量データの地図は最大 10,000 地点を維持し、絞り込み対象外と配布対象外にそれぞれ最大 20 % を割り当て、残りを対象地点に使う。空き枠は他の分類に回す。「補足あり」を選ぶと、補足 JSON に登録されている地点と未保存の補足を持つ地点を表示する。タグのないよみがな・別名などの補足も対象とする。除外地点を隠す場合は「除外地点を表示しない」を ON にする（初期状態は OFF）。タグは由来を区別せず、同じ名前を一つの選択肢にまとめる。地点 JSON・補足 JSON・画面上の編集で付いた同名タグをまとめて絞り込む。「絞り込みを解除」は検索語とタグ条件を解除し、条件がないときは無効になる。絞り込み・解除・タグ編集では地図の縮尺を変えず、新しい地点 JSON を開いたときだけ全地点に合わせる。

### 地点のタグを編集する

地点一覧の末尾の「タグ」列に、その地点の全タグを表示する。列見出しで並び替えでき、「近くの山」の一覧にも表示する。

地点を選び「補足を編集」を開く。既存タグの候補を選ぶと、その場でタグ一覧に追加する。新しいタグは名前を入力し、「タグを追加」を押す。タグの × で削除でき、「保存」で他の補足と一緒に適用する。「キャンセル」では変更を適用しない。詳細パネルではタグを表示する。見出しには「山名 (よみがな) の詳細」と表示し、複数の読みも併記する。補足で読みを削除した場合や読みがない場合は、山名だけを表示する。タグで絞り込んでいるときは、一覧の右クリックメニュー内の「このタグから削除」でも、その地点から該当タグを削除できる。最後の地点を削除してタグが空になった場合は、絞り込みを解除する。

詳細パネルの「読み込んだ元データ」は入力 JSON をそのまま表示し、画面上のタグ編集は反映しない。地点 JSON を保存する機能はない。編集結果は補足 JSON として保存する。

### 補足 JSON を開く

「補足 JSON ファイルを開く」で一つの `supplements.json` を読み込む。タグごとにファイルを分けず、`points` の `id` で地点に対応付ける。関連先は `relatedIds` に指定する。開き直すと補足全体を差し替える。未保存の編集がある場合は確認する。読み込み時は検索語とタグの絞り込み条件を維持する。選択していたタグがなくなった場合は、タグ条件を「すべて」に戻す。

地点 JSON 版6では `osmId` を使わず、関連先のグローバル ID を `relatedIds` に保持する。補足の保存は `id` に統一する。旧形式の `osmId` や一覧貼り付けの OSM ノード番号は、読み込み・入力の互換機能として扱う。別名欄は JSONL 形式で、1 行に 1 件の名前・読みの object を表示・入力する。従来の JSON 配列の貼り付けにも対応する。補正前の想定値は 1 行の JSON object として表示する。配布する補足ファイルの形式は通常の JSON のままとする。よみがなは1行に1つ入力し、複数の読みを登録できる。例えば白馬岳なら「しろうまだけ」「はくばだけ」を別の行に記入する。1つは文字列、複数は `nameReading` の配列として保存し、一覧・検索・別名への移動にも反映する。タグ情報の `nameReading` も同じ形式で複数の読みを指定できる。よみがな欄に入力すると、自動的に「補足の値を使う」へ切り替わる。補足編集画面の保存では編集した地点だけを更新し、検索・複数選択した絞り込み・スクロール位置を維持する。補足編集画面の「関連する地点 ID」で関連先を指定し、詳細パネルで確認できる。

形式と各項目は [補足データフォーマット](formats/supplements-data.md) を参照する。

不正な値・未知の id / osmId・同じ地点への二重指定・想定値の不一致がある場合は、補足全体を適用せず現在の表示を保つ。読み込み結果とエラーは画面下部に 5 秒間表示する。

地点一覧の行を右クリックするとメニューが開き、「配布対象から除外する」を選べる。除外済みの地点ではこの操作を無効にする。右クリックメニューの「選択した地点をチェック」で、選択した地点のよみがな・別名の読み・タグの読み・標高の未入力を、補足マージ後の値で確認する。結果はポップアップに地点名・ID・未入力項目をまとめて表示し、一覧の絞り込みと選択は変更しない。レポート画面の「クリップボードにコピー」で、チェック件数とレポート本文をコピーできる。選択していない行を右クリックした場合はその地点だけをチェックする。配布除外地点は、読み・標高を含む未入力チェックの対象外とする。右クリックメニューの「補足マージ後の地点 JSON を保存」で、選択した地点を版6の `selected-points.json` に書き出せる。複数選択中はまとめて保存し、選択していない行を右クリックした場合はその地点だけを保存する。未保存の補足・タグ編集と共通の出典・タグ情報を含め、配布対象外の地点は出力しない。各地点は1行ずつにする。「補足マージ後の地点 JSON をクリップボードにコピー」でも、保存と同じ内容をコピーできる。「選択した地点の Markdown 表をクリップボードにコピー」は、元データの名称・現在の表示名・読み・別名と読み・ID を表にする。現在の一覧順で連番を付け、著書順は推測しない。GSI の地点だけなら列名を「国土地理院での名称」「GSI ID」とする。配布対象外の地点は表にも含めない。「近くの山」は除外地点も含めて近い20地点を表示する。除外地点の名前には「（除外）」を付け、行の背景を暗くし、再度の除外操作は無効にする。「絞り込み中の地点だけを表示」が ON の場合は、一覧の絞り込み条件に従う。「近くの山」も行を右クリックするとメニューが開く。「配布対象から除外する」を選ぶと、その地点を除外できる。同名かどうかは条件にしない。既存の補正やタグは保持し、補足 JSON の `exclude: true` に記録する。ファイルへ書き出すには「補足 JSON を保存」を使う。元に戻すときは「除外地点を表示しない」を OFF にして地点を選び、補足編集画面で除外を解除する。

「この山名を基準の山へ移して除外」では、近くの地点の名前・よみがなを基準の地点へ設定し、基準の地点の変更前の名前・よみがなを別名に残す。近くの地点は配布対象から除外する。座標・標高・タグは引き継がず、両地点の既存の補足は保持する。相手の読みがない場合は基準の地点の読みを削除する。変更は補足 JSON にまとめて記録し、「補足 JSON を保存」で書き出す。

### 補足を編集する

地点を選び「補足を編集」を押す。地点一覧の行をダブルクリックしても、その地点の補足編集画面を開ける。OSM リンクやタグ削除ボタンのダブルクリックは対象にしない。表示名、よみがなの置き換え・削除、別名の追加・削除、除外、補正理由、管理用メモを編集できる。補正前の想定値は JSON で入力する。出典は保存画面で補足 JSON 全体の出典一覧として管理する。

「現在の名前・よみがなを別名に移して改名」を押すと、編集欄の現在値を別名へ追加し、新しい名前・よみがなの入力欄を空にする。同じ別名は重複させず、別名の削除指定にも入っている場合は削除指定を解除する。新しい名前・よみがなを入力して保存する。読みが不明なら、よみがなの「削除する」を選ぶ。

編集画面の「保存」で画面へ適用する。上部の「元に戻す」「やり直す」で、補足の編集・タグの変更・除外・山名の引き継ぎ・一括追加・クリアを最大 50 操作まで戻せる。Undo/Redo は補足の差分から変更地点を特定し、その地点の行・タグ・地図表示だけを更新する。Ctrl / Command + Z で元に戻し、Ctrl / Command + Shift + Z または Ctrl + Y でやり直す。入力欄と「近くの山」以外のダイアログ内ではこのショートカットを使わない。「近くの山」には「元に戻す」「やり直す」ボタンもあり、開いたまま操作するとリストを更新する。別の地点 JSON・補足 JSON を読み込むと履歴を消す。ファイルへ保存済みの内容は書き換えず、取り消した状態を保存するには再度保存する。保存時の入力エラーは、スクロールしても見える画面上部に表示し、次に保存を試すか編集画面を開き直すまで残す。ファイルへ書き出すには、上部の「補足 JSON を保存」を使う。元データは変更せず、詳細には、地点名・よみがなの変更前後、追加・削除したタグと別名、除外指定を表示する。補正理由も併記する。地点一覧では、元データから値が変わった地点名・よみがな・別名・タグを太字で表示する。削除して空になった項目は太字の「なし」とし、カーソルを重ねると元の値を確認できる。別名の名前が同じでも、読みの追加・変更・削除があれば別名欄を太字にする。近くの山の一覧も同じ表示にする。「変更後の補足 JSON」には、その地点の補足を未保存の変更も含めて、改行とインデント付きの JSON で表示する。補足がない地点は「補足なし」と表示する。「読み込んだ元データ」には元の JSON 全文を表示する。詳細パネルの一番下には、補足と未保存のタグ編集を反映した地点 JSON を、改行とインデント付きで表示する。補足編集画面の「配布対象から除外する」を ON にして保存した地点は、配布データに含まれず、補足マージ後の地点 JSON も空欄になる。その下に「配布対象から除外されます」と表示する。除外地点は初期状態では一覧と地図に表示し、行の背景を暗くする。「除外地点を表示しない」を ON にすると一覧で隠す。地図では赤色で表示を続ける。補足編集画面の「配布対象から除外する」は、元の地点名の上に配置する。「除外地点を表示しない」を OFF にすると、一覧で除外地点を確認し、除外指定を編集できる。

### タグを一括追加する

1. 「タグ一括追加」を開き、山の一覧を貼り付ける。1 行に 1 地点とし、地点名のみ、osmId のみ、ID と地点名の 2 列を使える。CSV 形式のテキストや表計算ソフトからの貼り付けに対応する。osmId は `#osmId,name`、地点 ID は `#id,name` の見出しを使う。両方の指定方法が混ざる一覧は `#id,osmId,name` とし、各行でどちらか一方だけを埋める。数値だけの見出しなし入力は osmId として扱う。
2. 「照合して補完」を押す。地点名・別名から ID を補い、ID から地点名を補う。GSI のように osmId のない地点も対象とする。同名の候補が複数ある場合は、すべて追加対象にする。「補完した対応表」は見出し行なしで表示する。
3. 要確認の行があれば、候補検索・選択や地点名・ID の直接入力で修正する。候補には所在地・標高・座標を表示し、OSM リンクから登録内容も確認できる。不要な行や重複は「除外」にチェックし、「修正した内容で再照合」を押す。
4. 全行の照合が済んだら、既存タグを選ぶか新しいタグ名を入力し、「タグを一括追加」を押す。同名タグの既存地点を残して追記し、同じ地点は重複させない。追加したタグ名で絞り込める。

この画面は追加専用で、補足 JSON の読み込み・保存は上部のボタンから行う。反映だけではファイルに保存されない。

### 保存とクリア

補足の編集画面では SVG ファイルの読み込みや本文の貼り付け、表示倍率の指定ができる。画像は編集画面と地点の詳細で確認できる。編集画面のプレビューは固定サイズで、SVG 表示倍率を変えても大きさは変わらない。地点リストと「近くの山」の SVG 欄には、画像の横に「1.0倍」のように SVG 表示倍率を表示する。画像のない地点は空欄にする。補足で画像を削除した地点の SVG 欄は「なし」と表示する。SVG 欄は表示倍率の数値順に並べ替えられる。「元の画像を使う」で画像の補足を取り消し、「画像を削除する」で元の画像も非表示にする。SVG の制限は地点データに埋め込む画像と同じで、保存前と生成時に検査する。

「補足 JSON を保存」で、すべてのタグと補正・除外を一つの `supplements.json` に保存する。絞り込み状態によらず全補足を保存し、`note`・`reason`・`expected` も引き継ぐ。保存画面では出典一覧を JSON で編集できる。保存先を選ぶ場合もダウンロードする場合も、地点を `id` の自然順（数字の並びは数値として比較し、`osm:2` → `osm:10` の順）で並べてから書き出す。タグ・別名・読みの配列の順序は保持する。BOM なしの UTF-8・LF で書き出す。

保存画面には「保存先を選んで保存」と「ダウンロード」を用意する。対応ブラウザでは保存先とファイル名を選べる。補足 JSON のファイル保存でも絞り込みとスクロール位置を維持する。保存時は各補足の `note` に元の地点 JSON の名前を自動で入れ、除外地点にも付ける。補正後の表示名は使わず、既存の `note` も元の名前へ更新する。補足編集画面には管理用メモの入力欄を置かない。「ダウンロード」は保存先を選ぶダイアログを使わず、ブラウザの通常のダウンロードで保存する。非対応の環境ではブラウザのダウンロード設定を使う。キャンセル・保存失敗では未保存の編集を保持する。osmId のある地点は `osmId`、ない地点は `id` を使って保存する。読み込んだ補足が `id` 指定の場合は、その指定を保つ。

「補足 JSON をクリア」は、確認後に補足と画面上の編集を取り消して、元の地点 JSON の値へ戻す。入力ファイル自体は書き換えない。

未保存のタグは絞り込み候補に「（未保存）」と表示する。補足や出典に未保存の変更がある場合はページタイトルにも表示し、タブを閉じる・再読み込み・別ページへの移動時にブラウザ標準の確認を出す。空になったタグは絞り込み候補から除く。

### 所在地の判定と通信

所在地は、[共同通信社の japan-choropleth](https://github.com/kyodo-official/japan-choropleth) が加工した国土交通省「国土数値情報 行政区域データ 2025 年版」（CC BY 4.0）を取得し、座標と照合する。約 9.7 MB の全国市区町村境界を一度取得し、ブラウザ内に保存して次回から再利用する。所在地は参考値で、境界付近では実際と異なる場合がある。取得できない場合は「未判定」、該当する行政区域がない場合は「不明」と表示する。所在地は元の JSON や補足 JSON には追加しない。

地図ライブラリ・地理院タイル・境界データの取得には通信が必要。地点ファイルはブラウザ内で処理し、読み込んだファイルや地点の座標をアップロードしない。地図を取得できない場合も、一覧・詳細表示・タグ編集は使える。

所在地判定用の境界データは初回取得後、ブラウザ内に保存し、次回から再利用する。保存済みの境界データがあれば、通信なしでも所在地を判定できる。ブラウザの保存データを削除した場合や、ビューアが使用する境界データの版を更新した場合は再取得する。保存を許可しないブラウザ設定では毎回取得する。

## 地点 JSON の形式

- 形式を変えたとき（任意の項目や種別を足すときも）は、同じ PR で `formats/` の文書と変更履歴、スキーマを更新する。公開した版の文書は消さない。
- 項目の取り方・収録する対象と重複の扱いは、データごとの README に書く。
- 地点ごとのグラフィックの SVG は、生成するときと公開する前に、内容と倍率を [graphics.py](osm-peaks/scripts/graphics.py) で検査する。SVG の取得元・作成者・利用条件は、データごとの README に書く。

## データを追加するとき

`points/<取得元と対象>/` に `README.md`・`scripts/`・`tests/` をまとめる。例えば OSM のランドマークを追加する場合は `points/osm_landmarks/` とし、実装時にこの一覧とルートの一覧を更新する。生成物は各フォルダの `build/`・`dist/` に置き、git に含めない。例外として、国土地理院版の配布用地点 JSON と出典要約 JSON はコミットする。

manifest は [リポジトリ共通仕様](../formats/manifest.md) に従い、公開 URL・ファイル名・元データの取得方法・公開時の件数基準はデータセットごとに定める。生成・公開処理の共通化は追加データの要件に応じて行う。

補足編集の「標高（m）」では元の値の維持・補足値への置き換え・削除を選べる。数値を入力すると自動的に「補足の標高を使う」へ切り替わる。0m・負の値・小数も指定でき、空欄や数値でない値は保存できない。補正後の標高は一覧・並び替え・チェック・マージ後JSONに反映し、標高の出典を「補足による補正」にする。元の地点JSONは変更しない。

## 地点のタグ

### 除外地点とタグの関連を絞り込む

「タグで絞り込み」の「除外地点：すべて」は配布除外地点だけを表示する。「除外地点：日本百名山」などの選択肢では、そのタグに関連する除外地点だけを表示する。「除外地点：関連タグなし」は関連するタグが見つからない除外地点を表示する。複数の選択肢を選べる。除外の選択肢を選ぶと「除外地点を表示しない」はOFFになる。

除外地点の名前が、除外されていないタグ付き地点の名前または別名と一致した場合、その地点のタグに関連すると推定する。名前は全半角と前後の空白をそろえて完全一致で比較し、位置の近さは条件にしない。同名の別の山にも一致する場合がある。詳細パネルにも推定した関連タグを表示する。

関連タグはビューアー内だけで計算し、除外地点にタグを付けたり、地点JSONや補足JSONへ関連情報を書き込んだりはしない。改名・別名・タグ・除外指定の編集やUndo/Redoで再計算する。既存のファイルもそのまま利用できる。

### タグの表示と読み

タグの意味と生成時の出典の扱いは、[補足データフォーマットの「タグと出典の引き継ぎ」](formats/supplements-data.md#タグと出典の引き継ぎ) を参照する。生成処理への組み込みと対応表の置き場所は、データセットごとの README に記載する。

OSM の「取得元での分類」は、セミコロンで区切られた分類をタグごとの選択肢に分ける。例えば `amenity=toilets; shop=hairdresser` の地点は、どちらの分類でも絞り込める。件数は各分類に該当する地点数で、複数の分類を持つ地点はそれぞれに数える。詳細パネルでも分類ごとに表示する。 `office=*`（事務所すべて）などのキー単位でも絞り込める。同じ地点に同じキーの分類が複数あっても、キー単位の件数では 1 地点と数える。 OSM の主な分類には日本語の説明を付ける。説明を登録していない値は、「店舗（説明未登録）」などの大分類と元のタグを表示する。タグの意味は [OSM Wiki の Map features](https://wiki.openstreetmap.org/wiki/Map_features) で確認できる。

版6の別名は `aliases` の各 object に `name` と任意の `nameReading` を記載する。旧版の文字列配列も確認用 HTML で読める。[地点形式](formats/data.md#別名のよみがな) と [補足形式](formats/supplements-data.md) を参照する。確認用 HTML では補足編集画面で別名ごとの読みを JSON で入力でき、一覧・詳細に読みを表示し、読みで検索できる。

タグ共通の読みは補足 JSON の任意の `metadata.tags` に記載し、版6の地点 JSON の `metadata`に引き継ぐ。確認用 HTML の保存画面で編集でき、タグの絞り込みは読みのあるものを読み順、読みのないものをその後に名前順で並べる。

確認用 HTML は地点データ版1〜5の JSON 配列と、版6の `points` 配列を持つ object の両方を読み込める。JSON・gzip のどちらも指定できる。版1〜4の `id` がない地点は `osmId` で識別し、読み込んだ元データには ID を書き足さない。

生成する山頂 JSON は、外側の object と metadata を整形し、`points` の各地点を 1 行ずつ出力する。JSONL に似た改行形式だが、ファイル全体は通常の JSON として読み込める。

「この山名を基準の山へ移して除外」では、基準の山の既存の別名を保ち、除外する山の別名と読みも引き継ぐ。同じ別名の読みは重複を除いてまとめ、明示的に削除した別名は復活させない。新しい表示名と同じ名前は別名から除く。

地点 JSON の読み込み中は 1,000 件ごとに件数を更新し、受信処理の間に画面を更新できるようにする。読み込み完了後は実件数と「一覧・地図を準備しています」を先に表示し、一覧・地図の準備が終わってから完了を表示する。
