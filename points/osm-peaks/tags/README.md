# 山頂のタグ対応表

対応表はこのフォルダの CSV だけを編集し、拡張子を除いたファイル名をタグ名にする。例えば `日本百名山.csv` から `日本百名山` を付ける。同じ地点を複数の CSV に入れると、各タグが付く。ファイル名の変更はタグ名の変更になる。

現時点では分類を確認した対応表を収録していない。百名山などの全件リストは、出典と対象の地点を確認してから追加する。以下の2件は形式を示す例で、完成した百名山の一覧ではない。

```csv
#osmId,name
165028676,奥穂高岳
204683948,羊蹄山
```

CSV は BOM 付き UTF-8・LF で保存する。Excel や Google スプレッドシートで編集した場合も、この形式にそろえて保存する。補完ツールとビューアーも BOM 付き UTF-8・LF で CSV を保存する。読み込み時は BOM なしの UTF-8 も受け付ける。osmId は正の整数で、指数表記や小数は使わない。name は確認用で、照合には osmId を使う。

## CSV を補完して確認する

次のコマンドは `points/osm-peaks/` で実行する。--points には取得済みの osm-peaks.json または osm-peaks.json.gz を指定する。外部通信は行わない。

```bash
python scripts/tag_csv.py tags/日本百名山.csv --points build/osm-peaks.json
```

入力は `name` だけ、`osmId` だけの列でもよく、2列のうち片方が空の行も補完する。

| 入力 | 動作 |
|---|---|
| 山名だけ | 表示名・別名に完全一致する候補が1件なら osmId を補完 |
| osmId だけ | 同じ ID の地点の表示名を name に補完 |
| 両方あり | 入力を保持し、ID の存在と表示名・別名との一致を検査 |
| 両方なし | エラー |

元の CSV は変更しない。補完結果は `build/tags/日本百名山.csv`、確認用一覧は `build/tags/日本百名山.html` に出力する。--output-dir で出力先を変更できるが、入力 CSV と同じ場所には出せない。生成した CSV と HTML は Git に保存しない。

HTML には山名・osmId・OSM の URL と、照合結果・データ上の山名・座標・標高を表示する。同名の候補が複数あれば全候補を表示し、ID は自動選択しない。候補がない場合も入力を残す。未解決の行があれば、確認用ファイルを出力したうえで終了コード 1 を返す。CSV の形式不備や ID の重複は終了コード 2 とする。山名の不一致は要確認として表示し、終了コードは 0 とする。

リンク先の地図と登録情報で対象の山を確認し、完成した CSV をこのフォルダへ反映する。名前による推測や件数だけでは百名山としての正しさは保証できない。山群を代表する一峰に付けるか複数の峰に付けるかを決め、出典・確認日・複数地点を選んだ理由はこの README に記録する。

## 生成時の検査

山頂生成はこのフォルダの *.csv を自動で読み込み、既存タグを保って追加する。タグがない地点の項目は追加しない。--tags-directory で別の対応表フォルダを指定できる。対応表フォルダがない場合はエラーにし、CSV がないフォルダではタグを追加しない。

公開用の対応表は osmId,name の2列を必須にする。空欄、不正な ID、同じ CSV 内の ID 重複、列数の不一致、山名やファイル名の前後の空白はエラーにする。ID が生成対象に存在しない場合も生成を中止する。山名が表示名・別名のどちらにも一致しない場合は警告し、ID に従ってタグを付ける。

単体テストは親フォルダの [テスト手順](../README.md#テスト) を参照する。実際の対応表と山頂の照合は生成時に行う。

## 地図で確認する

生成した HTML は、左に一覧、右に地図を表示する。一覧は独立してスクロールし、地図上の地点を選んでもページ全体は移動しない。選択した地点の行を一覧内に表示する。狭い画面では上に地図、下に一覧を配置する。山名を押すとその地点へ移動し、マーカーを押すと OSM へのリンクを表示する。照合済みの地点は緑、複数候補や山名の不一致は橙で表示する。見つからない地点も一覧には残す。山名・osmId・状態で一覧とマーカーを絞り込める。

生成した HTML をダブルクリックするなど、ブラウザで直接開くと地図と一覧を利用できる。ローカルサーバーの起動は不要。HTML は地点情報を内蔵し、CSV や JSON の追加読み込みは行わない。

地図表示にはインターネット接続が必要で、Leaflet 1.9.4 を CDN から、背景地図を国土地理院の標準地図から取得する。背景地図には [地理院タイルの出典](https://maps.gsi.go.jp/development/ichiran.html) を表示する。通信できない場合も一覧と OSM リンクは残る。背景地図は表示範囲だけを取得し、まとめて保存しない。生成物は公開・コミットせず、手元の確認に使う。

## 山頂データの全地点を表示する

CSV を指定せず --all を使うと、指定した JSON の全地点を表示する build/tags/osm-peaks.html を生成する。分類の対応表とは独立した、山頂データ全体の確認に使う。点の色はデータ収録地点であることを示し、分類の正しさを示すものではない。

```bash
python scripts/tag_csv.py --all --points build/osm-peaks.json
```

gzip も指定できる。全地点表示では補完 CSV を生成せず、入力データも変更しない。山名・osmId で絞り込み、一覧の山名から地図を移動できる。多数の点は Canvas で描画する。

地点を地図または一覧で選ぶと、右ペインに元データの JSON 全項目を表示する。省略された項目は追加せず、SVG 本文なども文字列として表示する。タグの選択欄は入力 JSON に収録された tags から作り、タグなしも選べる。山名検索とタグ条件は同時に適用する。分類の CSV を編集しただけでは入力 JSON のタグは変わらないため、タグ付きデータを生成してから全地点 HTML を作り直す。

## ブラウザで地点データを選ぶ

```bash
python scripts/tag_csv.py --viewer
```

共通の [viewer.html](../../viewer.html)、またはコピーした build/tags/point-viewer.html を直接開き、「地点 JSON ファイルを開く」で JSON または JSON.gz を選択する。以後は HTML を作り直さず、ファイル選択で表示データを切り替えられる。データを内蔵した全地点 HTML や CSV 確認用 HTML にも同じ選択欄がある。

地点データの共通形式（JSON 配列）を読み込む。id・name・latitude・longitude は必須で、osmId はなくてもよい。読み込み時は ID の重複、必須項目、座標、OSM ID、タグの形式を検査し、不正な場合は元の表示を保持する。これは表示に必要な検査であり、公開前のスキーマ検査の代わりにはしない。gzip の読み込みには DecompressionStream に対応するブラウザが必要で、非対応の場合は展開済み JSON を選択する。

ファイルはブラウザ内で読み込み、アップロードしない。タグ選択、一覧・地図の連動、JSON 全文表示も読み込んだデータに切り替わる。地図の外部取得は従来どおり行う。地図を取得できない場合もファイルの読み込みと一覧、JSON 全文表示を利用できる。

## ブラウザで CSV を重ねてタグを編集する

地点 JSON を選んだ後、「タグ CSV ファイルを開く」でこのフォルダの CSV を選ぶ。複数選択でき、ファイル名をタグ名として osmId で照合する。元の JSON にあるタグを保って表示用のタグに追加する。対応表は osmId,name の2列を必須にし、BOM・CRLF・引用符付きの項目も読み込む。不正な値・同じ CSV 内の ID 重複・見つからない ID があれば、選択したファイルを適用せず既存の表示を保持する。山名が表示名・別名と一致しない場合は警告する。

同じタグ名の CSV は差し替え、別のタグ名は追加する。「タグ CSV をクリア」で CSV のタグと手動での追加・削除を解除し、元の JSON のタグに戻せる。地点を選んでタグを手動で追加・削除することもできる。編集結果はタグ別 CSV に保存する。詳しくは [共通ビューアの使い方](../../README.md#地点データをブラウザで確認する) を参照する。地点 JSON を切り替えると CSV と手動編集は解除する。

CSV の見出しは `#osmId,name` とする。読み込み時は従来の `osmId,name` も受け付ける。
