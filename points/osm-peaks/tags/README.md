# 山頂のタグ対応表

タグ別に JSON ファイルを分け、このフォルダに置く。ファイル名は `日本百名山.json` のようにし、拡張子を除いた名前と `tag` を一致させる。同じ地点を複数の対応表に含めると、それぞれのタグが付く。

現時点では分類を確認した対応表を収録していない。以下は形式の例で、完成した百名山の一覧ではない。

```json
{
  "tag": "日本百名山",
  "source": "Wikipedia「日本百名山」の参照した版の固定リンク",
  "license": "CC BY-SA 4.0 https://creativecommons.org/licenses/by-sa/4.0/",
  "attribution": "Wikipedia「日本百名山」の投稿者",
  "changes": "山名を抽出し OpenStreetMap の osmId を追加",
  "points": [
    {
      "osmId": 204683948,
      "name": "羊蹄山"
    }
  ]
}
```

UTF-8・LF、BOM なしで保存する。`tag` と `points` は必須で、配布に使う各地点には正の整数の `osmId` と山名 `name` が必要。山名は確認用で、地点との対応付けには osmId を使う。スキーマは [tag-v1.schema.json](../../../schemas/points/tag-v1.schema.json) にある。

`source`・`license`・`attribution`・`changes` は任意の文字列で、実際の出典と加工内容に合わせて記載する。生成時は各対応表のこれらの情報を `tag` とともに manifest.json の `tagSources` にまとめる。元の OSM の出典とライセンスも残す。対応表を使う前に、山群を代表する一峰に付けるか複数の峰に付けるかを確認する。

## 山名と osmId を補完する

次のコマンドは `points/osm-peaks/` で実行する。--points には取得済みの地点 JSON または JSON.gz を指定する。外部通信は行わない。

```bash
python scripts/tag_json.py tags/日本百名山.json --points build/osm-peaks.json
```

補完前の `points` は `name` だけ、`osmId` だけでもよい。山名・別名の候補が 1 件なら osmId を補い、osmId が一致する地点から山名を補う。両方あれば入力を保持して一致を検査する。同名の候補が複数ある場合や見つからない場合は、未解決として入力を残す。

入力ファイルは変更しない。補完結果は `build/tags/日本百名山.json` に保存し、出典情報を引き継ぐ。--output-dir で出力先を変更できるが、入力と同じ場所は指定できない。生成物は Git に保存しない。

照合結果と候補の山名・osmId は画面に出力する。未解決の行があれば補完結果を出力して終了コード 1 を返す。形式の不備や重複 ID は終了コード 2 とする。山名の不一致は要確認として表示し、終了コードは 0 とする。

## 生成時の検査

山頂生成はこのフォルダの *.json を読み込み、既存タグを保って追加する。--tags-directory で別のフォルダを指定できる。フォルダがない場合はエラーにし、対応表がない場合はタグを追加しない。

不正な値、未知の項目、同じ対応表内の重複 ID、山名やタグ名の前後の空白はエラーにする。生成対象にない ID があれば、タグを反映する前に生成を中止する。山名が表示名・別名のどちらにも一致しない場合は警告し、ID に従ってタグを付ける。

## ブラウザで確認・編集する

[viewer.html](../../viewer.html) で地点 JSON を開き、「タグ JSON ファイルを開く」で対応表を選ぶ。タグの追加・削除と山名一覧からの一括追加ができる。「タグ JSON を保存」では出典情報を編集して保存できる。元の地点 JSON は書き換えない。

詳しくは [ビューアの使い方](../../README.md#地点データをブラウザで確認する) を参照する。テストは親フォルダの [テスト手順](../README.md#テスト) に従う。
