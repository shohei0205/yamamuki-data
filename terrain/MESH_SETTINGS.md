### 生成と品質

- 最詳細の Adaptive TIN から頂点を削減し、細かいレベルから粗いレベルへ生成する。粗いレベルの頂点は詳細レベルにも存在する。
- 20%の追加頂点枠と、頂点数を使い切る目標は廃止する。誤差と三角形の品質を満たせば終了する。保存頂点数はu32カウントで表す。従来の65,536頂点制限を廃止し、実行環境のメモリー上限は別に管理する。
- 山頂中心では山腹の半分の許容誤差とし、距離1 kmで山腹の条件へ滑らかに戻す。z14は既存の共通12.5 mメッシュを使い、6.25 mにはしない。
- 山頂は約100 mの平均標高格子で検出する。前後500 mの正方形内で最高、かつ比高30 m以上を条件とする。同値は座標順で選び、検出範囲の外周500 mは除く。複数山頂の影響が重なる場所は厳しい条件を使う。
- 山頂からの距離を `d`、`t = min(d / 1000, 1)` とし、山腹誤差へ掛ける係数は `0.5 + 0.5 * t² * (3 - 2t)` とする。許容誤差の下限は12.5 m。
- 生成・削減時の平面上の最小角は10°を維持する。異なるレベルの実行時接合では鋭角が残る場合があり、任意の組み合わせでの10°保証は未完了。

### 余白と三角形の格納

タイル担当矩形に交差する面を本体とし、そこから辺を共有する外側1層の面を余白として保存する。接合品質に必要な点は通常のメッシュへ事前に組み込み、別の「接合用追加候補」列は持たない。頂点と三角形は担当矩形の外にはみ出してよい。

三角形列は **`[本体面][余白面]`** の順に並べ、本体三角形数 `N` を保存する。復元後の三角形番号が `N` 未満なら本体、それ以降なら余白と判定する。頂点番号では判定しない。頂点列は両者で共有し、頂点・面ごとの余白フラグは持たない。

三角形の接続は共有頂点列への32ビット符号なしインデックス3個で表す。圧縮前は1面12バイト。座標のx・y・zは従来どおり各16ビットで1頂点6バイト。独自面順とTFC2を使い、zlibは重ねない。面順の最適化は本体・余白それぞれの中で行い、復元後も区切りを保つ。

同レベルで接続可能な元メッシュ全体に共通の識別子を持たせる。識別子にはタイムスタンプなどを含む文字列を使えるが、タイル個別の生成時刻にはしない。同一識別子の接続は再三角形分割せず、隣接する余白の重複除去を基本とする。全ポリゴン同士の総当たりは避け、読み込むタイルが変わったときに接続を更新する設計とする。

### 全国の作業領域と再開（2026-10-24 実装）

入口は `terrain-xyz-region-test --national`。起動スクリプトは `tools/terrain/start_national_xyz.ps1`、出力先は `build/terrain-national-xyz-20261024/terrain.sqlite3`。元標高は読み取り専用で開く。起動スクリプトが SHA-256 を計算し、設定・元ファイルの長さ・対象領域と一緒に再開時に照合する。

- 作業領域は z14 元標高の 4,096 セル四方（4,097 標本／辺、投影長約 39.136 km）。保存 XYZ タイルとは別の区切りで、全国の元 z14 タイルから列挙する。`--national-chunk-cells` と `--national-window x0 y0 x1 y1` は小範囲の試験用。window は作業領域番号の半開区間。
- 作業領域の外へ投影長 2 km 分を読み、山頂検出・地形指標を計算してから中心を切り出す。元標高の巨大な全国配列や作業 DEM ファイルは作らない。基本生成は既定で 4 作業領域を同時に処理する（`--national-workers`、起動スクリプトは `-ChunkWorkers` で指定）。各領域の標高接続・キャッシュ・形状は専用とし、候補評価など領域内の Rayon スレッドプールは全領域で共有する。共通プールは OS の論理プロセッサー数の半分。領域数を変えても生成設定・mesh_id は変えず、確定形状と保存 BLOB の一致を検証する。
- 領域内で z14 から z6 へ頂点を削減し、`chunks/chunk-x-y/zN.mesh` に中間形状を確定保存する。形状は XRG1、座標は領域内の元標高格子番号。`base_done` は全 9 レベルと有効タイル情報の保存後に記録する。
- 量子化と同期は z6 → z14。基本形状の境界点を全国共通の `(z, global_source_x, global_source_y)` 索引へ登録する。各作業領域はその境界点・直前の粗い確定レベル・同レベルの前回補修点をすべて含めて再分割する。補修で境界点が増えなくなるまで全国の作業領域を反復する。補修頂点を以降の詳細レベルにも引き継ぐ。
- XY は各レベルの量子化格子へそろえる。元標高セル単位では z6 が 4、z7 が 2、z8 以降が 1。高さを保存形式に丸めた後、間引いていない領域内の全元標高標本と比較し、山頂条件・許容誤差・最小角 10°を再検証する。不合格なら生成を停止し、完了扱いにはしない。
- 本体と外側 1 層の余白が i16 XY に収まるよう、各面の XY 軸方向の幅を保存タイル一辺の 0.49 以下に補修する。境界の検証は最終形状でも行い、両側に作業領域がある境界の片面辺と非多様体辺を拒否する。
- 各 z の全体形状を一括でメモリーに載せず、`national-work.sqlite3` の頂点・面・辺・R-tree 索引を使う。保存タイルの本体面を矩形交差で求め、辺を共有する面だけを外側 1 層として追加する。作業領域をまたぐ余白も同じ索引から取得する。
- 親頂点の参照先索引も作業 SQLite に置く。現在と直前のレベルを別テーブルで準備し、レベル完了記録と親索引の交代を一つのトランザクションで確定する。各タイルは保存前に YMV4 と TFC2 を復元し、頂点列と向き付き面を照合する。
- `national-config.json` の共通 mesh_id は生成開始時に一度だけ作り、再開で維持する。同じ元標高でも別の生成実行には異なる識別子を付ける。同じ z の保存タイルはすべて同じ識別子を持つ。
- 並列基本生成の進捗・有効タイル・完了記録は管理スレッドだけが書き込む。領域ごとの進捗は各作業スレッドが専用ファイルへ書く。ある領域が失敗したら新しい領域の割当を止め、処理中の他領域は保存して終了する。境界同期・全国保存は従来どおり領域順・レベル順に処理する。
- 再開時は確定済みの基本形状、同期済みレベル、保存済みレベルを利用する。基本形状・確定形状は削除しない。作り直せる面索引だけを次のレベルで置き換える。同一出力への二重起動は Windows の排他的なファイル共有モードで防ぐ。起動時・基本生成の領域切替時に空き 1 GiB 未満なら停止する。失敗は progress.json とログへ記録する。

作業領域の辺は三角形分割の制約線として残る。全国を一度だけ Delaunay 分割した結果とは異なり、とくに粗いレベルでは作業境界をそろえる点数の増加がある。保存タイル境界での独立生成とは異なり、保存時は作業境界を含む一つの接続索引から面を抽出する。全国完成後に容量と境界の見え方を確認する。

検証は `test_xyz_national.py <出力先> --resume-exe <exe> --source <元標高SQLite>`。隣接領域の境界列・標高、粗い点集合の詳細レベルへの包含、独立 Python 復元、参照深度 2 以下、再開前後の形状／BLOB 一致を確認する。この検証器は小範囲用で、全国全体を一括でメモリーに載せて実行しない。全国側の生成中検証は作業領域・保存タイル単位で行う。

### 座標・差分・描画

- x・yは符号付き16ビット。タイル本来の左端／上端を0、一辺を16,384単位とし、実座標は共通原点・タイル位置・一辺から復元する。余白も同じ座標系に入れる。
- zは符号なし16ビット。`u < 24000` は `(u - 24000) × 0.5 m`、それ以外は `(u - 24000) × 0.25 m`。範囲は−12,000～10,383.75 mで、全タイル共通。メートルへ復元してから補間・法線計算する。
- 生成後は粗いレベルから細かいレベルの順に保存する。z6～z9・z12は全頂点、z10・z11・z13・z14は親との差分とし、参照は最大2段。三角形接続はレベルごとに独立して保存する。
- DEM頂点法線・DEMに適合した傾きは保存しない。描画はLoop細分割＋形状保持を基本とし、法線は表示メッシュから計算する。分割数は保存容量に影響しない。
- 海岸線をメッシュへ組み込まない。標高欠損を0 mとする部分は実測海底ではない。地表テクスチャはASTC 8×8を採用し、各レベルの解像度は別途決める。

## 実装仕様 v4（2026-10-24）

この節は次期配布形式と生成器の実装契約である。v4で親参照の圧縮方式と可変長ストリームを導入し、頂点BLOBをYMV4とした。三角形BLOBはYMT3/TFC2を維持する。v3で三角形・親頂点参照を32ビットとし、YMV4/YMT3/TFC2へ更新した。旧16ビットの接続形式とは非互換。v2でレベル名もXYZのz6～z14に統一し、ランベルト投影からEPSG:3857／XYZへ変更し、保存メッシュ内Yも南向きとした。v1のタイル番号・座標BLOB・生成計画とは互換性がない。今回、未確定だった列名・BLOBのヘッダー・参照方法を実装用に具体化した。既存試作のバイト列との互換性はない。ここに書いた仕様の実装・全国生成が完了したという意味ではない。仕様を変更するときは形式の版と生成設定の指紋を変更する。

### 1. 単位・方向・基本規約

- 距離・高さはメートル、角度のmetadataは度、三角関数の引数はラジアン。計算は特記がなければIEEE 754 binary64。
- 投影座標Xは東、Yは北、Zは上。ただしタイル番号・保存するメッシュ内XYは右・下が正。保存三角形はこの右・下の平面で時計回りとし、東・北の平面へ変換すると反時計回りになる。地球曲率を加える表示座標変換は保存メッシュの外側で行う。
- 固定長整数はすべてリトルエンディアン。符号付き整数は2の補数。構造体をそのまま書かず、フィールド単位で符号化する。
- JSONはUTF-8、BOMなし。キーの並び順を意味に使わない。NaN・Infinity・重複キーは禁止。
- ファイル形式の整数カウントはu32、タイル番号はi32。SQLite上ではINTEGERを使う。BLOB内の頂点参照番号もu32。座標成分と版・フラグは16ビットを維持する。
- 量子化のroundは最も近い整数、ちょうど半分なら0から遠い側。Pythonの標準roundとは異なる。
- XYZの所属判定は左・上を含み、右・下を含まない。投影XYでは `[xmin,xmax) × (ymin,ymax]`。面の抽出は境界接触を含む閉矩形との交差を使う。点の所属と面の抽出を混同しない。

### 2. SQLiteスキーマ

```sql
PRAGMA application_id = 1498240077; -- ASCII YMTM
PRAGMA user_version = 4;
PRAGMA foreign_keys = ON;

CREATE TABLE metadata (
    key TEXT PRIMARY KEY NOT NULL,
    value TEXT NOT NULL
) WITHOUT ROWID;

CREATE TABLE tiles (
    z INTEGER NOT NULL CHECK(z BETWEEN 6 AND 14),
    tile_x INTEGER NOT NULL CHECK(tile_x BETWEEN -2147483648 AND 2147483647),
    tile_y INTEGER NOT NULL CHECK(tile_y BETWEEN -2147483648 AND 2147483647),
    mesh_id TEXT NOT NULL,
    vertex_count INTEGER NOT NULL CHECK(vertex_count BETWEEN 3 AND 4294967295),
    triangle_count INTEGER NOT NULL CHECK(triangle_count BETWEEN 1 AND 4294967295),
    body_triangle_count INTEGER NOT NULL
        CHECK(body_triangle_count BETWEEN 1 AND triangle_count),
    vertices BLOB NOT NULL,
    triangles BLOB NOT NULL,
    PRIMARY KEY(z, tile_x, tile_y)
) WITHOUT ROWID;
```

1行が1タイル。本体と外側1層の余白を同じ行へ保存する。空タイルは行を作らない。頂点法線・傾き・余白フラグ・接合候補・本体矩形・親の復元済み頂点列を重複する列は持たない。単独保存レベルでは、そのタイル自身の全頂点をvertices BLOBに保存する。頂点数・面数はデコード前の割当制限と本体描画に使うため保持する。三角形数は三角形インデックス数の1/3。

`mesh_id` は接続可能な同レベルの共通メッシュ全体に共通の文字列。例は `generation_id + ':z12'`。同じ版でも生成途中の異なる補修結果を混在させない。tile_x・tile_yのSQL上の型はi32範囲を許すが、配布検証とデコーダーでは非負かつ各zの範囲内であることを追加で必ず検査する。DB内で同一レベルに複数の互換性のないmesh_idが存在したら配布検証で失敗させる。

### 3. metadataの必須キー

valueはすべてJSON値の文字列表現とする。たとえば文字列値は `"YMTM"`、真偽値は `false`、オブジェクトは `{...}`。JSON.parseを1回行って取り出す。原点などのスカラーとオブジェクトの重複定義は作らない。

| key | JSON型・内容 |
|---|---|
| `format` | 文字列 `YMTM` |
| `format_version` | 整数4 |
| `generation_id` | UTC時刻と設定指紋を含む生成全体の識別子。再開時は保持 |
| `complete` | 全工程・検証終了時だけtrue |
| `distributable` | 配布用受入検証をすべて通した場合だけtrue |
| `crs` | 下記の座標参照系オブジェクト |
| `origin_x` / `origin_y` | 世界左上の投影座標。X=−πR、Y=+πR。数値はbinary64で生成 |
| `levels` | z6～z14の定義をz昇順に並べた配列 |
| `vertex_encoding` | 文字列 `YMV4` |
| `triangle_encoding` | 文字列 `YMT3/TFC2` |
| `vertex_index_bits` | 整数32。三角形と親頂点参照に適用 |
| `xy_units_per_tile` | 整数16384 |
| `height_encoding` | オブジェクト `{"zero":24000,"negative_step_m":0.5,"positive_step_m":0.25}` |
| `halo_layers` | 整数1 |
| `outer_compression` | 文字列 `none` |
| `settings` | 全生成条件・閾値・ソース復号形式を記録したオブジェクト |
| `source_manifest` | 各入力の用途、ファイル名、バイト数、SHA-256、標高基準・由来 |
| `settings_sha256` | 設定の正規化JSONのSHA-256、小文字16進64桁 |
| `validation` | 検証版、日時、件数、最大誤差・最小角、失敗件数を含む結果 |

`levels` の各要素は `{"z":14,"tile_size_m":2445.98490512564,"error_m":12.5,"summit_min_error_m":12.5}` の形。投影上の一辺は `2πR/2^z`。誤差は `12.5 * 2^(14-z)`。全レベルで最低頂点数・目標頂点数は設定しない。頂点数カウントの上限は4,294,967,295で、実在頂点のインデックスは0～vertex_count−1。u32番号自体は0～4,294,967,295を表せるが、この形式の頂点数カウントでは最大番号4,294,967,295は実在点を指さない。実用上の資源上限はこの理論上限と区別する。tile_size_mはCRSから再計算した値と相対誤差1e−14以内で一致させる。

指紋の正規化はキーをUnicodeコードポイント順に再帰的にソートし、配列順は保持、空白なし、UTF-8で行う。settings内の非整数パラメータは数値ではなく10進文字列で保存する（例："12.5"）。小数の末尾0と不要な小数点を除き、負の0は"0"、指数表記は禁止。整数は10進整数、文字列は制御文字・二重引用符・バックスラッシュだけJSONエスケープし、その他のUnicodeはUTF-8で直接書く。生成器が正規化した設定JSONそのものを保存し、再開時はそのバイト列を比較する。metadataのcrs等の表示用数値はこの指紋の入力にせず、同じ値をsettings内の定義から生成する。

### 4. 緯度経度からタイル番号まで

国土地理院と同じWebメルカトル／XYZを使う。CRS定義は以下とする。

```json
{
  "authority": "EPSG:3857",
  "type": "web_mercator",
  "input": "WGS84_longitude_latitude_degrees",
  "radius_m": 6378137,
  "central_meridian_deg": 0,
  "false_easting_m": 0,
  "false_northing_m": 0,
  "axis": ["east", "north"],
  "tile_scheme": "XYZ",
  "tile_axis": ["east", "south"],
  "local_mesh_axis": ["east", "south"],
  "unit": "metre"
}
```

保存する投影座標系はEPSG:3857。メッシュの局所座標とXYZのYは南向きなので、投影座標の北向きYとは符号が異なる。緯度経度はWGS84、標高は元DEMの標高で、楕円体高へ変換しない。

```text
R = 6378137
M = π*R
φmax = atan(sinh(π)) = 約85.0511287798066°
n = 2^z
S = 2*M/n
λ = longitude_deg*π/180
φ = latitude_deg*π/180
X = R*λ
Y = R*asinh(tan(φ))
origin_x = -M
origin_y = +M

tile_x = floor((X+M)/S)
tile_y = floor((M-Y)/S)
xmin = -M + tile_x*S
xmax = -M + (tile_x+1)*S
ymax = +M - tile_y*S
ymin = +M - (tile_y+1)*S

longitude_deg = (X/R)*180/π
latitude_deg = atan(sinh(Y/R))*180/π
```

入力は−180°≤経度≤180°、−φmax≤緯度≤φmax、有限値のみ。範囲外はエラー。範囲検査後に世界端の丸め誤差を0～n−1へ補正し、経度180°と最南端は最終タイルに入れる。世界外をクランプして受理しない。日付変更線をまたぐラップ描画は日本向けv2の対象外。

通常は左・上境界の点をそのタイルへ含める。子から親は `(z-1,tile_x/2の整数切捨て,tile_y/2の整数切捨て)`。番号は非負で、全行について `0 <= tile_x,tile_y < 2^z` をデコーダーでも検査する。zが1増えると細かくなり、タイル一辺は半分になる。北隣はtile_y−1、南隣はtile_y+1。

```sql
SELECT mesh_id, vertex_count, triangle_count, body_triangle_count,
       vertices, triangles
FROM tiles WHERE z=? AND tile_x=? AND tile_y=?;
```

地理院XYZタイルの `{z}/{x}/{y}` と、メッシュの `(z,tile_x,tile_y)` は同じ担当範囲を指す。画像256ピクセルに対しメッシュの一辺は16384単位なので、ピクセル境界pは局所座標64p、ピクセル中心p+0.5は64(p+0.5)。元標高を補間するときもこの半ピクセル差を維持する。

取得前に「行がない」と判断しない。未要求・取得中・取得失敗・存在しないタイルを別状態として扱う。完全なDBで存在しない担当領域を海色にする方針は描画側で適用する。

公式仕様：https://maps.gsi.go.jp/development/siyou.html

### 5. 頂点の量子化と共通識別

復元頂点1点の形式は次の6バイト。x・yの基準は当該タイルの左上で、Xは右、Yは下が正。

| バイト位置 | 型 | 内容 |
|---|---|---|
| 0 | i16 | x単位数 |
| 2 | i16 | y単位数 |
| 4 | u16 | 高さコード |

```text
qx = round((X-xmin)*16384/S)
qy = round((ymax-Y)*16384/S)
uz = round(24000 + Z / (Z<0 ? 0.5 : 0.25))

X = xmin + qx*S/16384
Y = ymax - qy*S/16384
Z = (uz-24000) * (uz<24000 ? 0.5 : 0.25)
```

qx・qyは−32768～32767。担当矩形の左上(0,0)、右下(16384,16384)。左／上の隣接タイルの開始辺は−16384、右／下の隣接タイルの終了辺32768は範囲外。高さは−12,000～10,383.75 m。範囲外・NaN・無限値はエラーで、飽和や整数オーバーフローで隠さない。

z14のxy基本単位 `g=2πR/(2^14*16384)`（約0.149291071 mの投影長）を用い、生成中の共通頂点IDを `(GX,GY)` のi64整数対とする。GX・GYは世界左上から東・南へ増え、`X=−M+GX*g`、`Y=M−GY*g`。標高は同一XYに一つだけ割り当てる。最初の量子化前は別の不変な生成頂点IDを持つ。

粗いレベルの刻み係数を `k=2^(14-z)` とし、`qx=GX/k-tile_x*16384`、`qy=GY/k-tile_y*16384`。GX・GYがkで割り切れることを確認し、整数演算で局所座標へ変換する。浮動小数点の大きい世界座標から引き算して共有点を再量子化しない。

同一頂点は、その頂点が存在する最も粗いレベルの刻みへ一度だけ丸め、全詳細レベルと隣接タイルで座標・高さを共有する。粗い点は詳細側の格子にも乗る。z6のxy刻みは約38.218514 mの投影長、最大丸め幅は各軸約19.109257 m。z14は各軸約0.074646 m。地表での水平幅は概ねcos(緯度)倍。高さ丸め幅は陸0.125 m・海底0.25 m。

丸めで頂点が合流、面が退化・反転、誤差超過・角度不足となったら、その粗いレベルでの点の採用／削減を再検討する。必要なら詳細側に候補を追加して該当範囲と祖先を再生成する。既存点を黙って削除・高さ平均して完了させない。最終量子化座標で品質検証が通ることが公開条件。

### 6. 頂点BLOB YMV4

全レベルを連鎖する差分保存は行わず、以下の独立保存レベルで参照を打ち切る。

| z | 頂点保存 | 参照先z | 最大親参照段数 |
|---|---|---:|---:|
| 6 | 全頂点 | なし | 0 |
| 7 | 全頂点 | なし | 0 |
| 8 | 全頂点 | なし | 0 |
| 9 | 全頂点 | なし | 0 |
| 10 | 親との差分 | 9 | 1 |
| 11 | 親との差分 | 10 | 2 |
| 12 | 全頂点 | なし | 0 |
| 13 | 親との差分 | 12 | 1 |
| 14 | 親との差分 | 13 | 2 |

metadataのsettingsへ `vertexFullZooms=[6,7,8,9,12]` と `maximumVertexDependencyDepth=2` を保存する。levelsの各要素にも `vertex_storage`（fullまたはdelta）と `maximum_parent_depth`（0～2）を保存する。準備コードの計画JSONでは同じ項目をcamelCaseで出力する。

全頂点保存は同じYMV4形式でD=R=0、A=Vとする。親タイルの取得・復元・三角形の読込は不要。単独保存でも粗レベルとの頂点集合の包含、共有点の座標・高さ一致は維持する。生成方式を独立TINへ戻すものではない。

差分保存では必要な親頂点だけ参照し、親の全頂点をコピーしない。余白点の参照先は幾何学的な親1枚に限定しない。参照先は必ず直上の粗いレベル `z-1`。同じzの全タイルが同じ保存方針なので、依存先が複数でも参照段数は最大2。参照先の数自体が2枚以下になる保証ではない。

差分の参照が一つもないタイルはD=R=0、A=Vで保存する。使われない依存先を依存表に残さない。全頂点保存指定のレベルでDまたはRが0以外なら不正とする。差分レベルでも、将来容量・読込数を比較して全頂点保存へ切り替える余地はあるが、自動判定は現時点では導入しない。

ヘッダーは32バイト。

| offset | 型 | 内容 |
|---:|---|---|
| 0 | 4 bytes | ASCII `YMV4` |
| 4 | u16 | 版4 |
| 6 | u16 | 親参照符号化方式。0=生u32列、1=グループ差分可変長。その他は拒否 |
| 8 | u32 | 復元頂点数V |
| 12 | u32 | 依存タイル数D |
| 16 | u32 | 親参照数R |
| 20 | u32 | 新規頂点数A。V=R+A |
| 24 | u32 | 親参照ストリームのバイト数P |
| 28 | u32 | 予約0 |

続いて次の順で保存する。

1. 依存タイル表D件。1件12バイト：`z:u32, tile_x:i32, tile_y:i32`（tile_x・tile_yは有効XYZ範囲の非負値）。
2. Pバイトの親参照ストリーム。復元後はR個の `parent_index:u32`。上位8ビットを依存タイル表の番号、下位24ビットをその親の復元頂点列のローカル番号とする。
3. 新規頂点A件。1件6バイト：前節のqx・qy・uz。

依存表は `(z,tile_y,tile_x)` 昇順、重複禁止。Dは0～256。親参照は `parent_index` 昇順。新規頂点は共通IDの `(GY,GX)` 昇順。復元頂点列は `[参照R点][新規A点]`。三角形番号はこの列を指す。

参照先選択は同じ共通頂点IDを含む直上レベルのタイルのうち `(tile_y,tile_x)` が最小のもの。親の本体に含まれるものを余白だけに含まれるものより優先する。本体所属は本体面に使われる頂点かで判定する。同一点を複数依存先から参照してはならない。対応する粗い点がなければ新規点として保存する。

親参照はu32のビットフィールドとする。連結・累積オフセット・二分探索は使わない。

```text
value = (dependency_slot << 24) | parent_vertex_index
dependency_slot = value >> 24
parent_vertex_index = value & 0x00FFFFFF
```

dependency_slotは0～255、parent_vertex_indexは0～16,777,215。生列の場合は親参照値をリトルエンディアンで保存する。例：slot=1・親頂点5は数値0x01000005、保存バイトは `05 00 00 01`。依存表から直接親を選び、その親の復元頂点列を直接参照する。親参照値の昇順はslot・親頂点番号の辞書順と一致する。

復元前にD≤256、slot<D、parent_vertex_index<親のvertex_countを検査する。参照先の親は最大16,777,216頂点まで。これを超える親への参照は生成エラーとし、下位24ビットへの切捨てや別の意味への解釈を行わない。当該タイル自身の三角形インデックスは引き続き全32ビットをローカル頂点番号として使うため、三角形側にこの24ビット制限はない。将来16,777,216頂点超の親を参照する必要が生じた場合は、別形式を定義する。

復元後の親参照は1点4バイトだが、保存時は生列と圧縮列を比較し、小さい方を選ぶ。同サイズなら生列。指定の全頂点保存レベルと最大親参照2段は維持する。自動の全頂点保存への切替は導入しない。

圧縮方式1はグループ数Gのu16リトルエンディアンから始め、各グループを次の順で並べる。

1. dependency_slot：u8。グループ間で厳密な昇順。
2. グループ内の参照数N：u32の符号なし可変長整数。1以上。
3. 最初の親頂点番号：符号なし可変長整数。
4. 残りN−1個は `今回の親頂点番号−前回の親頂点番号−1` を符号なし可変長で保存。

各親内の頂点番号は重複なし昇順。連番なら差分値0になる。slotは各グループに一度だけ保存し、復元時に上位8ビットへ戻す。可変長整数は下位7ビット先行・継続0x80・最大5バイトで、5バイト目の値は15以下、最短表現だけ受理する。頂点番号を復元した後、24ビットの上限と親の実頂点数を検査する。差分加算はchecked演算。

Gは1～D、グループ数・全参照数・ストリーム末尾を厳密に検査する。切断、重複slot、個数超過、番号超過、余分な末尾を拒否する。R=0なら方式0・P=0。方式0ではP=4R。復元配列はR個、割当前に方式0ではP=4R、方式1ではP≥R+2を確認し、実行時メモリー上限も確認する。

同じ親の連続する1000頂点の合成例では、生4000バイトに対し圧縮1005バイト。これは親参照ストリームだけの例で、実タイル全体や全国データの圧縮率ではない。zlibは追加しない。metadataのsettingsに `parentReferenceCompression="group-delta-varint-or-raw"` を記録する。

親頂点は世界左上基準の整数座標GX・GY（東・南向き）とuzへ復元してから子へ移す。親のi16値をそのままコピーしない。子の刻みで割り切れ、子のi16範囲に入ることを検証する。参照と新規の間を含め重複XYは禁止。BLOB全長は厳密に `32+12D+P+6A` バイト。

親差分は全タイルを横断する頂点共有ではなく、レベル間の再利用。ネットワーク／SQLite読込量の集計には初めて必要になる依存タイルのBLOBも含める。キャッシュキーは `(generation_id,z,tile_x,tile_y)`。復元済み親を共有し、親参照は最大2段、要求タイル自身を含む復元レベル数は最大3。z14→z13→z12またはz11→z10→z9で停止する。頂点の復元だけなら依存先のvertices BLOBと必要なヘッダー情報のみ読み、依存先のtriangles BLOBは取得しない。描画しない親のGPUメッシュは作らない。参照先なし・mesh_idと生成版不整合・範囲外参照はエラー。

### 7. 三角形BLOB YMT3とTFC2

本体と余白を独立したTFC2ストリームにして、区切りを越える面順変更と状態参照を防ぐ。ヘッダーは24バイト。

| offset | 型 | 内容 |
|---:|---|---|
| 0 | 4 bytes | ASCII `YMT3` |
| 4 | u16 | 版3 |
| 6 | u16 | フラグ0 |
| 8 | u32 | 全面数T |
| 12 | u32 | 本体面数B |
| 16 | u32 | 本体TFC2のバイト数L |
| 20 | u32 | 余白TFC2のバイト数H |

続いて本体Lバイト、余白Hバイト。本体B面、余白T−B面をそれぞれ空の状態から復元し、連結する。空区間のストリームも `c2` の1バイト。SQLiteのカウントとヘッダーが一致し、全長が `24+L+H` と一致することを検査する。

TFC2ストリーム：先頭 `0xc2`。辺FIFO15本、頂点LRU12個、last=0で開始する。面の頂点番号は0～V−1。

| 制御バイト | 処理 |
|---|---|
| 0～239 | `edge=code>>4, token=code&15`。FIFOのA→Bを使う |
| 240 | 独立面。A−last、B−A、C−BのZigZag整数を3個読む |
| 241～255 | 不正 |

共有辺のtokenは、0～11がLRU参照、12がA+1、13がB+1、14がlast+1。15は可変長整数Pを読み、`base=(P&1 ? B : last)`、`C=base+unzig(P>>1)`。ZigZagは `zig(d)=d>=0?2d:-2d-1`、逆は偶数ならp/2、奇数なら−(p+1)/2。整数は下位7bit先行、継続bit0x80、最大5バイト。差分ZigZagは最大33ビット、予測元bitを含むPは最大34ビットなので、計算・可変長整数の蓄積にはu64を使う。符号化範囲超過、途中切断、存在しないFIFO/LRU、不正な頂点番号、3頂点の重複を拒否する。

面A,B,Cの後、FIFOは先頭に `[B,A],[C,B],[A,C]` をこの順で追加して15本へ切り詰める。LRUはA、B、Cの順に各点を先頭へ移動し、重複を除き12個にする。last=C。予定面数を読んだ後に末尾が残れば拒否する。

独自面順はFIFO辺に対応する未訪問面から、`(符号バイト数, 未訪問の隣接面数, FIFO位置, 入力面番号)` の辞書順で最小を選ぶ。候補がなければ入力面番号最小の未訪問面。入力面順は各面を最小頂点番号からの巡回表現へ正規化して辞書順にする。向きを反転してはならない。トークンはLRU、A+1、B+1、last+1、差分の順で選ぶ。差分の予測元は `abs(C-B)<abs(C-last)` ならB、それ以外はlast。

エンコーダーは同方向の共有辺重複を拒否する。デコーダーが再現すべきものは頂点番号・面の向き・面数であり、最適化前の面順そのものではない。TFC2デコーダーをYMT3ラッパーから2回呼ぶ。旧TFC1のJS・WASMデコーダーは32ビット番号と34ビット整数に対応していないため流用できない。JSへ移植するときは32ビットのビット演算で値を切り詰めず、Numberの整数演算またはBigIntを使う。

### 8. 元標高の評価

入力は既存の `build/terrain-lod.sqlite3` の最詳細L14標高。ファイル名ではなくsource_manifestのSHA-256を固定する。入力は読み取り専用。L14は今回のzレベルとは別の元データのズーム番号。

投影XYを緯度経度へ逆変換し、Web Mercator画像のピクセル中心へ対応させる。

```text
N = 16384 * 256
px = (longitude_deg+180)/360*N - 0.5
py = (1-asinh(tan(latitude_rad))/π)/2*N - 0.5
```

周囲4ピクセルをバイリニア補間する。タイルをまたぐ参照を必ず取得し、タイル端でクランプしない。有効標高の重み合計が0.999999を超える場合のみ有効標高とし、それ以外は0 mへ埋める。欠損マスクは生成検証用に保持し、海岸に沿ってメッシュを切らない。海底の実標高はこの入力から生成できない。標高BLOBの復号方式もsettingsとsource_manifestに固定する。

最詳細の評価格子は地表換算で10 m以下の間隔とする。各作業領域の全緯度範囲で `投影格子間隔*cos(緯度) <= 10 m` を満たす間隔を使い、共有境界で格子を一致させる。簡単な基準実装では投影上10 m間隔を使えば日本全域で条件を満たす。世界左上原点に格子を合わせ、各処理領域の端から別々に刻まない。評価値と共有頂点の標高は同じ補間関数から求める。許容誤差はこの離散評価格子に対する最大鉛直差であり、元DEMの観測精度や地表全点の連続的な最大誤差を保証する値ではない。粗いレベルでも誤差検査用の格子を粗くして合格させない。

全国の対象領域は入力の有効標高ピクセルを投影した被覆から求める。旧ランベルト8 kmカタログのタイル番号は流用しない。有効標高が含まれるz14担当矩形と、その隣接形状の構築に必要な周辺領域を計算する。z14は元L14のXYZ境界と一致するため、有効標高を持つ元タイルのx・yをそのまま候補にする。元タイルの有効性検査前の処理計画では全L14行を候補とし、全欠損は生成時に省略する。z13以下の候補はz14キーを親へ集約する。同じタイル内の欠損部分は0 mとして面を維持し、タイル内海岸線の切り抜きは行わない。全欠損の担当タイルの行は省略する。元の有効領域が途切れていないことを入力被覆との比較で確認する。

### 9. 最詳細TINと粗メッシュ生成

Webメルカトルの長さはそのまま地表長とみなさない。山頂半径1 km・検出500 m・平滑化125 m・凸部250 mは地表換算値。距離判定はWGS84緯度経度上の測地距離、近傍検索の包囲範囲は緯度による尺度を考慮して保守的に広げる。勾配の差分距離も地表長で計算する。密度半径は当該レベルの投影タイル一辺の半分とし、世界左上の共通格子で数える。誤差は鉛直メートルなのでcos補正しない。

全国を保存タイルごとに独立三角形分割しない。処理を分割しても共通の頂点ID・辺・変更履歴で同じレベルの面構造を一致させ、その後で保存タイルへ抽出する。保存境界を全レベル共通の固定頂点列で埋めてはならない。

最詳細は四隅2面からGreedy Insertionで始める。各面内の評価格子で鉛直差最大の点を候補とし、最大誤差キューから追加する。点が辺上なら両面を分割する。向き・incircleは整数の厳密判定または適応精度述語を使う。共円の対角線は頂点IDの辞書順で一意にする。Delaunayの辺反転後、変更面だけ再評価する。z14の停止誤差は12.5 m。

品質補修は最小角10°未満の面を対象に、辺反転で改善できれば反転し、改善できなければ元格子上の未使用点を追加して再分割する。候補は問題面内または共有辺を挟む局所領域内から、補修後の最小角最大、最大誤差最小、頂点ID最小の順で選ぶ。補修が停止しない／適切な点が存在しない場合はその領域を失敗とする。任意入力で有限回で10°を達成する保証はないため、1処理領域あたり補修反復1,000,000回を安全上限とし、到達時は失敗理由を記録する。これは誤差・角度を緩めて完了させるための制限ではない。

z13以下は直前の詳細レベルの頂点を削除する。候補点の星状近傍を取り除き、残った境界を向き付き単純多角形として再三角形分割する。穴の外周・拘束辺を維持する。耳切りの有効候補をID順で選び、局所辺反転で最小角を改善する。削除後の面が以下を満たす場合だけ削除可能。

1. XYの被覆面積が削除前と等しく、重なり・穴・反転がない。
2. 新しい全三角形の最小角が10°以上。
3. 新しい全三角形内の評価格子が局所山頂制約を満たす。
4. 他の作業領域と共有する面・辺の同期が確定している。

山頂制約は冒頭の検出・距離係数を使い、局所許容値 `T(p)=max(12.5,error_m*scale(p))`。削除候補の合格判定は `max(abs(mesh_height(p)-DEM(p))/T(p)) <= 1`。浮動小数点誤差の許容は鉛直1e−6 m、角度1e−7度まで。面内標高はXY重心座標の線形補間。Loop後の形状はこの保存誤差の定義に含めない。

候補順位は地形の重みを掛けた誤差が小さいものから削除する。地形重みはDEMをσ125 m・半幅500 mの分離Gaussianで平滑化したBから計算する。

```text
slope = hypot(dB/dX,dB/dY)  （中心差分、外周は片側差分）
s = clamp((slope-tan(1°))/(tan(8°)-tan(1°)),0,1)
convex = clamp((4B-B西250m-B東250m-B南250m-B北250m)/50,0,1)
w = (0.02+0.98*s*s*(3-2*s))*(1+0.5*convex)
weighted_error = max(abs(mesh_height-DEM)*w)  （置換面の全評価格子）
```

密度は保存タイル一辺の半分の半径で数え、共有点は1回だけ数える。隣接領域も含む。基準4096点として `penalty=1+max(count-4096,0)/4096`、削除スコアは `weighted_error/penalty`。これは削除順の重みであり、追加予算・密度の強制上限ではない。円内の点数は空間ハッシュで算出する。近似する場合は別のpolicy版とし、試作の9×9密度表と同一結果とは扱わない。

最小スコア優先キュー、同点は不変頂点ID順。近傍面の版番号で古い候補を無効化する。削除時は局所候補に加え、密度半径内でスコアが変わる候補も更新する。優先順位が下がり得るのに古いキュー値を放置してはならない。削除可能な点がなくなったら停止し、目標個数まで無理に削除しない。

並列化は読込・DEM格子・誤差評価・独立領域の候補計算に使う。確定順は決定的にし、変更の影響範囲が重なる候補を同時適用しない。ワーカー既定はOS論理プロセッサー数の半分、最低1。キャッシュ上限は8 GiB。基本メッシュ・完成レベル・中間候補は別の作業SQLiteに保存し、配布用へ作業用表を混ぜない。

### 10. 余白補修とタイル抽出

品質補修点を通常メッシュへ追加し、詳細レベルにも存在する頂点にする。粗いレベルで新点が必要なら詳細側へ反映してから該当範囲を再確定する。粗い側にだけ新しい頂点を作らない。全レベルを先に不可逆な完了状態へせず、補修の影響を受ける範囲を無効化できる状態で保持する。

抽出は三角形と担当矩形のSAT交差判定で本体集合を得て、辺共有隣接を1回たどった面を余白集合にする。頂点接触だけでは層を増やさない。本体と余白の集合は排他的。共有辺キーは共通頂点ID2個を昇順にした組。面は分割・境界へクリップせず、そのまま保存する。

共通メッシュの同一面が隣のタイルに重複保存されることは許す。頂点リストは抽出した面が実際に参照する点だけに縮める。孤立点は保存しない。本体面0ならそのタイルは省略する。

長い本体面・余白面でi16xy範囲を超える場合は、抽出点を捨てず、共通メッシュで面を補修し、詳細側と同レベル隣接タイルにも反映して再抽出する。65,536点を超えても32ビット接続で保存できる。u32の個数範囲または実行環境の資源上限を超える場合は失敗とし、頂点インデックスを切り詰めない。隠れた小タイル分割を導入するなら形式の版を変更する。

### 11. 読込・同レベル接続・異レベル接続

読込順はmetadataの検査、必要行の取得、依存頂点の再帰復元、YMT3復元、カウント・範囲の検査、GPU資源作成。u32上限をそのままメモリー割当してはならない。ヘッダーの長さ計算はchecked u64/usizeで行い、BLOB実長・残りメモリー・GPUバッファ上限を先に検査する。親の復元を含め実行時予算を超えたら読込を拒否または粗いLODへ戻す。失敗タイルで描画中の正常な旧タイルを即座に消さない。

同レベル・同mesh_idは世界左上基準の共通整数XYとuzで頂点を統合する。保存面の時計回りは世界の東・北座標で反時計回りとなる。描画側がYを反転しない右・下座標を使う場合はfrontFaceの設定を合わせ、二重に反転しない。面キーは3つの共通頂点IDの巡回正規化で、逆向きとは区別する。重複面は1回描画する。接合帯以外の内部面は既存バッファを再利用し、全タイル同士の面比較を行わない。読み込み変化時に新規タイルの本体境界交差面・余白面と隣接タイルだけを処理する。面の削除は参照数で管理する。同レベル接合で新点・新面を生成してはならない。

異なるレベル／サイズでは担当矩形の隣接区間を求め、部分接触とT字も扱う。実行時に接するLOD差は任意。担当領域の重複は詳細レベルを優先し、同レベルならキー順で所有を一意化する。未ロードは接続相手に数えない。

接合帯は担当境界に交差する面と保存余白から作る。接合帯以外の面はそのまま維持する。帯を除いたメッシュの外周を拘束辺として、読み込んだ通常頂点だけで局所の拘束三角形分割を作る。内点・辺上点・部分区間の端を含めて制約を回復する。新しい標高点をDEMから取得したり、別候補配列を要求したりしない。同一XYの高さは詳細レベル優先、同レベルは一致必須。置換面が元の帯を完全に被覆し、残した面との境界でT字の未接続を残さないことを検査する。

接合品質の改善に通常頂点を追加選択するときは、未使用点の中から最小角が最も改善する点、同点は共通ID順。外側1層だけでは10°を満たせない組み合わせがあり得る。正しい被覆・反転なし・拘束辺一致は必須、接合帯だけの最小角10°は目標として結果を報告する。必須条件を満たせなければその切替を確定せず、隣接LODを近づけて必要タイルを取得する。隙間を許して完了しない。

この接合仕様は出力の契約で、局所三角形分割の高速化手法は変更できる。同じ入力から試作と完全に同じ面順を作る義務はない。読込の都度全シーンを再初期化せず、タイル集合が変わった接合帯だけを再計算する。

### 12. 描画とLOD切替

GPUへは共有頂点とuint32インデックスを渡す。WebGL2はUNSIGNED_INT、ネイティブ描画も32ビットインデックス形式を指定する。旧Uint16Array等のバッファへ暗黙に変換しない。ワイヤーなどで頂点展開する場合は別の表示用バッファとし、必要容量へ計上する。DEMの頂点法線・傾き情報は不要。

Loopは共有辺の両側を含む隣接情報から計算する。内部の奇数頂点は両端3/8ずつ・対向点1/8ずつ、境界辺は両端1/2ずつ。偶数頂点は価数n=3ならβ=3/16、n>3ならβ=3/(8n)、`(1-nβ)*P+β*sum(neighbors)`。実際のデータ外周は境界規則3/4・隣接2点各1/8。保存タイル端をデータ外周とみなさない。

形状保持rは0が通常Loop、1が線形分割形状。各分割段階で `P=(1-r)*LoopPosition+r*LinearPosition`。r既定0.5、範囲0～1。分割数1はOFF、2・4・8は各辺の分割数。段数はlog2(分割数)。GPU実装も同じ計算結果を使い、r変更はuniform等でリアルタイム反映する。法線は変形後の形状から再計算する。平滑OFFは面法線、ONは共有頂点の周囲面から算出した法線を正規化する。

LODアニメーションはディザ切替ではなく形状のモーフ。細メッシュの新点を粗メッシュの包含三角形へXY重心座標で投影し、共有点は固定する。粗→細は新点のZを粗面から細点へ、細→粗は逆へ動かす。接続切替とモーフ開始を同じフレームで確定し、完了後に旧メッシュを再表示しない。Loop使用時は両端の表示曲面を評価した位置で補間し、未分割平面へ一度戻さない。GPU資源・接合が準備できるまで現在表示を保持する。中断は現在の表示位置から次の遷移を開始する。

### 13. 生成・再開・公開までの工程

```text
入力の指紋と設定を固定
→ 共通10 m標高・山頂／重みの準備
→ z14 Adaptive TINと品質補修
→ z13 … z6を順に削減
→ 共有境界・余白に必要な補修を全詳細へ反映
→ z6 … z14の順に共有点を量子化、各段階を再検証
→ 本体＋外側1層を抽出
→ z6 … z14の順に独立保存レベルを挟んでYMV4とYMT3を保存
→ 全体検証
→ complete=true、distributable=true
```

作業用SQLiteには工程・タイル・設定指紋・入力指紋・確定版・エラーを記録する。完了したジョブをトランザクションで保存し、再開時は指紋と依存版が一致するものだけ再利用する。親や共通メッシュの補修で影響した出力は無効化して再作成する。SQLiteは単一書込担当とし、ワーカーは読取と計算を行う。1タイルの書込は原子的にする。

配布用は新しい一時SQLiteへ書き、全検証完了までcomplete/distributable=false。WALを使った場合はチェックポイントして接続を閉じ、単独ファイルで読めることを確認する。完成ファイルへの置換は同一ボリュームの原子的rename。失敗時に元データ・既存の配布ファイル・保存済み中間結果を削除しない。生成を開始する操作は今回の文書更新に含めない。

### 14. 受入検証と最小テスト

配布可否は以下をすべて満たした場合だけtrueにする。

- `PRAGMA integrity_check` がok、必須metadata・スキーマ・版が一致。全頂点保存レベルの依存0・親参照最大2段を検査し、全行のBLOBを実際に復元し、サイズ・予約値・親依存・番号・重複・孤立点を検査。
- 座標の順逆変換を全国の標本で往復し、誤差1e−6度以内。原点138°E・36°N、投影原点の負側、タイル境界、親子対応を試験する。
- z14→z6の頂点集合包含と、共有頂点の量子化後GX・GY・uz一致。全体のxy丸め許容範囲と高さ範囲を確認。
- 量子化後の全面が正向き・非退化。内部の無向辺は2面に属し、向きは逆。外周は1面。面重複、穴、自己交差なし。
- 全レベル・全評価格子で最大鉛直差と山頂局所制約を検査。格子点だけでなく、共有辺の接続・被覆を別途幾何検証する。
- 保存前メッシュとTFC2復元後の向き付き面集合が完全一致。本体／余白の分類、1層の辺隣接、カウントを再計算して一致。
- 同レベル全隣接タイルで共通面・共通点が一致。接続による新点・再三角形分割0。異LODは全差・全方向、4領域・T字・一部接触・未ロードを試験。
- Loop OFF／2／4／8、平滑ON／OFF、保持0／0.5／1で継ぎ目・NaN・反転を確認。LOD往復中に一瞬旧形状へ戻らないことを動画またはフレーム検査する。
- 破損BLOB試験：切断、余分な末尾、過大カウント、不明版、参照先欠落、自己参照、範囲外点、反転面。失敗時に過大割当やアプリ停止を起こさない。

バイト列の最小検査例：新点3点・親参照0・依存0ならYMV4は50バイト。高さ−12000 mはuz=0、0 mは24000、8848 mは59392、10383.75 mは65535。任意の一辺SでX−xmin=S/2はqx=8192、Y=ymax−S/2はqy=8192、−Sは−16384、+2Sは32768となり拒否する。TFC2空列は `c2`、単独面[0,1,2]は `c2 f0 00 02 02`。

容量はレベル別にタイル数、復元頂点数、本体／余白面数、YMV4合計、YMT3合計、依存込み初回読込量を集計する。別にSQLite実ファイルサイズとページ空き領域を示す。テクスチャはメッシュ容量へ混ぜず別計上する。

## 16ビット保存形式の採用方針（2026-10-22）

座標は16ビット固定小数、三角形の各頂点番号は符号なし16ビットとする。頂点番号は0～65,535なので、1メッシュに保存できる頂点数は最大65,536点。三角形の枚数の上限ではない。頂点数・三角形数を記録するヘッダーのカウントは32ビットを維持する。

上限は基本頂点だけでなく、共通プールからの追加点・共有辺の接続点・品質補修で必要になる点を含む最終メッシュへ適用する。追加工程で上限に達したタイルへは点を追加せず、残りの全国予算を他の候補へ回す。境界接続や基本誤差・最小角の条件を上限のために緩めず、収まらない場合は保存単位を分割する。表示時のLoop分割で増える頂点数は保存形式の上限とは別に扱う。

各タイルにタイムスタンプなどを含む文字列を保持する。接続可能な同一レベルの元メッシュ全体で共通とし、タイル個別の生成時刻にはしない。同一識別子なら重複除去だけで接続し、不一致なら余白を使う接合処理を行う。現在の試作のハッシュ付き文字列から生成版文字列への変更は未実装。


## 余白メッシュの採用候補（2026-10-24）

接合で必要な点を余白の通常メッシュへ事前に組み込み、接合専用の追加候補列を持たない方式を採用候補とする。同レベルの余白は共通メッシュから取り出し、直接結合できる形状をそろえる。525条件の拡大検証では接続はすべて成功したが、角度・標高誤差の保証は未完了。全国配布への確定採用ではない。[検証結果と残る課題](tools/terrain/OVERLAP_VALIDATION.md) に記録した。


## 余白を三角形の層数で保存する試作（2026-10-24）

タイル担当矩形に交差する面に加え、辺を共有する外側の面を2層保存する方式を実装した。固定距離方式も比較用に残す。通常12接合では2層で11条件、3層で12条件が角度10°以上。2層が常に十分とは保証しない。自動の局所拡張は未実装。[切り出しの定義・容量・検証結果](tools/terrain/OVERLAP_COMPARISON.md) を参照。


## 20%余裕枠の比較（2026-10-24）

地域の削減試作は独立TIN頂点数×1.2で停止する実装だったため、×1.0、誤差・角度のみで停止する方式と比較した。旧全国追加プールの再実行ではない。3地域・7段階・3方式の63メッシュを検証した。共通の最詳細を除くBLOB合計は、余裕なしで約16.9%減、目標なしで約39.1%減。後者は粗い段階で山頂形状が悪化した。固定20%枠の廃止と、山頂形状の保護条件の廃止は区別する。全国生成設定はまだ変更しない。[比較結果と条件](tools/terrain/BUDGET_COMPARISON.md) を参照。


## 山頂の誤差制約による削減試作（2026-10-24）

20%頂点数枠を使わず、山頂の許容誤差を半分にする試作を追加した。半径1 kmで山腹の公称誤差へ滑らかに戻し、最小角10°を維持する。最詳細12.5 mは共通。新方式を含む84メッシュの検証に成功。20%枠ありから容量合計約28.1%減で、山頂制約なしより多くの形状を残せるが、RMSEが悪化する段階もある。全国設定は未変更。[条件と全比較結果](tools/terrain/BUDGET_COMPARISON.md) に記録した。
