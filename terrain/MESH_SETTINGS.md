更新日: 2026-10-22

この文書は会話で合意した次回生成用の仕様をまとめる。設定を変更するときは、この文書も更新する。既存の実験用データや過去の生成設定とは区別する。

## レベルの定義

Q4 を最も詳細なレベルとし、レベルが一つ上がるごとに基本許容誤差・タイル一辺・密度参照半径をそれぞれ2倍にする。

| レベル | 基本許容誤差 | タイル一辺 | 面積／タイル | 全国タイル数 | 密度参照半径 |
|---|---:|---:|---:|---:|---:|
| Q4 | 12.5 m | 2 km | 4 km² | 約117,680 | 1 km |
| Q5 | 25 m | 4 km | 16 km² | 約29,420 | 2 km |
| Q6 | 50 m | 8 km | 64 km² | 7,355 | 4 km |
| Q7 | 100 m | 16 km | 256 km² | 2,157 | 8 km |
| Q8 | 200 m | 32 km | 1,024 km² | 686 | 16 km |
| Q9 | 400 m | 64 km | 4,096 km² | 238 | 32 km |
| Q10 | 800 m | 128 km | 16,384 km² | 95 | 64 km |
| Q11 | 1,600 m | 256 km | 65,536 km² | 未集計 | 128 km |
| Q12 | 3,200 m | 512 km | 262,144 km² | 未集計 | 256 km |

面積と一辺は球面ランベルト正角円錐図法の投影座標上の値。タイルは共通原点に配置し、粗いレベルの1枚が細かいレベルの2×2枚を包含する。

全国タイル数は `build/terrain-error-national-base.sqlite3` の、基本誤差800 m・状態1（標高あり）の8 kmタイル7,355枚を基準に集計した。Q4・Q5 は8 kmタイルを全面分割した概算で、有効標高のない子タイルを除けば減る。Q6～Q10 は共通原点でまとめた枚数。Q11・Q12 は未集計のため推測値を載せない。

## メッシュ生成

| 項目 | 設定 |
|---|---|
| 形式 | Adaptive TIN。頂点座標と三角形の接続を保持 |
| LOD | 各レベルを独立生成 |
| 基本メッシュ | 保存タイルごとに基本許容誤差を満たすまで頂点を追加 |
| 基本頂点数 | 固定の最低頂点数を設けず、頂点数を使い切る目標にしない |
| 保存頂点数の上限（次期形式） | 最終的な1メッシュあたり65,536頂点。基本・追加・境界接続で必要な頂点をすべて含む |
| 追加頂点予算 | 各レベルの全国基本総頂点数の最大20% |
| 追加方法 | 全国共通プールから、最も優先度が高い点を1点ずつ追加 |
| 優先度 | 標高誤差・周辺の勾配や山頂などの地形の特徴・周辺頂点密度を考慮 |
| 優先度の更新 | 頂点を追加して影響を受けた領域を再評価し、次の追加点を選ぶ |
| 追加点の標高誤差下限 | 設けない |
| 密度参照半径 | 各レベルのタイル一辺の半分 |
| 密度参照範囲 | タイル境界で切らず、隣接タイルも含める |
| 密度評価 | 参照範囲の頂点数を参照面積で割り、レベルごとの基準密度と比較 |
| 三角形の品質 | 最小角度10°を条件とし、細長い三角形を抑える |
| 不要点削減 | OFF |
| 異なるサイズの接続 | タイル境界に隙間ができないように接続する |

追加予算は使い切る義務ではなく上限とする。共有境界の頂点は密度評価で重複計上しない。基準密度は、従来のQ6相当で使った「参照円内4,096頂点」を各レベルの参照円面積で割った値を初期設定とする。密度比は `(周辺頂点数 / 参照面積) / 基準密度`。全国追加予算における共有頂点の数え方は、追加工程の実装時に明文化して検証する。

## 曲面と陰影

| 項目 | 設定 |
|---|---|
| 曲面補間 | Loop細分割＋形状保持 |
| 分割数 | 描画時に指定。保存メッシュの頂点数・容量には影響させない |
| 保存する形状情報 | 頂点座標・三角形接続・境界接続に必要な情報 |
| DEMに適合した頂点の傾き | 保存しない |
| DEM頂点法線 | 保存しない |
| 陰影用法線 | 表示メッシュから計算 |
| タイル境界 | 隣接形状を参照し、曲面と陰影をつなぐ |

## 地表テクスチャ

| 項目 | 設定 |
|---|---|
| 元データ | ESA WorldCover 2021 v200 の土地被覆分類 |
| 配色 | 分類ごとに独自のRGBを割り当てる |
| 保存形式 | ASTC 8×8 |
| ミップマップ | 全段を事前生成 |
| 解像度 | 128・256・512・1024・2048・4096画素を比較可能 |
| 縮小 | 分類の被覆率または色を面積平均。分類番号そのものは平均しない |
| 追加の平滑化 | 行わない |
| GPUへの読み込み | 対応環境ではASTCを直接使用。比較用ビューアーの非対応環境では同じASTCを復号したPNGで表示 |

上記の解像度は現在の比較画面の選択肢。全国配布で各メッシュレベルに割り当てるテクスチャの範囲・解像度・共有単位は未確定。

## 海と欠損

- 海岸線はメッシュに格納しない。保存・描画方式は別途検討する。
- 元標高の有効域マスクでメッシュを海岸形状に切り抜かない。
- タイル内の欠損標高は仮の0 mとして扱う。実際の海底標高を意味しない。
- 元標高の有効範囲は生成・検証用情報として保持する。
- タイルの存在しない範囲は海の色で描画する。
- タイルが存在するが未読み込みの範囲は、本来の海とは区別する。全国の最粗LODを常駐させて詳細へ置き換える案は、今後の実装事項とする。

## 全国基本生成の実行と再開

1. `tools/terrain-rs/build.ps1 -QNational -TargetDirectory <terrainの絶対パス>/build/terrain-q-rust-target` でRust生成器をビルドする。
2. `tools/terrain/start_national_q_mesh.ps1` で非表示のバックグラウンド生成を開始する。既定は4並列。
3. `build/terrain-q4-q12-basic.progress.json` と、`build/terrain-q4-q12-basic.launch.json` に記載したログを確認する。

出力は `build/terrain-q4-q12-basic.sqlite3`。プロセスのPIDは `build/terrain-q4-q12-basic.pid` に保存する。元標高のパス・サイズ・更新日時とレベル定義を照合し、異なる条件で既存出力へ追記しない。初回生成の記録を保持し、現在の実行エンジン・実行ファイル・開始時刻は別のメタデータへ保存する。出力ごとのOSロックで二重起動を防ぎ、タイル単位で確定保存する。停止後は同じコマンドで保存済みタイルを飛ばして再開する。失敗状態のタイルは自動再試行せず、原因を確認してから扱う。

空きディスク容量は既定で8 GiB以上を要求する。大きなタイルでは元DEMを31.25 m間隔で行帯ごとに読み、座標配列の一括展開を避ける。格子全体の評価に必要な作業メモリーが不足する場合は、許容誤差や格子間隔を黙って変えず停止する。

`basic`テーブルの`mesh`は、zlib圧縮したYQB1作業形式。識別子4 byte、頂点数・三角形数の各uint32、その後にfloat32のXYZ、uint32の三角形インデックスを置く。整数はリトルエンディアン。`source_validity`は元DEMの検証用の別列で、描画用の海岸マスクではない。法線・傾き情報は含めない。基本工程が終わっても`complete=false`・`distributable=false`のままとし、全国追加と境界接続の完了前に公開用形式として使わない。

### 追加頂点工程の実行時間と最適化

全国共通プールからの20%追加は、代表的な平野・孤立峰・山地のタイルで事前計測し、候補準備・優先度更新・頂点挿入・保存を含めて全国分の所要時間を見積もる。進行中も実測値で見積もりを更新する。数時間以上かかる見込みなら長時間の本実行を続けず、確定保存済みのデータを保持して停止し、Rustの処理を計測・最適化してから再開する。判断は保守的に2時間以上を目安とする。誤差・予算・優先度・境界条件を速さのために緩めない。

この方針は追加頂点工程に適用する。2026-10-22時点の全国基本生成は継続中で、追加頂点工程はまだ全国生成器へ接続していないため、現時点で追加工程の完了時刻は算出していない。


### 追加頂点の出力を基本メッシュと分離

追加工程は基本SQLiteを読み取り専用で参照し、結果を別SQLiteへ保存する。基本ファイルは`build/terrain-q4-q12-basic-rust-20261022.sqlite3`、追加結果の標準名は`build/terrain-q4-q12-additional-rust-20261022.sqlite3`とする。最適化の比較では`additional-run01.sqlite3`のように出力名を変えれば、基本生成をやり直さず反復できる。従来の基本DBへ追記・上書きしない。

追加出力の`additional`テーブルには追加後の頂点・三角形を含む完全なメッシュと、追加頂点IDを保存する。基本メッシュや元標高の有効域は複製せず入力DBを参照する。`jobs`で再開状態、`checkpoints`で全国共通プールの状態、`timings`で工程別の所要時間を保存する枠を用意した。基本DBの識別情報と追加条件を記録し、条件の違う再開や同一ファイルへの出力を拒否する。

`terrain-q-national --prepare-additional --base-input build/terrain-q4-q12-basic-rust-20261022.sqlite3 --output build/terrain-q4-q12-additional-rust-20261022.sqlite3`で追加工程用のDBを準備できる。基本生成が未完了なら作成を拒否する。このコマンドは出力の準備だけを行い、頂点追加や計測は実行しない。全国の追加計算そのものは引き続き未接続であり、準備後も`complete=false`・`distributable=false`とする。

検証: 別DBへの保存と再開、基本DBのバイト不変、同一ファイル・未完了入力・条件変更・用途の違う出力の拒否、メッシュとチェックポイントの確定保存を含むRust単体テスト52件に成功。

## 16ビット保存形式の採用方針（2026-10-22）

座標は16ビット固定小数、三角形の各頂点番号は符号なし16ビットとする。頂点番号は0～65,535なので、1メッシュに保存できる頂点数は最大65,536点。三角形の枚数の上限ではない。頂点数・三角形数を記録するヘッダーのカウントは32ビットを維持する。

上限は基本頂点だけでなく、共通プールからの追加点・共有辺の接続点・品質補修で必要になる点を含む最終メッシュへ適用する。追加工程で上限に達したタイルへは点を追加せず、残りの全国予算を他の候補へ回す。境界接続や基本誤差・最小角の条件を上限のために緩めず、収まらない場合は保存単位を分割する。表示時のLoop分割で増える頂点数は保存形式の上限とは別に扱う。

水平座標はタイル原点からの相対値とし、現行の15.625 m格子を整数で表せばQ12の512 km端点も32,768で収まる。現行格子上の点は誤差なく保存できる。標高の固定小数の刻み・基準値は別途検証して決める。タイルごとの丸めで共有辺の座標・標高がずれないことを条件とし、量子化後にも許容誤差と三角形の品質を検証する。

現行のYQB1（座標float32・頂点番号uint32）と生成中のプロセスはまだ変更していない。新形式の読み書き・上限処理・互換読込を実装し検証してから切り替える。2026-10-22時点の全国基本メッシュのタイル別最大頂点数はQ4から順に1,228・1,853・2,079・2,303・2,452・1,589・813・161・4点であり、基本段階では全レベルが16ビット番号の範囲内にある。追加・境界処理後の上限確認は別途必要。
