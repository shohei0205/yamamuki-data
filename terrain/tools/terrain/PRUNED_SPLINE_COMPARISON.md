# B スプラインの細部係数削減の比較

既存の「制御点から一続きの B スプライン」を保持し、粗い曲面と細部の差分係数に分け、影響の小さい細部係数を削除する試作。対象は富士山・槍ヶ岳・筑波山の 32 km 四方。全国生成や既存データは変更していない。

## 比較画面

http://127.0.0.1:61476/?region=fuji&keep=0.25&lpf=0

左は元の B スプライン、右は削減後。同じ視点を保持し、細部係数の残存率を 100・50・25・12.5・6.25% から選ぶ。「削減量に応じて全域をならす」を OFF にすると、係数削減だけの差を確認できる。「保存係数の位置」は保存した係数の位置を示す。係数の高さは曲面上の点とは限らない。

## 生成方法

- 元データは保存済みの 125 m 間隔の三次 B スプライン（n=256、余白込み 261×261 係数）。DEM の再読込は不要。
- 1 km 間隔の粗い曲面（n=32、37×37 係数）を最小二乗で当てはめる。ノット挿入行列 R により粗い曲面を細格子へ正確に展開し、残差 D を作る。
- 削除の評価は領域内の高さ誤差二乗と傾き誤差二乗の積分。傾きの重みは長さ 250 m の二乗。各ノット区間で 4 点の Gauss 積分を使う。
- 削除による目的関数の増減を優先度付きキューで管理する。一つ削除するたび、基底の重なる 7×7 の近傍だけ更新する。誤差の打ち消しによる負の増分も許容する。
- 指定数まで削除した後、粗い係数と残存位置を固定し、残った細部係数を同じ高さ・傾き目的関数で再調整する。対角前処理付き共役勾配法、相対許容誤差 1e-8、最大 800 回。最適な位置集合を保証する方法ではない。
- LPF を使う場合は全域に同じ係数 Gaussian フィルターを適用する。sigma は 125 m × 0.5 × sqrt(1/残存率−1)。端は線形外挿し、平面を保つ。連続曲面の厳密な Gaussian 積分を意味しない。
- LPF OFF では各品質の目標曲面が同じなので、削除順の異なる位置まで残す比較となる。LPF ON では目標自体が変わり、品質間の残存位置の包含関係は保証しない。

## 保存と復元

SQLite の surfaces は region, keep, info, base, indices, coefficients を持つ。主キーは (region, keep)。base は粗い係数の float32、indices は残存細部係数の昇順位置を差分 varint、coefficients は残存値の float32。それぞれ zlib level 6 で圧縮する。品質ごとに独立保存し、品質間の重複除去は未実装。

表示時は粗い曲面をノット挿入で展開し、残存差分を足して GPU 用の密な係数配列へ復元する。元 DEM や元の細格子は復元に不要。描画は既存の B スプライン曲面をポリゴン化する方式。

残存率は細部係数だけの割合。粗い係数 1,369 個は必ず残る。細部係数は 67,081 → 33,540 → 16,770 → 8,385 → 4,192 個。100% は分解保存の分だけ元の単独曲面より大きくなる。容量表示は 3 本の圧縮 BLOB の合計で、SQLite・JSON・通信のサイズを含まない。

## 測定結果と制約

LPF OFF・25% の圧縮 BLOB 合計と元 B スプラインに対する高さ RMSE：

| 地域 | 元 | 削減後 | 高さ RMSE |
|---|---:|---:|---:|
| 富士山 | 235,075 B | 71,992 B | 3.62 m |
| 筑波山 | 253,172 B | 70,805 B | 2.21 m |
| 槍ヶ岳 | 238,248 B | 73,408 B | 26.51 m |

高さと解析的な傾きを、257×257 の格子と Sobol 8,192 点で評価する。比較先は元の保存 B スプラインであり、DEM ではない。連続領域の最大誤差保証もない。info に引き継いだ元の rmse 等と、削減後の heightRmse 等は別の指標。

基底の滑らかさは維持するが、強い削減では小さな凹凸や山頂の変形が残る。特に槍ヶ岳の 25% は凹凸模様を視認した。LPF はその模様を弱める一方、山の細部や山頂も丸める。現状は採用決定ではなく比較実装。

## 再現と検証

terrain ディレクトリで専用 Python 環境を使い、次を実行する。

```text
python tools/terrain/prune_ridge_spline.py generate
python tools/terrain/prune_ridge_spline.py generate --no-lpf --output build/spline-pruning-no-lpf-v1
python tools/terrain/prune_ridge_spline.py serve
python tools/terrain/test_prune_ridge_spline.py
node tools/terrain/test_pruned_spline.cjs
```

既存出力は上書きしない。現在の出力は build/spline-pruning-v2 と build/spline-pruning-no-lpf-v1。以前の試行と元データも保持。

単体テスト 3 件：ノット挿入と平面保持、全候補を再評価した削除順との一致、保存モデルの復元と再調整目的関数の低下。ブラウザーでは 3 地域×5 残存率×LPF ON/OFF の 30 条件に成功。API と描画断面の一致、100% での左右画素差、容量、保存係数表示、視点維持、WebGL エラーを確認。元の B スプラインの制御点表示の回帰テストも成功。


## 6.25% のまだら模様への対処：連続基底版

槍ヶ岳では細格子の係数を飛び飛びに残すと、局所基底の盛り上がりがドット状に見えた。残存係数の再調整だけでは解消しないため、係数予算内の完全な粗い基底へ再近似する比較を追加した。

http://127.0.0.1:61477/?region=yari&keep=0.0625&lpf=0

CLI の --continuous で選ぶ。粗い基底の係数をすべて保存し、孤立した細格子の差分係数は残さない。元の係数配列をノット挿入行列 R の擬似逆行列で左右から投影する係数空間の最小二乗法。高さ・傾き目的関数による再調整とは異なる。基底は 2 倍刻みで、予算内に収まる最大の細かさを使う。50% と 25% は 250 m、12.5% と 6.25% は 500 m 間隔で同じ結果になる。割合は予算の目安であり実際の残存率ではない。

槍ヶ岳 6.25% は 4,761 係数、圧縮 BLOB 合計 16,913 B、元曲面との高さ RMSE 30.99 m。旧方式の 22,568 B・48.40 m より小さく、孤立した点状の凹凸も視認上改善した。ただし全体が丸まり、鋭い峰の形状は失われる。全域 LPF は OFF 固定。旧方式は 61476 と既存 SQLite に保持した。

出力は build/spline-pruning-continuous-v1。生成例：

```text
python tools/terrain/prune_ridge_spline.py generate --continuous --no-lpf --output build/spline-pruning-continuous-v1
python tools/terrain/prune_ridge_spline.py serve --continuous --output build/spline-pruning-continuous-v1 --no-lpf-output build/spline-pruning-continuous-v1 --port 61477
```

単体テストに、細格子の孤立係数がないこと、予算以内であること、保存基底からの復元、粗い曲面の再投影不変性を追加。3 地域×5 設定のブラウザー検証にも成功。検証スクリプトは環境変数 CONTINUOUS_SPLINE=1 で連続基底版を選ぶ。
