# 自由配置点から復元する滑らかな曲面

> 現在の標準は、共通 LPF を維持して [再現誤差に応じて中心を配分する自由曲面](ADAPTIVE_ALLOCATION_SURFACE_COMPARISON.md)（v8）。均等配置版 v7 は `layout=scale`、以下の旧方式 v6 は `layout=legacy` で比較できる。

## 現在の実装（2026-10-26）

現在は 512・2,048 点に全点を使う薄板スプライン、8,192・32,768 点に Clough–Tocher の C1 三次曲面を使う。少数点でも従来の三次曲面を選べる。正負の放射基底を足す旧方式と、正の局所面を重ねる中間案は、少数点で円形の凹凸が残ったため採用しない。旧方式のコードは `adaptive_surface_rbf_legacy.py` と `.js`、旧データは v4、中間案のデータは v5 に残した。

表示は http://127.0.0.1:61473/?region=yari&renderer=adaptive&points=8192 。比較用の 61475 も同じ v6 データを使う。既存の格子 B スプラインは選択肢に残す。

### 制御点の配置

入力は従来と同じ、保存済みの不規則な XYZ と保護点。元 DEM や元メッシュの三角形は曲面復元には使わない。外周角・保護点を含め、領域を覆うため最遠点を最大 128 点まで選ぶ。次に、復元した曲面の標高差を全入力点で評価し、残差の絶対値に `min(1,既存制御点までの距離/100m)` を掛けた値で選ぶ。一度に最大 128 点を追加し、曲面と残差を再計算する。予算は 512・2,048・8,192・32,768 点。入力候補数を上限とする。XY を格子に置き直さず、不規則な入力候補から選択する。配置後に XY を連続的に動かす最適化ではない。

### 曲面・保存・描画

- SciPy の `CloughTocher2DInterpolator` で Delaunay 分割と傾きを復元する。区画内は三次曲面で、区画の境界でも高さと一次微分が連続になる。二次微分まで連続する C2 の保証はない。[公式の仕様](https://docs.scipy.org/doc/scipy/reference/generated/scipy.interpolate.CloughTocher2DInterpolator.html) を参照。
- `build/adaptive-free-surface-v6/adaptive.sqlite3` の `surfaces(region,budget,info,model)`、WITHOUT ROWID に保存する。model は点ごとの little endian float32 `[x,y,z]` を zlib level 6 で圧縮した BLOB。予算ごとに独立。三角形・法線・曲面係数は保存しない。info に方式、点数、入力点に対する RMSE・最大差、保護点の差、容量を記録する。
- 読み込み時、三角形を重心で 3 区画へ分け、各三次多項式を 10 係数へ復元する。区画ごとの XY 6 個＋係数 10 個を float32 で GPU に渡す。領域検索用の 128×128 ビンと候補リストも作る。これらは復元後の作業メモリー・通信量であり、保存 BLOB の容量と区別する。
- GPU は同じ三次多項式から高さと解析的な勾配を求める。読み込み・描画分割数の変更時に表示ポリゴンを生成して保持し、カメラ操作では再生成しない。法線 ON では画素ごとに曲面の傾きを評価する。制御点表示は曲面上の実際の XYZ。プロファイルも同じ多項式を使う。
- 描画ポリゴンのために規則格子を使うが、保存する制御点を規則格子にしているわけではない。レイキャストではない。描画分割は最大 8（1024×1024 セル）で、指定 16 は現在 8 に抑える。
- 凸包の辺上の係数評価が浮動小数点の丸めで領域外とされた場合、その評価点だけ同一区画の内側へ 1e-9 の比率で寄せる。保存した制御点は動かさない。非有限値やビン候補数 1024 超はエラーとして扱い、不完全な曲面を黙って返さない。

### 検証と制約

3 地域×4 点数の 12 モデルを生成。`test_adaptive_surface.py` は平面の再現、12 モデルの係数と SciPy の値の一致、共有辺の一次微分、保護点と有限値を確認する。`test_adaptive_surface.cjs` は 12 表示の読み込み、GPU と CPU の高さ・勾配、点表示、方式切り替え、カメラ操作時に再生成しないことを確認する。結果は v6 の `numeric-verification.json` と `browser-verification.json`。

少数点では細かな尾根を再現できず、三次補間のオーバーシュートもあり得る。C1 連続であることは、元の山に形状が一致する保証ではない。RMSE は保存した入力点に対する値で、元 DEM 全点や区画内全域の保証ではない。全国化、タイルの接合、LOD 間差分、クライアント内の曲面復元は今回の対象外。現在の比較サーバーが SciPy で曲面を復元する。

## 旧方式の記録（以下は v4 の仕様）

# 自由配置の滑らかな局所曲面の比較

2026-10-26。制御点を必要な場所へ集めるため、一様 B スプラインの格子係数とは別に、自由位置の局所基底を合成する試作を追加した。比較画面は http://127.0.0.1:61473/?region=yari&points=32768 。「曲面の描画」で格子 B スプラインとも切り替えられる。既存データや方式は保持する。

## 何が自由配置なのか

基底の中心 XY は、保存済みの不規則点から選ぶ。各位置へ 1 個ずつ置く格子ではない。新しい中心は残差が大きい場所へ追加し、影響半径も周囲の密度から決める。配置した後に XY を連続的に移動させる最適化は今回は行わない。有限な入力候補から選ぶ方式である。

入力は `build/ridge-surface-half-budget-v2/ridge.sqlite3` の vertices と corners。元 DEM、三角形・四角形の面、法線は近似に使わない。候補点には元 DEM の標高格子由来の座標も含まれるが、その全格子を保存する方式ではない。

これは非格子 B スプラインや T スプラインの実装ではない。Wendland C2 の局所基底を使用する。以前の少数 Gaussian 曲面とは同じ広い RBF 系統だが、今回は有限の支持範囲、多段階の半径、誤差優先の点配置を使い、最大 32,768 個まで比較する。

## 曲面の式

`h(x,y)=b0+b1*x/S+b2*y/S+Σ wi φ(||(x,y)-ci||/Ri)`、S=32,000 m。

`φ(r)=(1-r)^4(4r+1)`（0≤r<1）、範囲外は 0。各中心 ci は任意の平面座標、Ri は影響半径、wi は符号付きの高さ係数。勾配は各項について `-20 wi (1-r)^3 ((x,y)-ci)/Ri²`。中心でも勾配の極限は有限で、支持範囲の境界では滑らかにゼロになる。曲面は有限個の C2 関数の和であり、近傍セットの選び直しで別の局所近似へ切り替える方式ではない。

関数の定義は [MathWorks の radial basis function の説明](https://www.mathworks.com/help/mbc/model/radial-basis-functions-for-model-building.html) と [Fass の講義資料](https://math.iit.edu/~fass/Notes590_Ch11Print.pdf) を参照。半径の決め方・点の追加・保護点の補正は今回の試作独自の条件。

## 配置と近似

1. float32 保存後に同じ XY へ重なる入力点をまとめる。
2. 山頂候補と外周角を初期中心に含める。その後、既存中心から最も離れた入力位置を選び、領域カバー用に最大 256 点まで置く。残差だけで初期点を固めると、支持範囲が足りない場所が生じるためである。
3. 各新中心の半径は、その時点の中心集合の 8 番目の近傍までの距離×1.8、下限 120 m・上限 8,000 m。粗い基底の半径は、後で点を追加しても縮めずに保持する。粗い形と細部を同時に持たせる。
4. 全入力点に対して、平面成分と基底係数をまとめて疎な最小二乗で近似する。保護点の残差の重みは 20、他は 1。L2 正則化は 0.003。列のノルムで前処理し、前回の係数を初期値にして LSMR を実行する。反復上限は 1,600、atol/btol は 1e-6。
5. 残差の絶対値に、既存中心までの距離を 100 m で抑えた係数を掛け、優先度とする。優先度が高い位置から重複せず選び、256 点または現在の点数と同程度の単位で追加して再近似する。追加した点どうしの距離もその場で更新する。
6. 比較用の予算は 512・2,048・8,192・32,768。入力候補より多くは置かない。未補正の学習点上の最大残差が 0.5 m 以下なら、それ以上の追加を止める。これは早期停止の目安であり、元 DEM の誤差保証ではない。
7. 保護点の最終残差に対し、他の保護点へ届かない小さな C2 基底を同じ位置へ追加する。半径は最も近い別の保護点までの距離×0.4 と 500 m の小さい方（最低 0.5 m）。低点数では補正が大きくなり、山頂付近の形が不自然になる場合がある。

多くのモデルは反復上限で近似を終えている。最小二乗の厳密な最適解が得られたという結果ではない。solverStop と iterations を記録し、実際の残差を表示する。

## 保存

`build/adaptive-free-surface-v4/adaptive.sqlite3` の `surfaces(region,budget,info,model)`、WITHOUT ROWID。各予算は独立保存。model は little endian float32 の平面係数 3 個に、基底ごとの `[cx,cy,radius,weight]` を続けた列を zlib level 6 で圧縮する。最初の controls 個が通常基底、残り corrections 個が保護補正。補正は既存中心と同じ XY のため、中心点の表示では二重に描かない。

位置と半径は float32、単位は Web メルカトル上の m。メタデータに中心数・基底数・残差・反復状態・山頂注視位置を記録する。量子化、LOD 間の差分、全国用の接合形式は未適用。表示の保存量は BLOB のみで、SQLite の管理領域、検索用の導出表、表示用メッシュを含めない。

## GPU 描画と点表示

`/api/adaptive?region=yari&budget=32768` が平面係数と基底列を返す。サーバーは保存基底だけから、64×64 の空間検索表を作る。セルには支持範囲の外接矩形が触れる基底をすべて列挙する。セル番号は検索用であり、制御点を格子へ移す処理ではない。支持範囲内の全基底を漏らさず含め、シェーダー内で実際の円内かを判定する。セル境界でも同じ関数の和になる。

GPU は読み込み時に曲面から描画用メッシュと中心マーカーを生成し、移動・回転中は保持する。描画分割は 1/2/4/8/16 を指定でき、実際は最大 8（128×分割数の辺分割、最大約 210 万三角形）。この描画用の規則格子は保存データでも制御点でもない。

滑らかな陰影は画素位置で同じ基底の解析勾配を評価する。OFF は描画三角形の面法線。水色は自由配置の基底中心を曲面上の高さに置いたマーカーであり、重み wi をそのまま Z として描いた点ではない。橙色の近似入力点、点の透過表示も使える。入力点は点検用の追加転送で、曲面の復元には不要。

## 自由配置曲面の細かな襞への対処（2026-10-26）

細長い区画に曲率が集中し、細い折り目として見える箇所を槍ヶ岳で確認した。C1 連続の確認だけでは見た目の品質を保証できなかった。画素ごとに元の曲面の法線を計算する方法も、描画ポリゴンで再現できない細かさの陰影を出していた。

表示側に「曲面のならし」を追加。なし・40・80・120・160 m から選べ、標準は 40 m。中心の重み 0.2、上下左右の距離 r の 4 点を各 0.1、斜めの距離 (r,r) の 4 点を各 0.05、上下左右の距離 2r の 4 点を各 0.05 とする 13 点平均で、高さと勾配を一緒にならす。領域外は境界位置の高さを延長し、延長した方向の微分はゼロにする。連続な面積積分や誤差上限付きの平滑化ではなく、離散的なフィルターである。

GPU で表示ポリゴンを作る際に計算し、法線も同じ表示頂点に保持する。画素ではその法線を補間し、表示形状より細かな陰影を独立に作らない。ならしや分割数の変更では表示用バッファだけを再計算し、データの再取得やシーンの初期化はしない。カメラ操作時は再計算しない。曲面の法線 OFF は、ならした表示ポリゴンの面法線を使う。

保存 XYZ と SQLite は変更しない。表示上の高さと山頂の高さは変わり、水色の点もならし後の曲面に沿って表示する。ならし前の保護点誤差と、ならし後の表示精度を混同しない。細い尾根も丸まるため、なしとの比較を残す。URL の `fairing=0` または `fairing=40` でも指定できる。

ブラウザー検証に、13 点平均と GPU の高さ・勾配の一致、法線の隣接差の 99 パーセンタイルの低下、法線 ON/OFF を追加した。32,768 点の 3 地域で、99 パーセンタイルは槍ヶ岳 1.004→0.634、富士山 0.379→0.255、筑波山 0.484→0.294。これは勾配差の指標であり、襞が全域で解消したという保証ではない。槍ヶ岳 8,192 点の前後画像は v6 の `yari-fold-before.png` と `yari-fold-fair40.png` に保存した。


## 512 点の線状模様への対処（2026-10-26）

三次曲面の大きな区画の近くに線状の曲がり方が残り、40 m のならしだけでは抑えられなかった。少数点向けに、区画を持たず全点から復元する薄板スプラインを追加した。「少数点の曲面」で「薄板（区画なし・2048点以下）」と「三次曲面（従来）」を切り替えられる。8,192 点以上は計算量と作業メモリーを抑えるため従来の三次曲面を使い、この選択を無効にする。

保存済みの XYZ をそのまま使う。点を増やしたり、SQLite を書き換えたりしない。選択点は従来の三次曲面の残差で選んだ点であり、薄板専用に再最適化した配置ではない。

薄板の式は、`q=xy/32000` として `h(q)=b0+b1*qx+b2*qy+Σ wi φ(||q-ci||)`、`φ(r)=r² log(r)`。`r=0` は関数値・勾配の極限を使う。係数は `[K+λI,P;Pᵀ,0] [w;b]=[z;0]`、`P=[1,qx,qy]` を倍精度で解き、`λ=1e-7`、`Pᵀw=0`。重みと平面係数を float32 へ変換して復元用の係数とする。周辺点だけで別々に曲面を作る方式ではない。式と正則化の意味は [SciPy RBFInterpolator の仕様](https://docs.scipy.org/doc/scipy/reference/generated/scipy.interpolate.RBFInterpolator.html) を参照。

薄板の係数には数百万単位の正負の値があり、GPU 単精度の対数と打消しで数 m の高さ誤差を生じた。そのため `thin_plate_grid` で高さと解析的な勾配を倍精度評価し、一時的な 1,025×1,025 の RGBA32F キャッシュ（約 16 MiB）へ格納する。XY 制御点を格子に変える処理ではなく、読み込み時に作る描画用のキャッシュで、SQLite には保存しない。式の直接評価と比べ、格子間にはバイリニア補間の近似誤差がある。画面の復元データ量にキャッシュも加算する。

GPU はテクセルを手動でバイリニア補間し、従来と同じ 13 点のならしを適用して表示ポリゴンと法線を保持する。キャッシュ生成と係数の解法は CPU、表示分割・ならし・描画は GPU。最初の読み込みではキャッシュ生成の待ち時間が増えるが、生成結果はサーバーで保持し、カメラ操作では作り直さない。新たな外部ライブラリは追加していない。

API は `/api/adaptive?region=yari&budget=512&lowSurface=thinPlate`。`lowSurface=cubic` で従来方式。`kernelMode=1` が薄板で、`base`、`features` の重み、`fieldGrid`、`fieldN=1024` を返す。`kernelMode=0` は従来の区画係数。info の kernel・RMSE・最大差・保護点誤差は実際の方式に合わせて再評価する。保存容量は引き続き元の XYZ BLOB の容量であり、読み込み時の復元データ量とは別である。

`test_adaptive_surface.py` に SciPy の独立実装との比較、平面の再現、倍精度キャッシュと解析的な勾配の検証を追加。`test_adaptive_thin_plate.cjs` は 3 地域×2 点数で GPU の高さ・勾配、13 点のならし、断面、従来方式への切り替えを確認する。記録先は v6 の `thin-plate-browser-verification.json`。512 点の槍ヶ岳の前後画像は `yari512-lines-before.png` と `yari512-thin-after.png`。

線状模様が減ることと、山の再現性が高まることは同じではない。512 点では細い尾根を省略し、薄板にもオーバーシュートがあり得る。正則化と表示のならしで山頂の高さも変わる。全域で線や不自然な形状が消えたという保証ではない。
