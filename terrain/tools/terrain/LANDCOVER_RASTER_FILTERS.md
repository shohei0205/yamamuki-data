# 地表分類画像の前処理比較（Rust）

2026-11-05。富士山を中心とする128 km四方（EPSG:3857投影距離）の試作。元データはESA WorldCover 2021 v200。目的は、分類画像のノイズをベクトル化する前に減らし、境界の凹凸とデータ量を比較すること。

## 生成

データ生成はRustバイナリterrain-landcover-rasterで実行する。元GeoTIFFの読込・投影座標からの最近傍サンプル・4分類統合・ノイズ除去・ポリゴン化・共有境界簡略化・PNG/GeoJSON/SQLite出力はすべてRustから実行。GDAL/GEOSのネイティブC APIを使用し、Pythonの生成スクリプトは呼ばない。現在のDLLは既存環境のrasterio.libsから読み込むが、Pythonランタイムへの依存ではない。参考陰影だけは比較のため既存PNGをコピーする。

起動:
    ./tools/terrain/generate_landcover_raster.ps1 -Build

出力先既定:
    build/landcover-raster-fuji-v4

別条件では既存結果を上書きせず、-Outputで新しい出力先を指定する。-Sizeは256の倍数。-MinimumCellsの初期値は9。テスト:
    ./tools/terrain-rs/build.ps1 -LandcoverRaster -Test

元の10 m製品をそのまま10 mで処理する比較ではない。従来試作と同じ2048×2048、62.5 m投影間隔で分類値を最近傍サンプルする。分類番号はRGBの中央値として扱わない。

## 分類とフィルター

分類:
- その他: 市街地、草地、農地、低木、雪氷などの残り全部
- 森林: WorldCover 10/95
- 砂礫地・裸地: 60（砂・土・岩・疎植生を含む）
- 内水: 80のうちGSI陸域内
- 海: 別のGSI海岸線ベクターから生成。4分類の多数決対象ではない

3方式は同じ元分類画像を入力にし、同じ境界簡略化を実施する。比較を混同しないよう、従来版にあったベクトル化後の面積しきい値による領域除去は3方式とも実施しない。

1. none / なし: 分類画像を変更しない。
2. majority / 3×3多数決: 同期更新で1回だけ実施。陸上3分類の有効な近傍票を数え、元分類が最多票と同数なら維持。別分類同士が最多票で同数の場合も変更しない。分類番号の大小・走査順に依存しない。
3. regions / 小領域除去: 4連結の同分類成分を作り、9画素未満の小成分を共有辺の長い、より大きい陸上成分へ全体として統合。同面積の場合は決定的なID順を使い循環を防ぐ。初期面積・隣接関係に基づく1パスで、反復侵食ではない。9画素ちょうどは保持。

水域は元の内水画素を維持し、別画素を内水へ変更もしない。海側画素は変更しない。多数決は範囲外周を固定。小領域除去は範囲外周・海岸に接する成分を保持する。9画素は約35,156 m²未満の投影面積に相当し、実面積は緯度に応じて小さくなる。

## ベクトル化とLOD

ノイズ除去は全画像へ実行し、その後256×256画素ずつGDALPolygonize（4連結）で領域化する。処理区画の境界をフィルター境界にしない。

GSI陸域で切り取り、海を別分類として追加。全境界線をnode化・polygonizeしてT字接点を共有する。その後GEOS CoverageSimplifyVWを使用する。C APIのpreserveBoundaryは1として外周を固定する。陸上3分類だけを強く簡略化する段階でも内水・海岸との境界を固定する。区画を結合して全域の分類別ポリゴンを出力する。

全5LODの境界目安は0 / 25 / 75 / 200 / 500 m。内水・海岸の簡略化目安は最大16 m。これは最大位置誤差の保証ではない。各段階で面積合計を照合し、全域結合後には各分類のgeometry validityと面積合計、SQLite integrity_checkを検査する。面積検査だけを隙間・重なりの厳密な証明とはしない。

## 保存・表示

各方式に以下を保存する。
- reference.png: 前処理結果のパレット分類画像
- level-0～4.geojson.gz: 比較表示用ベクトル
- landcover-vectors.sqlite3: 分類別geometryのWKB+zlib、既存試作互換
- manifest.json: フィルター条件・変更画素数・容量・分類別面積・生成時間

親manifest.jsonに3方式の集計を保存する。PNG、GeoJSON、SQLiteは比較用の別表現であり、配布容量としてすべてを合算しない。前処理結果は独立LODであり、新たな差分コーデックの試験ではない。

http://127.0.0.1:61495/?filter=majority

「画像前処理」で方式を選び、「左：前処理なし／右：選択方式」で同じ視点・LODを比較する。新しい3方式では境界は同じ直線方式に固定し、ノイズ除去と曲線化の効果を混ぜない。従来のベジェ試作は「従来データ（ベジェ比較用）」に保持する。配信サーバーはPython、Web描画はJavaScript/WebGLであり、今回のデータ生成言語とは別。表示用三角形は保存しない。

### 2026-11-05 ノイズ除去後の共有三次ベジェ適合

Rustで詳細輪郭を接点間の共有経路に分け、端点接線付き最小二乗と誤差による再帰分割で三次ベジェへ適合。多数決・小領域除去の各5LODを生成し、川・海岸・外周は固定。自己交差は不正位置の経路だけを局所的に直線へ戻す。圧縮BZF1に共有曲線とリング参照を保存し、ブラウザーで直接復元する。生成99.95秒。全10データでJavaScript復元座標とRust評価結果が完全一致。5件のRustテスト、Edgeの左右比較・LOD表示検証に成功。61495の「共有三次ベジェ適合（Rust・新）」で比較。生成結果はbuild/landcover-bezier-fit-fuji-v5、詳細仕様と容量はtools/terrain/LANDCOVER_BEZIER_FIT.md。曲線版は必ずしも粗い直線LODより小さくならない。

### 2026-11-05 多数決後に残るドット状小領域の除去

多数決後の分類画像自体に小さな陸上孤立領域が残っていることを確認。富士山周辺22km（2048格子の行列848:1200）の9画素未満の4連結領域は合計528画素。曲線化だけで発生したものではない。

新方式majority-clean（多数決＋孤立領域除去）は3×3同期多数決1回の後に、4連結9画素未満の陸上小成分の統合を行う。川・湖沼・海は固定。範囲端と海岸に接する小成分も従来どおり保持する。小さな実在の陸上分類も統合され得るため、意味的に誤分類と判定したものではなく表示上のノイズ除去である。

元画像からの変更は160,457画素、多数決単独からの追加変更は19,716画素。水域・海の画素マスクは前後で完全一致。富士山周辺22kmの上記小成分画素は0になった。全域の水域や端・海岸保護対象まで消す処理ではない。

Rustで全5LODを再生成（21.24秒）、その結果へ共有三次ベジェ適合（33.00秒）。分類SQLiteは3,444,736 bytes。出力はbuild/landcover-raster-clean-fuji-v1とbuild/landcover-bezier-clean-fuji-v1。BZF1のJavaScript復元は全5LODの全座標でRust評価結果と差0。EdgeでL0/L2/L4、面積、除去前後の左右比較を検証した。

再現:
    ./tools/terrain/generate_landcover_raster.ps1 -Build -OnlyFilter majority-clean -Output build/landcover-raster-clean-fuji-v1
    ./tools/terrain/generate_landcover_bezier_fit.ps1 -Build -SourceRoot build/landcover-raster-clean-fuji-v1 -Filters majority-clean -Output build/landcover-bezier-clean-fuji-v1

実際の再生成時は既存manifestがない新出力先を使う。61495/?filter=majority-clean&curve=fit&mode=cleanup-split は左が従来の多数決ベジェ、右が孤立領域除去後。従来の多数決単独・小領域除去単独も比較用に保持。


### 2026-11-06 地表ベクトルのLOD別情報量を段階的に削減

従来は全LODで同じL0輪郭・同じ領域を保持していたため、許容値を増やしても容量があまり減らなかった。新試作ではLODごとに分類画像を整理し、そのレベルの輪郭から共有ベジェを生成する。最詳細L0はこれまでと同じ入力を保持する。

| LOD | 多数決半径 | 窓 | 小領域統合しきい値 | 投影面積しきい値 |
|---|---:|---:|---:|---:|
| L0 | 0（追加なし） | — | 9画素 | 0.03515625 km² |
| L1 | 1画素 | 3×3 | 16画素 | 0.0625 km² |
| L2 | 2画素 | 5×5 | 64画素 | 0.25 km² |
| L3 | 4画素 | 9×9 | 256画素 | 1 km² |
| L4 | 8画素 | 17×17 | 1,024画素 | 4 km² |

各LODは同じL0分類画像から独立に作る。広い窓の多数決は3分類の積分画像で計算し、窓面積に比例する処理を避ける。元の水域と海側画素、画像端を固定。小領域統合では川・湖沼・海岸接触・外周成分を従来どおり保護する。陸上3分類の細い模様や小領域は、粗いLODで統合・省略され得る。

新LODでは共通境界の最大16m簡略化も停止し、水域・海岸の元ベクトル形状を保持する。陸上3分類の共有辺だけを簡略化する。画像は同じ2048×2048（投影62.5m）であり、水域マスクを低解像度へ縮小する方式ではない。表示には各LODのreference-N.pngを使う。

Rust生成器の--progressive-lodと、ベジェ生成器の--source-levelsを追加。後者は各LODの輪郭から別の共有経路グラフを作る。粗い分類画像の変化を曲線近似誤差と混同しない。ベジェ近似目安50/62.5/100/200/500mは、それぞれの整理後の輪郭に対するもの。

新しい粗輪郭の検証で、平滑化後の「直線のみの経路」も元位置から動いているのに補修対象から外れる不具合を修正。曲線タグではなく固定/未補修経路で判定する。空間インデックスで全ての厳密交差を一括検出し、GEOSの不正理由（穴が外周の外にある等）と該当領域の経路へ補修対象を限定する。補修は必ず未補修経路を元形状へ戻し、進捗なし・同一経路の再補修はエラーにする。形状・分類別MultiPolygon・面積検査を省略しない。

最終出力:

- build/landcover-bezier-lod-fuji-v5（Rust生成19.28秒）

## 2026-11-06 元分類の密度で62.5 mノイズ除去後にベクトル化

採用処理順を変更した。従来の「62.5 m画像へ点サンプルで間引き→除去→ベクトル化」では細い河川を先に失う。新方式は元分類を保持→物理幅62.5 m四方の多数決→面積基準の小領域除去→ベクトル化→共有境界の曲線化。生成はRust。

- ESA WorldCover 2021 v200（公称10 m）を128 km範囲の16384²、Webメルカトル上7.8125 m間隔で保持する。元TIFFの行・列インデックスの最大進み幅が両軸とも1で、元分類の行・列を飛ばしていないことを確認。7.8125 mは新しい観測精度を意味しない。
- 多数決窓は62.5 m四方。8セル幅の偶数窓は端セルを半重みにして対称化。水域と海・対象外は陸域3分類の投票から除外し、水域を消さない。
- 初期小領域閾値は従来9×62.5²=35,156.25 m²を維持し、現格子では576セル。粗LODの追加窓幅は187.5 / 312.5 / 562.5 / 1062.5 m、小領域面積は0.0625 / 0.25 / 1 / 4 km²。距離・面積は投影座標上。
- 多数決は列ごとの移動集計で作業領域O(画像幅)。巨大な3分類積分画像は作らない。表示用PNGのみ処理後に2048²へ縮小し、ベクトル生成入力には使わない。
- 水域は全LODで保護。元資料にない流路の接続は捏造しない。水域形状のL0との対称差はL1～4とも約4.15e-8 m²（浮動小数点差）。
- 本採用はWaterDetail=1。先行した水域のみ高密度化するWaterDetail実験は非採用。
- metadataのminimumCells=9とfilterRadiusCellsは従来62.5 m基準の設定値。各LOD行のminimumCellsは実際の現格子セル数。waterSimplifyMはWaterDetail=1では適用しない。

出力:
- build/landcover-native-filter-fuji-v1/majority-clean
- build/landcover-native-filter-bezier-fuji-v1/majority-clean

再現:

続けてgenerate_landcover_bezier_fit.ps1を-GeometricFit -FairBoundary -SourceLevelsで実行。

全5LODの分類・除去・ベクトル化236.90秒、共有曲線生成101.78秒。観測時の作業セット約1.7 GiB（ピーク測定ではない）。

検証: Rust 14テスト成功。全5LODのBZF1デコード座標はRust参照と差0、SHA256一致。EdgeでL0/L2/L4および河川拡大L4にブラウザーエラーなし。

## 2026-11-06 河川・湖沼のLOD簡略化

元の分類密度で62.5 m四方のノイズ除去をしてからベクトル化し、その後に陸と水域を一つのカバレッジとして共有境界を簡略化する。L0～L4の許容値は投影距離で0 / 4 / 8 / 16 / 32 m。海岸線と処理ブロックの外周は固定し、水域の面は削除しない。その後、従来どおり陸同士の境界をLOD別に簡略化し、共有ベジェを生成する。

富士山128 km四方の河川・湖沼座標数（曲線化前）はL0～L4で230,413 / 229,375 / 156,628 / 101,260 / 71,910。L4は直前の228,993点から約69%減。水域ポリゴン数11,743は同じで、面積は142.07→139.65投影km²（約1.7%減）。全LODの水域形状は有効。L1の4 m簡略化は元の7.8125 m格子に対して小さく、効果は限定的。

配信用曲線データは4,327,088 / 2,081,140 / 1,421,028 / 1,056,952 / 876,427 B。合計9,762,635 B。出力はbuild/landcover-native-water-lod-fuji-v1とbuild/landcover-native-water-lod-bezier-fuji-v1。61495の比較画面は左に前回の元分類処理、右に水域簡略化版を表示する。

## 2026-11-06 粗LODの小水域省略

元分類でノイズ除去した後、ベクトル化の前に8近傍で水域を連結成分にまとめる。面積と外接矩形の対角長が両方とも基準未満の内陸成分だけ、接する辺が最も多い陸域分類に置き換える。海に接する成分と生成範囲の端に達する成分は保持する。ベクトル化後は陸と共有する水際をまとめて簡略化する。
