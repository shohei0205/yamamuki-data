# 全域で解像度をそろえた自由配置曲面

> これは均等配置版 v7 の記録。現在の標準は [誤差に応じた再配分版 v8](ADAPTIVE_ALLOCATION_SURFACE_COMPARISON.md)。画面では「ほぼ均等配置（比較元）」を選ぶと v7 を確認できる。

## 変更の目的

以前は保存済みの不規則点を残差順で選び、元の高さを通る曲面を作っていた。512 点でも槍ヶ岳の最近接点の間隔は中央値 125 m、一部では 4 km 以上空き、少数点で特定部分だけ細かく残った。また、Clough–Tocher の三次区画の曲がり方が造形として目立った。陰影の平滑化だけでは解消できなかった。

新方式は、点数から全域共通の尺度を決めて標高を先にならし、面積を基準に自由配置した局所二次曲面を滑らかに合成する。三角形の区画や面のつながりを保存・復元には使わない。点の高さを厳密に通す補正も行わない。低点数ほど山頂も低く丸くなる。

比較画面は http://127.0.0.1:61473/?region=yari&renderer=adaptive&points=512&layout=scale&fairing=0 。「点の配分と曲面」で「全域を同じ解像度に（新）」と「誤差優先の点配置（従来）」を切り替える。格子 B スプライン版と旧自由配置版のコード・データも保持している。

## 尺度

一辺 S=32,000、中心数 N に対し `d=S/sqrt(N)`、標高 LPF の `sigma=0.3*d`、局所曲面の影響半径 `R=1.6*d`。全域で同じ σ と R を使い、山頂や誤差の大きな場所だけ帯域を高くしない。以下の水平距離は Web メルカトル上の m で、地表の距離とは緯度の縮尺係数だけ異なる。

| 中心数 | 平均間隔 | 事前 LPF の σ | 局所曲面の半径 | 3 地域の圧縮 BLOB |
|---:|---:|---:|---:|---:|
| 512 | 1414.2 m | 424.3 m | 2262.7 m | 15.8～15.9 KiB |
| 2,048 | 707.1 m | 212.1 m | 1131.4 m | 63.1～63.8 KiB |
| 8,192 | 353.6 m | 106.1 m | 565.7 m | 253.0～255.9 KiB |
| 32,768 | 176.8 m | 53.0 m | 282.8 m | 1013.4～1019.4 KiB |

各点が中心 XY・半径・二次曲面の 6 係数を持つため、XYZ だけの旧方式と同じ点数でも容量は増える。たとえば槍ヶ岳の 512 点は旧 XYZ の約 3.6 KiB に対し、新方式は約 15.8 KiB。同じ保存容量での品質比較ではない。

## 生成

`tools/terrain/scale_surface.py` が生成器。今回の新方式は、生成時に `build/terrain-lod.sqlite3` の元標高を使う。従来方式は保存済み不規則点を入力としていたため、入力条件も同一ではない。

1. 地域中心は `build/lpf-curve-smooth-prototype/comparison.sqlite3` の regions から読む。32 km の外側にも各辺 5 km の余白を取り、31.25 m 間隔で元標高を参照する。元標高のデコードと補間は既存の `lpf_curve_compare.Source` を使う。欠測の扱いも同じ。
2. 地域と点数ごとに、全域を同じ Gaussian σ で LPF 処理する。`gaussian_filter` に `sigma/31.25`、`truncate=4`、`mode=nearest` を指定する。最も粗い条件でも、曲面の半径と LPF の参照幅の合計を 5 km の余白内へ収める。LPF の仕様は [SciPy の説明](https://docs.scipy.org/doc/scipy/reference/generated/scipy.ndimage.gaussian_filter.html) を参照。
3. 中心の初期位置は seed 2841 の scrambled Sobol 列。規則格子や元標高の格子へ置き直さない。seed 7183 の別の Sobol 列を、最低 65,536 点・中心数の 4 倍の多い方だけ作り、面積を評価する。
4. LPF 後の勾配の大きさ g に対する重みは `1+0.5*tanh(g/0.4)`。平野と山地の重みの差は 1～1.5 に抑える。候補を最も近い中心へ割り当て、重心へ寄せる処理を 3 回行う。1 回の移動は最大 `0.2*d`。密度を完全に等しくする保証や、最短距離の厳密保証ではない。誤差順の追加・山頂の固定は使わない。
5. LPF 標高を 62.5 m 間隔で参照し、各中心の半径 R 内で局所二次式を最小二乗近似する。重みは正規化座標 q に対し `exp(-4*dot(q,q))`。6×6 の正規方程式へ対角 `[1e-12,1e-10,1e-10,1e-8,1e-8,1e-8]` を加え、倍精度で解く。保存時は float32。
6. 125 m 間隔の 257×257 点で、生成曲面と元標高・LPF 後の標高の差を別々に記録する。元標高全点や領域内全域での最大誤差保証ではない。

生成用の参照格子や元標高は配布モデルへ含めない。表示時には保存した局所曲面だけを使い、元 DEM は参照しない。

## 復元する曲面

各中心 ci の正規化座標を `q=(xy-ci)/R` とする。

`Pi(q)=a0+a1*qx+a2*qy+a3*qx²+a4*qx*qy+a5*qy²`

`wi=(1-r)^4*(4*r+1)`（`r=length(q)<1`、範囲外は 0）

`h(xy)=sum(wi*Pi)/sum(wi)`

Wendland C2 の重みを使う。旧 RBF の符号付きの局所補正の和や、中心で発散する逆距離重みではない。局所曲面の係数は正負を取り得るが、合成の重みは非負。分母が正なら、支持範囲の境界も含め、数学上は二階微分まで連続になる。重みの形は [MathWorks の RBF の説明](https://www.mathworks.com/help/mbc/model/radial-basis-functions-for-model-building.html) を参照。重み付き合成・配置・尺度の条件は今回の実装独自のもの。

解析的な勾配は `dw=-20*(1-r)^3*q/R`、`dh=(sum(w*dP+dw*P)-h*sum(dw))/sum(w)`。CPU での分母が 1e-12 未満なら生成・検証をエラーにする。検証した領域と点数では外周角も覆われている。

## SQLite と GPU

`build/adaptive-free-surface-v7/adaptive.sqlite3` の `surfaces(region,budget,info,model)`、WITHOUT ROWID。model は各局所曲面について little endian float32 の `[cx,cy,R,a0,a1,a2,a3,a4,a5]` を続け、zlib level 6 で圧縮したもの。予算ごとに独立保存。三角形・インデックス・参照格子・法線は保存しない。

info に方式、数、容量、σ と R、点間隔と密度の統計、元標高と LPF 後への誤差、地域中央の生成高さを保存する。`peakError` は地域中央の元標高との差で、全山頂の誤差上限ではない。

API は `/api/adaptive?region=yari&budget=512&layout=scale`。`kernelMode=2` が新方式。GPU 用に各曲面を 12 float＝RGBA 3 テクセルへ詰め、末尾 3 個を 0 にする。既存 API の `triangles` フィールドを共用しているが、このモードでは三角形情報ではなく局所曲面係数である。`features` は中心点表示用の XY・R・a0。128×128 のビンと候補リストを実行時に作り、候補数が 1024 を超えたらエラーにする。

GPU は元の自由配置基底から高さと勾配を評価し、表示用の格子ポリゴンと法線を保持する。描画用に三角形は使うが、その三角形を単位に造形を作る方法ではない。点数変更・分割数変更時だけ再生成し、カメラ操作では再生成しない。後段の「曲面のならし」は新方式の標準では 0。追加で指定することもできる。水色の点は合成後の曲面上へ投影した中心位置で、元標高を厳密に通る制御頂点ではない。

新方式は元標高から生成したため、旧方式で使っていた保存済み TIN の入力点表示を無効にする。比較元メッシュの表示や容量は別の参照値である。

## 検証と制約

`test_scale_surface.py` は平面の再現、解析的勾配と差分の一致、同じ形の二つの山の再現差、12 モデルの点間隔・密度・有限値・外周のカバー・非格子配置を確認する。`test_scale_surface.cjs` は 3 地域×4 点数について、CPU と GPU の高さ・勾配、中心点の位置、カメラ操作時の再生成なし、旧方式への切り替え、面法線モードを確認する。

記録は v7 の `numeric-verification.json`、`browser-verification.json`、地域別の overview 画像。槍ヶ岳の 512 点では最近接間隔が約 958～1,561 m、中央値約 1,238 m。半径 `2*d` 内の点数は全モデルで中央値 12、99 パーセンタイル 15。厳密な密度上限を課した結果ではなく、今回の地域・配置の実測値である。

点数が少ないと山頂・尾根・谷は丸まり、高さも変わる。二次近似のオーバーシュートを完全には防いでいない。すべての点数・視点で造形の模様が消える保証ではない。画面上の分割数を下げれば、描画ポリゴン自体の角張りも残る。全国化、異なるサイズのタイル間の接合、LOD 差分は今回の比較には含めない。

```powershell
./build/terrain-venv/Scripts/python.exe -X utf8 tools/terrain/adaptive_surface.py serve --scale-output build/adaptive-free-surface-v7
./build/terrain-venv/Scripts/python.exe -X utf8 tools/terrain/test_scale_surface.py
```
