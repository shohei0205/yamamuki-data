## 入力と出力

入力は読み取り専用の `build/terrain-lod.sqlite3`。今回固定したSHA-256は `6e6331be2bb17ece2b42db591acf7a3da4cd44bf6a472fbe76ec699b001bb3f4`。元L14の256ピクセル標高を境界またぎで補間する。3地域とも評価DEMの準備は完了した。1地域約3.51 GBで、元ファイルは変更しない。

出力先は `build/xyz-regional-200km-20261024/<region>/`。regionは `tsukuba`、`yari`、`fuji`。

| ファイル | 内容 |
|---|---|
| `region.json` | 中心・格子原点・範囲・元標高の指紋 |
| `dem.f64` / `valid.bits` | 評価標高と有効標高マスク。再開時に再利用 |
| `z14.mesh`～`z6.mesh` | 詳細から粗い順の中間形状。完了レベルを再利用 |
| `z*.report.json` | 量子化前の誤差・角度・頂点数 |
| `terrain.sqlite3` | YMV4、YMT3/TFC2で保存した地域試験データ |
| `packing-report.json` | z別のタイル数・容量・親参照圧縮・量子化後の品質 |
| `independent-verification.json` | Pythonの独立復元器による全タイル検証 |
| `progress.json` | 実行工程。失敗時は理由も保持 |
| `generate.launch.json` / `generate.log` / `generate.err` | 生成PID・引数・ログ |

全体の状態は出力ルートの `run.json`、起動記録は `run.launch.json`。生成と独立検証を1地域ずつ実行してから次へ進む。既存の配信サーバーは変更しない。

## 処理

Rustの `xyz_region_test.rs` と `xyz_region_pack.rs` で、元標高の取得、共通最詳細TIN、山頂制約付き削減、量子化後の補修、余白抽出、新形式保存、即時復元照合を行う。保存前の量子化が粗い点の位置を動かすため、粗い側の確定点を詳細側の補修にも含める。場所を指定した手直しはしない。

量子化後は局所許容誤差と最小角10°を再確認し、不合格を合格として扱わない。新しい補修点は通常のメッシュへ含め、別の接合候補配列は保存しない。z6～z9・z12は全頂点、z10・z11・z13・z14は親との差分、最大親参照2段。親参照は8＋24ビットで、タイル別差分可変長と生列を実サイズで選ぶ。

評価と地形重みの準備を並列化し、スレッド数は論理プロセッサー数の半分。地域自体は順番に処理し、大きい評価配列を複数地域で同時保持しない。共有頂点密度はR-treeの円内件数で数える。余白座標が範囲外になる長い面を抑えるため、最詳細に形状補助点を置き、削減時にも面の幅を制約する。最低頂点数の目標として予算を使い切る処理ではない。

固定点の挿入中に不要な標高走査を行わず、挿入後に完成した面だけを評価する最適化を追加した。合成試験で出力頂点・三角形・誤差は完全一致し、標高の評価回数は953,982→176,128。200 kmの初回試行は最詳細TIN工程で止め、DEMを保持してこの版へ切り替えた。

## 実行方法

terrainディレクトリから実行する。

```powershell
./tools/terrain-rs/build.ps1 -XyzRegion -Test -TargetDirectory "$PWD/build/terrain-q-cache-target"
./tools/terrain-rs/build.ps1 -XyzRegion -TargetDirectory "$PWD/build/terrain-xyz-test-target"
./tools/terrain/run_xyz_region_test.ps1
```

継続実行は最後のコマンドを同じ出力先で実行する。run.lockの排他ロックで二重実行を拒否する。非表示の実行ではPowerShellをStart-Processで起動し、WindowStyle Hidden・ログ・PIDを指定する。生成停止は当該起動記録とコマンドラインを照合してから行う。出力ファイルを消して再開する必要はない。

小範囲の確認は `run_xyz_region_test.ps1 -Output build/xyz-region-smoke -Extent 4000`。単一SQLiteの独立検証は次のコマンド。

```powershell
./build/terrain-venv/Scripts/python.exe -X utf8 tools/terrain/verify_xyz_region.py build/xyz-regional-200km-20261024/tsukuba/terrain.sqlite3
```

## 今回の試験の限界

- 200 km領域で切った共通メッシュなので、粗いXYZタイルの世界全体での担当範囲を埋めるデータではない。地域外への表示には使わない。
- 地形重み・山頂検出の距離は地域試作の投影距離であり、仕様書の測地距離による特徴判定は未統合。
- 異なるLODの実行時接合、部分接触、Loop後の表示はこの生成・復元試験だけでは検証しない。
- completeは当該地域試験の全工程完了を表す。上記の未検証事項があるためdistributableは常にfalse。

全体の採用仕様は [MESH_SETTINGS.md](../../MESH_SETTINGS.md)。この試験で全国生成の実装・品質保証が完了したとは扱わない。

## 粗メッシュの工程内進捗

`reduce-mesh` は `part` に境界準備・候補評価・頂点削減・誤差と角度の検証を出力する。候補評価では `processed/total`、削減では削減済み数と開始時頂点数、`queued` に残りヒープ件数、`elapsedSeconds` に工程経過秒を記録する。約 1 秒間隔で更新するが、単一の候補評価中などは更新間隔が長くなる。削減は品質条件で終了し目標数が未定のため、削減の完了率は計算しない。

進捗ページ `http://127.0.0.1:61460/` は 3 秒間隔で読み取る。2026-10-24 の進捗対応版への切替では旧ログを `.before-progress` として保持し、保存済み z14・z13 を引き継いで z12 から再開した。切替前後を含む壁時計の合計時間と、再開後のレベル内時間は区別する。

## 2026-10-24 補修の局所更新

- 全体の再三角形分割、全角度の三角関数計算、全 DEM の再照合を補修の各反復で行う処理は解消した。

## 2026-10-24 削減候補の重複面評価をキャッシュ

頂点削減で隣接候補を更新する際、同じ頂点組の三角形を繰り返し標高照合していたため、面の頂点番号と順序をキーにしたキャッシュを追加した。座標・標高・重み・局所誤差係数が不変の同一レベル内だけ有効にする。毎レベルの開始・終了で消去する。

キャッシュは Mutex 付き 16 区画、各 16,384 面（全体最大 262,144 面）。区画上限でその区画を消去し、最近の面を保存する。ロック中に標高走査は行わない。誤差打切りで不合格になった部分評価は、同じかより厳しい許容値で不合格を証明できるときだけ再利用する。合格の評価値や削減順位を近似しない。

### ブラウザ展開の一括取得

`/api/bundle` で表示対象タイルと必要な親頂点 BLOB を一括取得する。サーバーは YMV4 の依存表だけを読み、親三角形は転送しない。メッシュ復元は引き続きブラウザ側で行う。バイナリー応答は `manifestLength:u32LE`、UTF-8 JSON（`rows` と `entries`）、各 entry の頂点・三角形 BLOB の順。entry は `[z,x,y,vertexBlobBytes,triangleBlobBytes]`。親参照専用 entry の triangleBlobBytes は 0。

ブラウザの個別タイル／親タイル HTTP 往復を、地域情報と一括 BLOB の原則 2 リクエストへ削減した。親依存の復元も Promise.all で待ち合わせる。面の重複キー作成で面ごとの配列確保・sort を避ける。描画内容や保存形状を簡略化する変更ではない。

### レベル変更時の未取得 BLOB だけを転送

ブラウザは地域を含む z/x/y キーで頂点 BLOB・三角形 BLOB・復元済み頂点を保持する。レベル・表示範囲変更時にキャッシュを消さない。`POST /api/bundle` の JSON `known` は `[z,x,y,hasVertices,hasTriangles]` の一覧で、サーバーは保持済みの成分を省く。親として頂点のみ取得済みのタイルを表示する場合は、未取得の三角形のみを返す。一括応答の entry で該当成分の長さ 0 は未送信を意味する。表示専用 API であり、SQLite への書込は行わない。

地域 DB のサイズと更新時刻から identity を返し、変更時には該当地域のキャッシュを無効化する。圧縮 BLOB 保持量は 128 MiB を上限に古いエントリーを破棄する。復元済み頂点・描画用配列は別途メモリーを使うため、これはブラウザ全体のメモリー上限ではない。ページの再読込でもキャッシュは消える。形状の GPU 組立は現状、表示切替ごとに行う。

画面の「今回取得」は今回送信した頂点・三角形 BLOB の合計（一覧 JSON や HTTP ヘッダーを除く）。ブラウザで槍ヶ岳 z14 → z13 → z14、32 km 範囲を確認し、最後の z14 の取得 BLOB は 0.000 MiB。3 地域でレベルを下げてから上げる計 54 回の試験で既取得成分の再送がないこと、再訪レベルの転送 BLOB が 0 になること、独立復元器と頂点が一致することを確認した。コマンドは `node tools/terrain/test_xyz_incremental.cjs build/xyz-viewer-fixtures.json`。


### タイル一覧待ちの削減

## YMV4・TFC2 の WASM 復元

`xyz_decoder.wat` に新形式の独立 WASM 復元器を追加した。TFC2 の FIFO/LRU、ZigZag・最大 5 バイトの可変長整数、u32 三角形番号、YMV4 の生／グループ差分親参照、親頂点のコピー、i16 XY・u16 高さの座標展開を WASM で処理する。最大 34 ビットの予測値演算には i64 を使う。ヘッダー検査、親タイルの非同期取得、キャッシュ管理は JavaScript が担当する。

ソースからのビルド: `node tools/terrain/build_xyz_wasm.mjs`。既存のローカル wabt を利用し、`build/xyz_decoder.wasm`（現時点 1,543 bytes）を生成する。生成 WASM はコミットしない。`xyz_wasm.mjs` が入力を WASM メモリーへコピーし、復元結果を独立した typed array として返す。作業領域は最大 512 MiB。実データの全体 RAM 上限ではない。

テスト HTML は WASM を既定とし、「復元」で JavaScript 比較版も選べる。WASM 読込が失敗した場合に黙って JS へ切り替えず、画面にエラーを出す。切替時は復元頂点キャッシュを消すが、取得済み BLOB は維持する。

`node tools/terrain/test_xyz_wasm.mjs build/xyz-viewer-fixtures.json` で 27 地域・レベル別サンプルの頂点と三角形が JS／独立 Python 結果と一致した。約 40 億の頂点番号を使う u32 三角形、不正制御値・切断・重複頂点も確認した。ブラウザで槍ヶ岳 z14・32 km・225 タイルの WASM 表示に成功。単回観測は取得 0.12 秒・頂点復元 0.01 秒・面復元と組立 0.19 秒で、厳密な速度比較ではない。サーバーは引き続き BLOB 配信のみで復元はしない。


### 描画配列の組立と再訪キャッシュ

地域・レベル・表示範囲・DB identity・復元方式ごとに位置・法線・三角形 index の typed array を保持する。再訪時は重複除去・面復元・法線集計を省き、GPU へ再転送する。描画配列の上限は合計 128 MiB、古い entry から破棄する。圧縮 BLOB の 128 MiB 上限とは別であり、GPU・復元座標・一時配列も別途メモリーを使う。

初回組立は、地域格子の整数 XY を `(gx-px*64)*((n-1)*64+1)+(gy-py*64)` で数値キー化する。今回の約 200 km の格子では安全整数の範囲内に収まり、文字列確保を省ける。面は入力頂点数合計 + 1 を基数として 3 index を連結し、基数の 3 乗が安全整数以下の場合だけ数値キーを使用する。大規模な場合は文字列へ戻す。三角形ごとに作っていた辺・法線配列をスカラー演算へ変更し、面積重みの頂点法線という定義は維持する。

ブラウザの槍ヶ岳 z14・32 km で 158,527 頂点・313,335 面が変更前と一致。初回組立は単回観測 0.13 秒（直前の版は 0.21 秒）。z14→z13→z14 の再訪は「組立済み再利用」、GPU 転送約 0.002 秒。厳密な複数回性能比較ではない。
