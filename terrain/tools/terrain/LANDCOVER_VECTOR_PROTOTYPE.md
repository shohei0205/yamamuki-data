# 富士山の地表ベクトルLOD試作

対象は富士山を中心としたWebメルカトル上の128 km四方。全国生成済みの地形SQLiteとは独立した地表領域データである。分類原本は既存のESA WorldCover 2021 v200 COG、海岸は既存の国土地理院ベクトル由来の陸域WKBを使う。

## 分類

| 表示 | 元データ |
|---|---|
| 森林 | WorldCover 10・95 |
| 砂礫地・裸地 | WorldCover 60。砂礫だけでなく露出土壌・岩地・疎な植生も含む |
| 河川・湖沼 | WorldCover 80のうち国土地理院陸域の内側 |
| その他 | 上記以外。市街地・農地・草地・低木等は区別しない |
| 海 | 国土地理院の海域。陸上分類とは別 |

WorldCoverから河川と湖沼そのものを区別することはしない。元の分類解像度より細い河川は保証できない。試作は62.5 m投影間隔（2048角）で分類を最近傍サンプルするため、10 m原本の全情報は含まない。原本を全解像度ベクトル化した結果ではない。4096角の生成指定も残している。

## LOD

| LOD | 境界簡略化の目安 | 陸地3分類の小領域統合 |
|---|---:|---:|
| L0 | なし | なし |
| L1 | 25 m | 2,500 m²未満 |
| L2 | 75 m | 10,000 m²未満 |
| L3 | 200 m | 40,000 m²未満 |
| L4 | 500 m | 160,000 m²未満 |

領域境界は共有ネットワークとして扱い、coverage simplificationで同時に簡略化する。処理は16 km四方の64バッチへ分け、バッチ境界は固定する。境界を横切る領域は面積だけで統合せず、同分類を最後に再結合する。Visvalingam系の目安であり最大境界位置誤差の保証ではない。水域・海は小領域統合の対象外。陸地3分類の小領域は、共有する辺が長い隣接する大きな陸地領域へ統合する。隣接グラフを作り、統合後に同分類の境界を取り除いてから簡略化する。まず全分類を最大16 mで簡略化し、次に乾いた陸域3分類だけを簡略化する。その部分集合の外枠を固定するため、水域と海岸の境界が別々に動かない。各LODで隙間・重なり・不正ポリゴンを検査する。

比較画面は平面ベクトル表示、元4分類PNGとの左右比較、任意分類の表示切替、自動／固定LOD、境界線、参考地形陰影、データ量表示を備える。陰影PNGは表示の補助であり、地表領域の保存データではない。3D地形へのGPU重畳・保存タイル分割・異なる地表LODを同時に表示する接合は今回の対象外。

## 保存と起動

- build/landcover-vector-fuji-v2/landcover-vectors.sqlite3: metadataとfeatures(level,class,geometry)。geometryは局所メートルXYのWKB＋zlib。
- level-N.geojson.gz: 同じ領域の比較HTML配信用。gzipをHTTP Content-Encodingとして返す。
- manifest.json: 分類、原本、出典、レベル別容量・頂点数・領域数・検査結果。
- reference.png: 同じサンプル分類のパレットPNG比較用。
- relief.png: 元DEMの参考陰影。分類とベクトルの生成判定には使わない。

生成: python tools/terrain/generate_landcover_vectors.py --size 2048 --output build/landcover-vector-fuji-v2
既存の完成出力は上書きしない。試作の元領域キャッシュ batch-SIZE-Y-X.wkb / .codes は同じ出力ディレクトリ内で再利用できる。配布には含めない。

表示: python tools/terrain/landcover_vector_server.py --port 61495
http://127.0.0.1:61495/

依存: 既存のterrain Python環境のrasterio、shapely 2.2、numpy、Pillow。参考陰影に既存DEMキャッシュを使う。作業用コードはこの試作ではPythonで、既存のRust地形生成器は変更しない。

### 表示の高速化と検証

保存形式は穴付きの領域ポリゴンのままとし、読み込み時にEarcutで三角形化してWebGL 2へ渡す。穴などで面積が一致しない領域だけは、サーバーのGEOS制約付きDelaunayへフォールバックする。配布データにはこの派生三角形を含めない。三角形は表示用の派生データで、配布SQLiteには保存しない。元の領域面積と三角形化後の合計面積を全レベルで照合する。穴を省いた描画は分類が一致しなかったため採用しない。領域の境界線も別のGPUインデックスで表示する。

CPUの三角形化・GPU転送に要した準備時間とGPUバッファ容量を表示する。画面の「描画命令」時間はCPUでの命令発行であり、GPU完了や3D描画時間ではない。全LODの切替、左右比較、拡大表示をEdgeのブラウザー自動テストで確認する。


## 共有二次ベジェ境界（2026-11-05）

直線ポリゴン境界の角張りを比較するため、共有する境界の角を二次ベジェで丸める試作を追加した。61495の「境界」で直線／共有ベジェを選択し、「表示 → 左：直線／右：共有ベジェ」で比較する。丸めは弱・標準・強、曲線細分は4・8を選べる。表示用三角形は引き続きGPUへ渡すが、地被覆境界そのものを曲線として構成する。

全分類のリングから共通の節点・辺グラフを作り、次数2の角だけを丸める。次数3以上の分類接点と外周は固定。元の角を二次ベジェの制御点とし、隣接辺上の開始・終了位置を求める。切り取り距離は隣接辺長の45%以下、他の非接続境界までの距離の35%以下。対向するリングでは同じ曲線のサンプルを逆順に使うため、独立に丸めて隙間を作る方式ではない。細い水路や穴の近傍は丸めを弱める。この方式は角の丸めであり、元の細かい凹凸を全面的に消す曲線適合ではない。

コードはlandcover_curves.py、配信はlandcover_vector_server.py。curves/level-N-quadratic.npzには共通XY、丸め距離、リングの節点参照とオフセット、分類・領域・リング対応を保存する。二次曲線を復元できる情報であり、表示用の細分三角形は保存しない。既存SQLiteは直線境界の比較元として保持する。NPZの圧縮は試作のZIP/DEFLATEで、全国配布形式として確定したものではない。

富士山L2・標準・4細分では共通123,310点、丸め対象109,129角、曲線制御NPZ 1,189,750 bytes。これは従来WKBに加算する必須差分ではなく、別の試作保存表現。動的GeoJSON転送量とGPUバッファ容量は異なるため区別する。初回はグラフ準備約0.9秒、曲線評価約6.1秒、その後ブラウザーの三角形化・転送も必要。曲線結果はサーバーでキャッシュし、GPUキャッシュは256 MiB目安で退避する。

検証: 人工ケースの共有境界・細い水域と穴・三方向接点の3テスト。EdgeでL2の左右比較、強さ変更、8細分、描画面積照合を確認。L2描画面積の相対差は約4.3e-14。複雑な領域は従来同様にGEOS制約付きDelaunayへフォールバックするが、曲線化したリングの頂点番号を使用する。


## データ生成の実装言語（2026-11-05 決定）

今後のデータ生成はすべてRustで実装する。地形、地被覆ベクター、曲線境界、圧縮・エンコード、生成時の前処理・補助情報生成も対象とする。Pythonで新たな生成ロジックを追加しない。既存の地表ベクター・共有ベジェ境界のPython試作は、今後の改修・再生成に際してRustへ移行する。既存の生成済みデータはこの方針変更だけを理由に削除しない。ビューワーのHTML/JavaScriptおよび生成を起動するシェルスクリプトは生成アルゴリズムの実装言語とは区別する。

### 2026-11-05 分類画像のノイズ除去を先行するRust試作

富士山128kmで、元GeoTIFF→4分類→フィルター→ベクトル化をRustで実装。前処理なし／3×3多数決1回／4連結9画素未満の小領域除去を全5LODで生成。内水・海の画素マスクは同一。全5LOD SQLiteは12,300,800 / 4,523,008 / 4,019,712 bytes。生成281.96秒、Rust8テストとEdge表示検証が成功。61495で左右比較する。新3方式は前処理の効果を比較するため直線境界に統一し、従来のベジェ試作は別選択肢として保持。仕様・再現手順はtools/terrain/LANDCOVER_RASTER_FILTERS.md。

### 2026-11-05 ノイズ除去後の共有三次ベジェ適合

Rustで詳細輪郭を接点間の共有経路に分け、端点接線付き最小二乗と誤差による再帰分割で三次ベジェへ適合。多数決・小領域除去の各5LODを生成し、川・海岸・外周は固定。自己交差は不正位置の経路だけを局所的に直線へ戻す。圧縮BZF1に共有曲線とリング参照を保存し、ブラウザーで直接復元する。生成99.95秒。全10データでJavaScript復元座標とRust評価結果が完全一致。5件のRustテスト、Edgeの左右比較・LOD表示検証に成功。61495の「共有三次ベジェ適合（Rust・新）」で比較。生成結果はbuild/landcover-bezier-fit-fuji-v5、詳細仕様と容量はtools/terrain/LANDCOVER_BEZIER_FIT.md。曲線版は必ずしも粗い直線LODより小さくならない。
