# 骨格制御点から一続きの B スプラインへ近似する比較

2026-10-26。尾根・谷の折れを弱めても三角形模様が残ったため、面ごとの曲面をやめ、高さと陰影を同じ B スプラインで求める試作を追加した。比較画面は http://127.0.0.1:61472/?region=yari&fitN=256 。元の四角形主体曲面、既存の階層 B スプライン、RBF も残している。

## 入力と生成

入力は `build/ridge-surface-half-budget-v2/ridge.sqlite3` の 3 地域の制御点 XYZ と保護点 ID。三角形・四角形の面、骨格の辺、法線、元 DEM は近似計算に使わない。左側の比較元 TIN は表示用に別途読み込む。

各地域 32 km 四方を、一様な 3 次テンソル積 B スプラインで近似する。区間数 n=128・256・512、間隔は 250・125・62.5 m。制御係数は規則格子に配置する。自由位置の少数 NURBS パッチや、非格子型スプラインの実装ではない。不規則な保存点を観測値とした曲面近似であり、元の標高画像を単純に拡大する処理とは異なる。

観測行列 A は各点へ影響する 4×4 の基底値から作る。目的関数は `||A c-h||² + 0.08² (||Dxx c||²+||Dyy c||²+2||Dxy c||²)`。微分項は係数の差分であり、距離で正規化した物理的な曲率ではない。今回の各間隔の正則化係数は共通。全域の曲率を弱く抑え、観測点のない場所を補う。

保存モデルの corners に含まれる山頂候補と外周角を等式制約とする。制約行列から一部の係数を消去し、残りを LSMR で反復近似する。単純な係数選択で条件が悪い場合は列ピボット付き QR で消去する係数を選ぶ。上限は 4,000 回、相対停止条件は atol/btol=2e-6。今回の 9 モデルはすべて solverStop=2 で終了した。制約は元データに記録された候補点の位置と高さに対するもので、実際の山頂標高の正しさを別途保証するものではない。

## 描画

既存の B スプライン用 GPU 描画を再利用する。高さと解析勾配を同一の基底関数から評価し、曲面の法線で陰影を付ける。単純節点の内側は C2 連続で、元 TIN の辺で曲面や法線を分けない。元の三角形模様を隠すために画像をぼかす処理ではない。

画面へ出す形は曲面を三角形へ分割して近似する。「曲面の法線で陰影」が ON のとき、陰影は分割頂点の法線補間ではなく画素位置の B スプライン勾配を使う。OFF では生成三角形の面法線になるため、面は見える。推奨の確認条件は法線 ON、曲面分割 4。描画の 400 万面目安で実際の分割回数を下げる場合がある。n=512 の 4 分割指定は実際 2 分割・2,097,152 三角形。

新しい描画方式の選択肢は「制御点から一続きのBスプライン」、間隔は専用の「制御点Bスプラインの間隔」で変更する。以前の「尾根・谷の折れ」はこの方式では使用せず無効にする。通常の B スプラインとも切り替えられる。

## 保存形式と容量

出力は `build/ridge-spline-prototype-v4/spline.sqlite3`。`surfaces(region,quality,n,info,coefficients)`、WITHOUT ROWID。各段は独立保存。必要範囲の係数 `(n+5)×(n+5)` を little endian float32 とし、zlib level 6 で圧縮する。原点は本来の領域より 2 区間外側、係数の配列幅は n+5。HTTP は `/api/ridge-spline?region=yari&n=256`。JSON に info・size・halo=2・span=32000・summit・base64 の係数を返し、gzip 圧縮する。

容量は曲面係数の圧縮 BLOB で、SQLite の管理領域や転送 JSON とは異なる。元の入力は三角形メッシュの約半分の予算で作った制御網だが、再構成した B スプラインの容量をその予算へ再調整してはいない。特に 62.5 m 版は地域によって元 TIN より大きくなる。選択した間隔と表示容量を見て比較する。前に試した階層差分・量子化コーデックも、この試作へは未適用。

## 制約と検証

B スプラインの滑らかさは得られるが、面から点への近似方法を変えたため、すべての制御点を通るわけではない。尖った山頂の周囲が丸まること、観測点が少ない場所で盛り上がりが生じることは引き続き比較が必要。山頂の一点の保持と、山体全体の形状の正確さは別の評価である。全国生成・地域間接合・LOD 差分保存にはまだ適用していない。

`test_ridge_spline.py` の 4 テストで、基底の重み和と傾斜平面の再現、節点をまたぐ勾配の連続、面情報を変えても近似結果が変わらないこと、保存した 9 モデルの保護点保持と反復終了を確認した。`test_ridge_spline.cjs` は 3 地域×3 間隔、陰影切替、通常 B スプラインとの往復、比較元 z10 への切替を確認する。既存の B スプラインと RBF も回帰テストする。

```powershell
./build/terrain-venv/Scripts/python.exe -X utf8 tools/terrain/ridge_spline.py generate --output build/ridge-spline-prototype-v5
./build/terrain-venv/Scripts/python.exe -X utf8 tools/terrain/ridge_spline.py serve --output build/ridge-spline-prototype-v4 --port 61472
./build/terrain-venv/Scripts/python.exe -X utf8 tools/terrain/test_ridge_spline.py
node tools/terrain/test_ridge_spline.cjs
```

画面は 61470 から比較用データや既存方式を取得するため、61470 とその既存依存サーバーを動かしておく。生成と新曲面の復元には元 DEM は不要。

## 制御点の重ね表示

「Bスプライン制御点」を初期状態で ON にし、水色の点を重ねる。XY は係数の格子位置、Z は保存された係数値そのもの。曲面を必ず通る点ではない。表示領域内の `(n+1)²` 点を描き、外側 2 区間の補助係数は表示しない。点の位置は GPU で係数テクスチャから作るため、表示専用の座標データは不要。

「近似の入力点」は橙色で、元の不規則な制御網に保存されていた XYZ を表示する。必要になった地域だけ `/api/ridge-spline-input?region=yari` から読み、メモリーへキャッシュする。この転送は点検用であり、曲面係数の保存容量には含めない。「地形越しに点を表示」は初期状態で ON。OFF にすると深度テストで隠れた点を消す。点を描く間は深度を書き込まず、描画後は元の深度設定へ戻す。

`test_ridge_spline_points.cjs` では点の個数、実際に描いた水色・橙の画素、制御点 OFF、入力点 ON、深度切替、地域・間隔を変えたときの更新を確認する。

規則格子から外れた中心配置は [自由配置曲面の比較](ADAPTIVE_FREE_SURFACE_COMPARISON.md) と http://127.0.0.1:61473/ に追加した。格子を変形したBスプラインではなく、別のC2局所基底を合成する方式。従来の格子版はそのまま選べる。
